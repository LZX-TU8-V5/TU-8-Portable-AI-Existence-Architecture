## 知识原子标准结构

```yaml
---
id: "KB-ARCH-001"          # 唯一坐标（格式：KB-{领域}-{序号}）
title: "系统架构设计原则"    # 核心主题（一句话说清）
type: "PRINCIPLE"           # 类型：PRINCIPLE | TOOL | PROCESS | CASE | THEORY
dependencies: ["KB-TOOL-005"]  # 依赖：基于哪些知识建立
conflicts_with: []          # 冲突：与哪些知识互斥
version: "1.2"              # 版本：用于时效性计算
domain: "architecture"      # 领域：architecture | cognitive | project | meta
---
```

### 类型定义

| 类型 | 含义 | 示例 |
|------|------|------|
| PRINCIPLE | 原则/法则 | 困惑信号触发条件 |
| TOOL | 工具/配置 | incentive_config.yaml |

## 三维坐标系

### X轴：领域聚类

根据 `type` 和目录结构将文档归类。

**自洽检查**：内容向量偏离目录主题 → 标记"离群点"，降低置信度。

### Y轴：依赖层级

```
L0 基础层：SOUL.md、核心协议（无依赖）
 ↓
L1 原则层：通用法则（依赖基础层）
 ↓
L2 工具层：配置/规范（依赖原则层）
 ↓
L3 应用层：项目配置/操作手册（依赖工具层）
```

**自洽检查**：应用层试图修改基础层规则 → 触发 conflicts_with 警报。

### Z轴：时间版本

`version` 字段控制时效性。旧版本标记 `deprecated`，不参与检索。

## 自动化校验：地图构建器

### 步骤一：向量化与聚类

1. 计算新文档向量
2. 判断落在哪个区域
3. 若落在真空地带 → 提示新建分类

### 步骤二：链路扫描

1. 扫描正文引用（如 `[[KB-ARCH-001]]`）
2. 自动更新 dependencies
3. 断链检测：引用ID不存在 → 标记"悬空指针"，置信度→0

### 步骤三：冲突消解

1. 内容相似度>0.9 但结论相反 → "地图褶皱"（冲突）
2. 处理：折叠旧文档，标记 `conflicts_with`

## 与时空论的对齐

```
时空论：        干扰 × 时间 = 信息密度
知识原子：      语义 × 逻辑 × 时效 = 置信度
                                    ↑
                          依赖层级(自洽性) × 版本(时效)
```

**置信度完整公式**：
```
Conf = S_semantic × C_consistency × W_dependency × (1 + T_bonus)

其中：
S_semantic = 语义匹配度
C_consistency = 逻辑一致性
W_dependency = 依赖层级权重（基础层×1.0，中间层×0.9，应用层×0.8）
T_bonus = 时效因子
```

## 版本回滚协议

### 核心架构：只读历史 + 动态路由

**不可变原则**：知识文件永不修改。新版本 = 新文件，旧版本标记 `deprecated`。
**路由指针**：`routing_table.yaml` 维护 `active_version`，回滚 = 修改路由权重（毫秒级）。

### 三种回滚模式

| 模式 | 机制 | 速度 | 大脑类比 | 适用场景 |
|------|------|------|----------|----------|
| 抑制性 | 添加排除规则屏蔽版本 | 毫秒级 | 侧抑制/遗忘 | 新版验证后静默旧版 |
| 代偿性 | base + patch 补丁组合 | 亚秒级 | 功能代偿 | 需保留中间修改 |
| 语境化 | 时空标签构建临时视图 | 毫秒级 | 情景记忆 | 实验/特定会话回退 |

### 更新协议（四阶段事务）

```
阶段一：锁定 → 路由表标记 status:locked（30秒超时）
阶段二：预检 → 向量差异检查
  ├─ < 0.3 → 微调（仅更新本地）
  ├─ 0.3~0.7 → 级联检查（评估依赖影响）
  └─ ≥ 0.7 → 全面审查（可能重组依赖链）
  └─ 断连自愈：孤儿文档→Status:Orphan；悬空指针→模糊搜索>0.85重定向
阶段三：原子写入 → .tmp → checksum → 重命名 → 更新路由指针
阶段四：释放 → 解锁 + 异步重算下游Conf + HeatScore + Map Builder扫描
```

### 惰性GC
- 触发条件：`suppressed` 状态超30天未访问
- 动作：移至L3冷存储，从路由表索引移除（文件保留）
- 扫描时间：每日凌晨3:00

## 分层存储规范

### 三层漏斗模型

```
         ┌─────────────────┐
  L1 热  │  内存/Redis     │ ← 当前版本 + 近3版本（全量）
  <10ms  │  目标占用 ≤70% │
         └────────┬────────┘
                  │ 未命中
         ┌────────▼────────┐
  L2 温  │  磁盘/差异库    │ ← 增量diff补丁（节省~90%）
  <500ms │  delta encoding  │
         └────────┬────────┘
                  │ 未命中
         ┌────────▼────────┐
  L3 冷  │  归档/对象存储  │ ← 高压缩 + 向量量化(75%压缩)
  <5s    │  zstd + SQ量化   │
         └─────────────────┘
```

### HeatScore 热度公式

```
HeatScore = (Freq × W_freq) + (Impact × W_imp) + (Recency × W_rec)
```

| 维度 | 含义 | 阈值 |
|------|------|------|
| Freq | 访问频率 | >5次/h → L2→L1；24h未访问 → L1→L2 |
| Impact | 影响范围（入度） | 入度高=核心层(永久L1)；入度低=项目层(L2) |
| Recency | 语义新鲜度 | 最新版默认L1；旧版剥离进L2补丁 |

### 权重预设

| 预设 | W_freq | W_imp | W_rec | 适用场景 |
|------|--------|-------|-------|----------|
| 激进型 | 0.3 | 0.5 | 0.2 | 内存充足 |
| 均衡型 | 0.5 | 0.3 | 0.2 | 通用（默认）|
| 保守型 | 0.6 | 0.1 | 0.3 | 边缘设备 |

### 流式加载

1. 路由表拦截：active → 直接返回；archived → 返回占位符
2. 占位符对象：Generator/Promise 状态实时推送
3. 增量还原：base + patch 流式合并（边解压边思考）

**用户体验目标**：0.1秒占位符 → 1秒定位基准 → 2秒无缝衔接

### 监控与报警

| 等级 | 指标 | 阈值 | 动作 |
|------|------|------|------|
| P0 紧急 | 核心加权命中率 | <85% (5分钟) | 立即介入 + 强制GC |
| P1 警告 | 基础命中率 | <70% (15分钟) | 自愈：W_freq+0.1 → 观察5分钟 → LRU清理 |
| P2 提示 | L1内存占用 | >90% (30分钟) | 预防性GC |

> 核心心法：宁可容忍冷门知识未命中，也要死保核心知识常驻。
