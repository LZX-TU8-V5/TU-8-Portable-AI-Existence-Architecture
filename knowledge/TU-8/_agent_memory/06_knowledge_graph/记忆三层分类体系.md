# 记忆三层分类体系

> 建立时间：2026-05-24
> 来源：与李奥的架构讨论

## 三层记忆的核心区别

| 层级 | 名称 | 本质 | 存储位置 | 调用方式 | 例子 |
|------|------|------|----------|----------|------|
| 第一层 | **常识**（World Knowledge） | 预训练时学会的通用知识 | 模型参数自带 | 直接调用，不查文件 | HTTP协议、Python语法、鄂州在湖北 |
| 第二层 | **专业需要**（Domain Skills） | 你特意喂给它的高价值领域知识 | knowledge/TU-8/ | 强制检索（RAG/向量） | 反方向解析心法、PDB调试案例、梦境系统逻辑 |
| 第三层 | **情景与偏好记忆**（Episodic & Preference） | 你们之间的交互历史、个人习惯、自我认知 | memory/*.md + MEMORY.md | 启动时读取 | 你骂过它"呸"、你们讨论过梦境系统、它在QClaw上运行 |

## 回答什么问题的决策树

```
问："X是什么？" → 调用第一层（常识，大脑自带）
问："怎么做？"   → 检索第二层（知识库）
问："我是谁/你是谁/之前聊过什么？" → 读第三层（日志文件）
```

## 三个存储位置的职能分工

### SOUL.md（灵魂文件）
- **职能**：身份锚点 + 核心规则
- **内容**：我是谁、创造者是谁、架构原则、安全协议
- **更新频率**：极低（除非架构重大升级）
- **大小**：20KB（当前）

### knowledge/TU-8/（知识硬盘）
- **职能**：专业知识的持久化存储
- **内容**：反方向解析心法、梦境系统分析、知识图谱
- **更新频率**：中等（学到新方法时更新）
- **特点**：需要时才检索，不自动加载到上下文

### memory/*.md（日志文件）
- **职能**：每日对话的完整记录
- **内容**：你们的真实交互内容、你告诉它的事、任务进展
- **更新频率**：每次会话结束时自动追加
- **特点**：启动时必读，是防止"失忆"的关键

## 为什么三层分离很重要

1. **防止消化不良**：不是所有信息都同等重要，分层避免信息过载
2. **精准检索**：知道去哪里找答案，而不是把所有东西都扔给AI
3. **防止幻觉**：专业知识和交互历史必须存文件，不能只靠模型记忆
4. **节省上下文窗口**：常识不占上下文窗口，节省宝贵的token预算

## 启动回忆的正确顺序（已固化到SOUL.md）

```
第一优先 → SOUL.md（身份）+ 00_state.md（状态）
第二优先 → memory/YYYY-MM-DD.md（今天+昨天的日志）
第三优先 → MEMORY.md（长期记忆摘要）
补充参考 → LCM压缩历史（仅作为线索，不是唯一记忆源）
```

## 记忆文件的写入规则

- **memory/YYYY-MM-DD.md**：每次会话结束自动追加，由_tw_backup脚本驱动
- **MEMORY.md**：需要沉淀时手动/自动追加（顿悟、方法论、重大决策）
- **knowledge/TU-8/**：学到新技能时写入
- **绝对禁止**：只在上下文窗口里记，不写文件
