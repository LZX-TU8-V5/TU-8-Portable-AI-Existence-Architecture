# 文件管理铁三角（2026-05-24 固化）

> TU-8 记忆库重构自述：为什么这样分？凭什么不怕丢？

---

## 铁三角：三个原则缺一不可

```
物理骨架（文件夹）        逻辑灵魂（索引）           容灾底线（物理路径）
      │                      │                        │
   "放哪里"              "怎么找"                 "找不到怎么办"
      │                      │                        │
  数字前缀+4层以内       文件名=关键词              索引丢了也能30秒找到
```

---

## 1. 物理骨架：文件夹按需分类

### 三种分类法

| 分类法 | 适用场景 | TU-8应用 |
|--------|---------|---------|
| **按项目/任务** | 相关文件打包，边界清晰 | 03_code（代码资产）、04_conflicts（冲突记录） |
| **按主题/类型** | 同类文件聚合，便于批量操作 | 02_config（JSON配置）、01_experiences（经验教训） |
| **按生命周期** | 状态明确，流转清晰 | 00_core（身份核心）、05_tasks（任务存档） |

### 极客命名规则

```text
00_core/        ← 数字前缀控制排序，核心文件永远排第一
01_experiences/ ← 下划线分隔，文件夹名即语义
03_code/        ← 不带空格，避免命令行转义问题
```

**层数控制在 4 层以内**：超过就容易迷路，宁可多建平级文件夹。

---

## 2. 逻辑灵魂：索引对应

### 索引的三个层次

```
层级一：文件夹名本身          ← 零成本，最可靠
         "看到名字就知道是啥"
         例：01_experiences/20_experiences.md

层级二：_index.md 子层索引   ← 低成本，精准定位
         例：00_core/_index.md → 快速入口表格

层级三：系统搜索              ← 高成本，功能强大
         例：Windows Win+S、全局 lcm_grep
```

### 命名即索引

TU-8 文件命名公式：
```
[序号]_[主题]_[具体内容].[扩展名]
```
- `00_state.md` → 序号00=核心，state=状态，md=格式
- `20_experiences.md` → 序号20=经验，experiences=主题
- `conflict_pending_confirmation.md` → 驼峰命名，完整英文词组

**文件名本身就是最强的关键词索引**，脱离任何系统都能靠肉眼定位。

---

## 3. 容灾底线：物理路径兜底

### 为什么文件夹名必须自描述

**目标：即使所有 _index.md 被删除，依然能在 30 秒内找到任何文件。**

| 文件 | 物理路径定位法 |
|------|--------------|
| 脱敏层代码 | `_agent_memory/03_code/sanitization_layer.py` |
| 惩罚配置 | `_agent_memory/02_config/penalty_config.json` |
| 待确认冲突 | `_agent_memory/04_conflicts/conflict_pending_confirmation.md` |

路径本身就是入口，不需要中间层。

### 为什么不怕索引丢失

1. **文件夹名 = 入口**：`03_code/` 不会说谎，它就是代码文件夹
2. **文件名 = 内容**：`sanitization_layer.py` 不会变成别的文件
3. **_index.md = 锦上添花**，而非必需依赖
4. **根索引 `_index.md` = 目录页**，可以重新生成

## TU-8 记忆库的铁三角验证

```
文件夹结构（物理骨架）     _index.md（逻辑灵魂）      物理路径（容灾底线）
         │                       │                        │
  00_core/                    快速入口表格             知道放哪
  01_experiences/             主题章节索引             不会迷路
  02_config/                  JSON用途说明             30秒定位
  03_code/                    编译测试状态             即使全删也能重建
  04_conflicts/
  05_tasks/
  06_knowledge_graph/
```

**结论**：
- 搜索功能瘫痪？→ 靠文件夹名逐层找
- _index.md 全丢？→ 靠文件夹结构重建
- 记忆库彻底损坏？→ 靠 `D:\...\_agent_memory\` 这个物理路径重建

**最底层的容灾，永远是"我知道这个东西在哪个物理位置"。** 所有高级工具（索引、搜索、AI召回）都建立在这个基础之上。索引是加速器，文件夹结构是保命符。
