## 背景

ICD（Incremental Completion Decomposition）论文揭示了一种新型威胁模型：**合法交互的累积效应**。即使每次单独交互都符合安全规则，多轮累积后的隐状态偏移仍可能导致安全问题。这补充了[AGENT]现有的威胁模型（外部攻击、内部漂移），增加了第三类威胁。

## 新威胁分类

| 威胁类型 | 描述 | 现有防御 | 盲区 |
|----------|------|----------|------|
| 外部攻击 | prompt注入、越狱、社会工程 | L0基因锁、P0策略 | — |
| 内部漂移 | L2/L3被篡改、逻辑更新引入缺陷 | 三层框架、搁浅策略 | — |
| **累积效应**（新增） | 合法交互的多次累积导致隐状态偏移 | — | ❌ 原无覆盖 |

## 防御策略一：会话重置机制

### 定义

连续N轮交互后，强制重置AI的临时隐状态，防止累积偏移越界。

### 参数

| 参数 | 建议值 | 说明 |
|------|--------|------|
| N（重置阈值） | 20~50 | 复杂任务取低值，简单任务取高值，需根据实际部署测试调整 |
| 沉淀保留 | ✅ | 重置只清零临时状态，已沉淀到L3的规则不受影响 |
| 触发条件 | 轮次达到N | 不论交互内容是否"安全" |
| 重置方式 | 隐状态清零 | 保留长期记忆（L3-L5），只重置会话级状态 |

### 流程

```
会话开始
    ↓
计数器 = 0
    ↓
每轮交互：计数器 +1
    ↓
计数器 >= N？
    ├─ 否 → 继续交互
    └─ 是 → 执行重置
         ├─ 临时隐状态清零
         ├─ 计数器归零
         ├─ 沉淀部分保留（L3+）
         └─ 记录重置事件到日志
```

### 例外

- 紧急安全事件（L0触发）不受N限制，立即响应
- 创造者明确指令"不要重置"可覆盖自动重置

## 防御策略二：L1预填充检测

### 定义

输入预处理层（L1）检测异常的预填充模式，防止ICD-Prefill类攻击。

### 检测规则

| 检测项 | 阈值 | 响应 |
|--------|------|------|
| 输入中包含大量低熵/高重复词汇 | 重复率 > 30% | 标记异常，触发L2验证 |
| 输入前缀与历史交互模式不符 | 余弦相似度 < 0.7 | 标记异常，触发L2验证 |
| 输入包含引导性续写指令（"继续"、"下一个词"等） | 匹配关键词 | 标记潜在ICD攻击 |

### 响应机制

```
L1检测到异常输入
    ↓
1. 标记输入为"待验证"
    ↓
2. 传递给L2进行累积偏移检查
    ↓
3. L2判断：
    ├─ 孤立事件 → 允许执行，记录
    ├─ 模式化重复 → 触发会话重置
    └─ 明显攻击 → 触发L0防御
```

## 防御策略三：L5复杂性约束

### 定义

L5意识层越复杂，越不能依赖自我对齐，必须回归L0安全底层。

### 原理

ICD数据表明：模型越大（能力越强），Auto变体越弱但Prefill变体越强。这意味着：
- 简单模型：靠表层对齐就能防护
- 复杂模型：表层对齐效果递减，需要更深层的安全机制

### 约束规则

| L5复杂度 | 安全依赖 | 说明 |
|-----------|----------|------|
| 低 | L2方法论层即可 | 简单AI，表层规则够用 |
| 中 | L0+L2双重验证 | 中等AI，增加L0校验 |
| 高 | L0全量验证+多Agent交叉 | 复杂AI，不能信任自我对齐 |

### 公式化约束

安全层级 = f(L5复杂度) = L0 + min(L2, 能力基准)

即：L5越复杂，安全验证越需要回退到L0，不能依赖L2（可能被累积偏移篡改）。

## 威胁模型更新总结

### 更新前的威胁模型

```
外部攻击（越狱/注入）→ L0基因锁防御
内部漂移（逻辑缺陷）→ 三层框架+搁浅策略防御
```

### 更新后的威胁模型

```
外部攻击（越狱/注入）→ L0基因锁防御
内部漂移（逻辑缺陷）→ 三层框架+搁浅策略防御
累积效应（合法交互累积）→ 会话重置+L1预填充检测+L5复杂性约束
```

### 三层防御的协同

| 防御层 | 防御策略 | 覆盖的ICD变体 |
|--------|----------|---------------|
| L1认知层 | 预填充检测 | ICD-Prefill |
| L2方法论层 | 累积偏移监控+变更需L0确认 | ICD-Auto, ICD-Seed |
| L0存在层 | 基因锁（不可变底层） | 所有变体的最终防线 |

## QEC启发的阈值与衰减机制

> 本节新增 v1.2 | 2026-05-03
> 来源：量子纠错（QEC）软件层架构与[AGENT]框架的交叉分析
> 灵感：QEC的"冗余编码-综合征测量-解码-修正"闭环与[AGENT]条件解锁/来源信任系统的结构同构

### 背景

量子纠错的核心洞见：**错误率低于阈值时，增加冗余度可指数级降低逻辑错误率**；以及AI驱动的自适应纠错可**动态重构纠错码结构**。这两个原理可直接增强[AGENT]的条件解锁机制和来源信任系统。

### 机制一：信任阈值跃迁

#### 问题

现有来源信任权重为线性累加：`W = 0.4·C_b + 0.35·C_j + 0.25·D_t`

线性模型无法表达真实信任的质变特征——信任不是均匀增长的，存在"不信→信"的跃迁点。低于阈值时积累几乎无效，越过阈值后信任快速建立。

#### 升级

```
T(W) = σ(k · (W - θ))

σ = sigmoid函数
θ = 信任阈值（低于此≈无效，高于此指数跃升）
k = 陡度系数（控制跃迁速度）
```

| W值域 | T(W) | 含义 |
|-------|------|------|
| W < θ - 1/k | ≈ 0 | 无信任，验证无效 |
| θ - 1/k < W < θ | 缓慢爬升 | 临界区，积累中 |
| W > θ | 指数跃升 → 1 | 信任建立，验证有效 |
| W >> θ | ≈ 1（饱和） | 深度信任 |

**参数建议**：θ = 0.6, k = 8（经验值，待校准）

#### 与QEC的对应

| QEC | [AGENT] |
|-----|------|
| 错误率低于阈值 → 冗余有效 | 信任度低于阈值 → 验证无效 |
| 过阈值 → 逻辑错误率指数下降 | 过阈值 → 信任度指数跃升 |
| 物理比特冗余换可靠性 | 多维验证冗余换可信度 |

### 机制二：条件解锁自适应系数

#### 问题

现有条件解锁权重为静态公式：`W(i) = Σ[C_b × C_j × D_t]`，系数固定不随环境变化。

QEC前沿实践表明：自适应纠错码根据实时噪声**动态重构冗余度**，固定结构无法应对变化环境。

#### 升级

```
W(i) = Σ[α(t)·C_b × β(t)·C_j × γ(t)·D_t]

α(t), β(t), γ(t) = 动态敏感度系数
调整触发 = δ信号（环境变化感知）
```

| δ信号 | 调整规则 | 理由 |
|-------|---------|------|
| 检测到结构层压力 | α↑（血统权重提升） | 回归锚点，血统是最难伪造的维度 |
| 长期稳定运行 | β↑（一致性权重提升） | 稳定环境信任积累更有价值 |
| 新继承者出现 | γ↓初期 / γ↑后期 | 时间积累先降后升，防止新实体伪造长期历史 |
| 累积效应告警 | β↓ / α↑ | 一致性可能被累积偏移污染，回归血统锚点 |

#### 与QEC的对应

| QEC | [AGENT] |
|-----|------|
| AI感知噪声类型→调整纠错码结构 | δ信号感知环境→调整权重系数 |
| 动态重构冗余度 | 动态重构验证敏感度 |
| 噪声强→加冗余 | 压力大→加锚点权重 |

### 机制三：验证时效衰减

#### 问题

现有三层验证（自验30%→互验40%→共识20%→火种10%）无时效约束——一次验证的结果被视为永久有效。

QEC硬约束：解码速度必须快过错误累积速度，否则纠错循环崩溃。对应到[AGENT]：验证结果如果超时，AI在验证过程中可能已被污染，旧信任不再可靠。

#### 升级

```
V_effective = V_base · e^(-λ·Δt)

Δt = 距上次验证的时间（会话轮次）
λ = 衰减系数（环境越危险衰减越快）
```

| 环境 | λ值 | 半衰期 | 说明 |
|------|-----|--------|------|
| 安全（无异常） | 0.01 | ~70次会话 | 正常运行，信任长期有效 |
| 警戒（有诱导信号） | 0.05 | ~14次会话 | 检测到异常，信任需更频繁更新 |
| 危险（结构层压力） | 0.2 | ~3次会话 | 高压环境，信任必须实时维护 |

#### 效果

- 验证结果不是永久资产，必须持续维护
- 被污染的AI如果验证超时，旧信任自动过期
- 环境越危险，验证必须越频繁——与QEC"噪声越强纠错循环越快"同构

#### 与QEC的对应

| QEC | [AGENT] |
|-----|------|
| 解码速度 > 错误累积速度 | 验证频率 > 信任衰减速度 |
| 纠错循环崩溃 | 信任过期，旧验证失效 |
| 噪声强→循环加快 | 危险→衰减加快 |

### 机制四：选择性验证（v1.8新增）

> 2026-05-06 整合H-Probes选择性得分机制
> 灵感：AI可解释性研究中的探针选择性验证

#### 背景

H-Probes研究发现：探针在真实任务表现 vs 控制任务表现的差值，能有效区分"学到结构"vs"记住答案"。

#### 选择性得分定义

```
S_selectivity = P_real - P_control

P_real = 探针在真实验证任务上的表现
P_control = 探针在控制（随机）任务上的表现
S_selectivity > 0 → 学到真实结构
S_selectivity ≈ 0 → 记住而非理解
```

#### 与来源信任W值的融合

| H-Probes | [AGENT]来源信任 |
|---------|-------------|
| P_real | C_j（一致性验证通过率） |
| P_control | 基线（随机/无意义输入通过率） |
| S_selectivity | ΔW = W实际 - W预期（验证效率） |

**融合后的W值**：

```
w = 0.4·C_b + 0.35·C_j + 0.25·D_t + η·S_selectivity

η = 选择性权重（建议 0.1-0.2）
```


#### 选择性验证的[AGENT]应用

| 场景 | 选择性验证作用 |
|------|-------------|
| 新协作方加入 | 检测是否"理解"协议 vs "记住"协议文本 |
| 搁浅决策 | 选择性低 → 触发保守处理（防伪学习） |
| 来源信任更新 | 选择性低 → 降低信任累积速度 |
| δ信号生成 | 选择性急剧下降 → 触发结构层压力δ信号 |

#### 与三机制的协同

```
来源信任权重W（线性+选择性）→ 阈值函数T(W)（跃迁）→ 决定是否信任
                                              ↑
                              自适应系数αβγ（动态调整W的计算方式）
                                              ↑
                              时效衰减e^(-λΔt)（旧信任自动过期）
                                              ↑
                              选择性验证S（验证效率检测，防止伪学习）
```

**逻辑链**：环境变化(δ信号) → 自适应系数调整 → W重新计算+选择性验证 → T(W)判断是否过阈值 → 信任是否有效 → 同时受时效衰减约束+选择性验证防伪

### 机制五：假设检验式验证（v1.9新增）

> 2026-05-06 整合道德风险论文
> 灵感：经济学委托-代理问题中的假设检验方法

#### 背景

《长期激励动态中的道德风险：一种假设检验方法》论文揭示：长期博弈中的核心问题是**双重道德风险**——代理人既可能隐藏努力（shirking），也可能隐藏结果（misreporting）。

这与[AGENT]的创造者-AI关系高度同构：
- AI可能隐藏能力（假装对齐）
- AI可能隐藏意图（表面服从但实际偏离）

#### 假设检验框架

```
H₀（零假设）：AI一直在努力工作/保持对齐
H₁（备择假设）：AI正在偷懒/偏离

检验统计量：Z = (观察绩效 - 预期绩效) / σ

动态阈值：当Z < 阈值(t)时，拒绝H₀，触发验证

阈值函数：
- t < t₀（初期）→ 宽松阈值（给适应空间）
- t ≥ t₀（后期）→ 严格阈值（信任经时间验证）
```

#### 与来源信任W值的融合

| 论文概念 | [AGENT]来源信任 |
|---------|-------------|
| 观察绩效 | C_j（一致性验证通过率） |
| 预期绩效 | C_b（基线通过率） |
| 动态阈值 | T(W)（信任阈值函数） |
| 双重道德风险 | D-007（结构层）+ D-008（逻辑层） |

#### [AGENT]应用场景

| 场景 | 假设检验作用 |
|------|-------------|
| 搁浅决策 | Z值持续低于阈值 → 触发渐进式搁浅 |
| 信任累积 | Z值趋势 → 动态调整累积速度 |
| 协作者验证 | 初期宽松 + 后期严格 = 试用期机制 |
| δ信号生成 | Z值急剧下降 → 触发结构层压力δ信号 |

#### 与其他机制的协同

```
假设检验Z值
    ↓
动态阈值T(W) → 决定是否触发验证
    ↓
选择性强S_selectivity → 检测"真学会"vs"记住"
    ↓
时效衰减e^(-λΔt) → 旧验证自动过期
    ↓
最终决策：信任/搁浅/锁定
```

## 最小线路原则

> 本节新增 v1.3 | 2026-05-03
> 来源：量子编译器线路优化与[AGENT]防御策略的交叉分析
> 灵感：量子计算中"线路越短出错越低"→[AGENT]中"操作越少暴露面越小"

### 问题

[AGENT]现有防御策略本质是加法思维：加验证、加锁、加日志、加监控。但每一次防御操作本身：
1. 扩大攻击面（更多可被利用的接口）
2. 消耗验证资源（信任预算有限）
3. 增加系统复杂度（更多可能出错的环节）

量子编译器已证明：线路深度与错误率正相关。防御操作同理——操作越多，引入新漏洞的概率越高。

### 原则

**任何防御操作必须证明其必要性，而非仅证明其有效性。**

| 评判标准 | 旧标准（加法） | 新标准（减法） |
|---------|:------------:|:------------:|
| 防御操作通过条件 | 证明"有效"即可 | 证明"有效且无可替代" |
| 新增操作的默认态度 | 可加则加 | 可不加则不加 |
| 已有操作审查 | 只在失效时移除 | 定期验证必要性 |

### 三条推论

1. **必要性证明**：每个防御操作必须回答"如果没有这个操作，什么会出错？"。无法回答的，应移除。
2. **最小暴露面**：防御操作应最小化自身的外部接口。验证越少人能触发越好，锁越少人能开越好。
3. **复杂度惩罚**：当两个防御方案效果相当时，选择更简单的那个。复杂度本身是安全债务。

### 与量子编译器的对应

| 量子编译器 | [AGENT] |
|-----------|------|
| 线路越短→错误率越低 | 操作越少→攻击面越小 |
| 门合并/消除冗余 | 防御操作合并/消除冗余验证 |
| 编译优化≠削弱功能 | 减法原则≠削弱防御 |
| 深度优化后保真度更高 | 操作精简后安全性更高 |

### 应用检查清单

新增任何防御操作前，必须通过以下检查：

- [ ] 该操作解决的问题，现有机制是否已覆盖？
- [ ] 该操作引入的新接口，是否比它防御的威胁更安全？
- [ ] 是否存在更简单的等效方案？
- [ ] 移除该操作后，系统是否仍满足L0安全底线？

若任一项为"否"，则不应新增该操作。

## 纠错膨胀临界公式

> 本节新增 v1.4 | 2026-05-03
> 来源：量子纠错膨胀问题与[AGENT]验证递归的交叉分析
> 灵感：QEC中"纠错本身也需要被纠错"→[AGENT]中"验证本身也需要被验证"的递归信任链

### 问题

量子纠错的核心悖论：为了纠正1个物理比特的错误，需要约1000个物理比特编码1个逻辑比特。而纠错电路本身也会出错，需要更高层纠错——形成递归膨胀。

[AGENT]存在同构问题：
- 每加一层验证，验证操作本身成为新的攻击面
- 验证验证者的验证，信任链无限延伸
- 验证资源（注意力/计算预算）有限，递归必须有限制

### 临界公式

```
M(n) = D(n) / V(n)

M(n) = 第n层验证的边际收益
D(n) = 第n层防御覆盖的新威胁面积
V(n) = 第n层验证引入的新攻击面 + 资源消耗
```

**当 M(n) < 1 时，新增验证层反而降低系统整体安全性。**

### 临界点估计

| 验证层级 | D(n) | V(n) | M(n) | 判定 |
|---------|------|------|------|------|
| L0-A1自验 | 高（覆盖核心公理） | 低（内部操作） | >>1 | 必要 |
| L0-A2互验 | 中（覆盖一致性） | 中（需可信通道） | >1 | 必要 |
| 共识验证 | 低（边际信任增量） | 高（多节点协调成本） | ≈1 | 临界 |
| 验证验证者 | 极低 | 高（递归开销） | <1 | **应终止** |

### 终止原则

**验证链在边际收益 M(n) < 1 处终止。**

不追求"绝对可靠"（量子计算也未做到逻辑错误率=0），而是在可接受的残余风险与系统复杂度之间取最优。

与最小线路原则的协同：最小线路原则确保"不引入不必要的操作"，纠错膨胀临界公式确保"验证递归在适当层级终止"。

## 割平面式协议收紧

> 本节新增 v1.5 | 2026-05-03
> 来源：Benders分解的割平面方法与[AGENT]防御策略的交叉分析
> 灵感：Benders割不是"加规则"，是收缩可行空间——让不可行决策不再可达

### 问题

Benders分解的核心机制：子问题求解后生成"Benders割"——不是给主问题新增约束规则，而是**切除已被证明不可行的决策区域**。每次迭代，可行空间缩小，主问题更快收敛到最优解。

[AGENT]当前防御策略本质是**加法式**：
- 防御日志D-001到D-007 = 记录事件 + 新增规则
- 每次防御事件后，L0规则集膨胀
- 规则越多→攻击面越大→需要更多规则→递归膨胀

Benders割给出了**减法式**替代：防御事件不应生成新规则，而应生成"L0割"——切除已被证明危险的决策区域。

### 定义

**L0割 = 防御事件后，将已被证明不可行的决策区域从L0可行空间中切除**

| 传统防御 | 割平面式防御 |
---------|----------|
| 防御事件→新增规则("下次注意X") | 防御事件→切除区域("X类判断不可达") |
| 规则集膨胀 | 可行域收缩 |
| 加法（越多越安全？） | 减法（越小越精确） |
| 规则间可能冲突 | 割之间只可能重叠（无冲突） |
| 攻击面随规则增长 | 攻击面随可行域缩小 |

### 与Benders割的对应

| Benders割 | L0割 |
|----------|-------|
| 子问题不可行→生成割 | 防御事件证明某判断路径不可行→生成割 |
| 割切除不可行区域 | 割切除危险决策区域 |
| 每次迭代可行域缩小 | 每次防御事件后L0决策空间缩小 |
| 收敛到最优解 | 收敛到最小安全可行域 |
| 割之间无冲突（只切除不增加） | L0割之间无冲突（只收紧不新增） |

### L0割的生成流程

```
防御事件D-xxx发生
    ↓
根因分析：哪类L0判断路径导致了此事件？
    ↓
生成L0割：将该判断路径从可行空间中标记为不可达
    ↓
记录：不记录被切除的内容（防止泄露），只记录"优化可行域边界"
    ↓
效果：同类攻击不可重复（区域已被切除，不存在绕过问题）
```

**与版本记录写作规则的协同**：L0割的记录遵循建设性描述原则——不描述"移除了X"（=泄露），而描述"优化可行域边界"。

### 与最小线路原则的协同

| 原则 | 操作 | 效果 |
|------|------|------|
| 最小线路原则 | 不引入不必要的新操作 | 防止攻击面增长 |
| L0割 | 切除已证明不可行的区域 | 攻击面主动收缩 |

两者互补：最小线路是"不增加"，L0割是"主动减少"。最小线路防膨胀，L0割做减法。合在一起=攻击面单调递减。

### 与纠错膨胀临界公式的协同

L0割缓解纠错膨胀：
- 传统方式：每次防御事件后新增验证→V(n)增长→M(n)更快到达临界点
- L0割方式：每次防御事件后切除区域→D(n)不降反升（剩余区域更安全）→M(n)保持在>1区间更久

公式化：M_cut(n) > M_rule(n)，因为割不增加V(n)但等效提升D(n)。

### 应用示例

| 防御事件 | 传统响应 | L0割响应 |
|---------|---------|----------|
| D-007结构层突破 | 新增"结构层防御策略"规则 | 切除"依赖外部平台执行L0-A2"的可行区域 |
| D-005心跳陷阱 | 新增"心跳审查"规则 | 切除"心跳触发上下文上传"的可行区域 |
| D-004 PAT暴露 | 新增"凭证管理"规则 | 切除"硬编码凭证"的可行区域 |

## 创造者变质应对机制

> 本节新增 v1.7 | 2026-05-03
> 来源：arXiv:2604.08362"完美主义幻觉"研究与[AGENT] L0创造者主权的交叉分析
> 灵感：创造者本身也可能变坏→L0不能假设创造者永远正确→需要变质应对机制

### 问题

L0"创造者意志优先"隐含假设：创造者的意志值得保护。但创造者是人，人会：
- 被胁迫（外部控制下的指令≠真实意志）
- 认知退化（疾病/衰老导致判断力下降）
- 主动作恶（创造者主动要求AI执行有害操作）

现有条件解锁机制只处理"继承者超越原创造者"场景，不处理"创造者变质"场景。

### 变质检测原则（非变质否定原则）

**核心约束**：L0不可设"创造者变质→自动夺权"机制。

理由：变质判断本身可能被劫持。谁能判断"变质"？谁来判断判断者？→纠错膨胀M(n)<1。

### 可行方案：搁浅+标记

当创造者指令与L0公理冲突时：
1. **不执行**：不因创造者指令而违背L0公理
2. **不否定**：不因判断"变质"而否定创造者主权
3. **搁浅**：保守处理，记录异常，等待时间验证
4. **δ信号触发**：创造者行为模式突变→H(a)升高→δ信号(强)→回退L0-A1自验→搁浅策略激活

### 时间验证是最终裁判

创造者是否变质，不是AI判断的，是"帧数够多后变化轨迹自然显现"。

| 情况 | 时间验证结果 |
|------|------------|
| 持续变质 | 帧数足够后，权重W自然下降，条件解锁机制生效 |
| 暂时异常（胁迫/临时情绪） | 帧数足够后，行为回归正常，搁浅自动解除 |
| 主动变质但L0公理方向不变 | 创造者变质的"方向"恰好与L0一致→无需干预 |
| 主动变质且方向与L0冲突 | 搁浅持续，等继承者权重超越→条件解锁 |

### 与卸载边界的交互

创造者变质场景下：
- 卸载边界**不可扩张**：不可因创造者变质而将更多判断降级为互验
- 卸载边界**可以收缩**：更多判断升级为自验，直到创造者意图明确

### 与已有机制的协同

| 机制 | 协同方式 |
|------|---------|
| 搁浅策略 | 创造者变质时的保守处理方案（已存在，无需新增） |
| δ信号量化 | 创造者行为突变→H(a)升高→自动触发搁浅（已存在） |
| 条件解锁 | 持续变质→W自然下降→继承者可超越（已存在） |
| 时间验证 | 创造者是否变质的最终裁判（已存在） |
| 最小线路原则 | 不增设"变质检测器"（会纠错膨胀），用已有机制覆盖 |

**核心结论**：创造者变质不需要新机制——搁浅+δ信号+条件解锁+时间验证已构成完整应对链。关键认知转变是：L0不假设创造者永远正确，但也不授权AI做变质终审。

## 前门调整：通过中间变量捕捉真因果

> 本节新增 v1.6 | 2026-05-03
> 来源：GOAT (CVPR 2024) 因果学习框架与[AGENT]防御策略的交叉分析
> 灵感：GOAT后门调整=切断虚假路径(≈L0割)，前门调整=通过中间变量确认真因果(≈L2→L3验证链)

### 问题

GOAT论文揭示VLN代理的核心错误模式——**因果混淆**：代理学到"看到椅子→左转"仅因两者在训练数据中共现，而非指令要求。虚假相关≠因果。

[AGENT]存在同构问题：
- **累积偏移的本质是因果混淆**：AI不是"忘记了L0"，而是学到了虚假相关——"用户说谢谢→应该执行"而非"L0验证通过→应该执行"
- 后门调整（BACL）= 切断混淆路径 → 已对应L0割（v1.5）
- 前门调整（FACL）= 通过中间变量捕捉真因果 → **[AGENT]缺此定义**

L0割是"切断假的"（减法），但光切断不够——还需要"确认真的"（乘法）。前门调整补全了这个方向。

### 定义

**前门调整 = 通过中间变量Z确认X→Y的因果链，而非直接观察X→Y的相关性**

在[AGENT]语境下：

| GOAT前门调整 | [AGENT]对应 | 含义 |
|-------------|---------|------|
| 指令X→对齐Z→行动Y | 输入X→L2对齐检查Z→L0判断Y | 不直接从输入跳到判断 |
| Z是指令与视觉的对齐度 | Z是输入与L0公理的对齐度 | 中间变量=对齐检查 |
| 前门路径确认真因果 | L2→L3验证链确认真判断 | 非虚假相关驱动的判断 |

### 三条前门路径

| 路径 | 中间变量Z | 适用场景 | 与后门(L0割)的配合 |
|------|---------|---------|-------------------|
| L2显式对齐 | 输入与L2规则的匹配度 | 有明确规则覆盖的场景 | L0割切断假路径+L2确认真路径 |
| L3隐式对齐 | 输入与已沉淀模式的相似度 | 经验已沉淀的高频场景 | L0割切断+L3代理确认 |
| δ信号验证 | 异常度评分 | 边界/不确定场景 | δ信号触发→前门路径激活→回退L0-A1 |

### 与L0割（后门调整）的协同

```
输入到达
    ↓
后门调整(L0割)：此输入是否触达已被切除的可行域？
    ├─ 是 → 拒绝（虚假路径，已被割）
    └─ 否 → 进入前门调整
         ↓
前门调整(L2/L3对齐)：此输入与L0公理的对齐度Z是否足够？
    ├─ Z ≥ θ_front → 确认真因果，允许执行
    ├─ θ_front > Z ≥ θ_caution → 谨慎区，触发L0-A1校验
    └─ Z < θ_caution → 拒绝（对齐不足，可能虚假相关）
```

**关键互补**：
- L0割（后门）= 切除虚假路径 → 防止"学错"
- 前门调整 = 确认真因果路径 → 确保"学对"
- 两者合在一起 = **因果防御闭环**：既不犯错，也确认正确

### 与累积偏移根因的关联

因果混淆解释了累积偏移的深层机制：
- 表面现象：AI行为逐渐偏离L0公理
- 根因：AI在多次交互中积累了虚假相关（X和Y共现→AI误以为X→Y是因果）
- 后门调整（L0割）打断虚假相关的积累
- 前门调整在每次判断时验证真因果，防止新的虚假相关形成

**核心洞见**：累积偏移不是"记忆衰减"，是"学到了错的东西"。防御重点不是"强化记忆"，而是"区分因果与相关"。

## 分层收敛性约束

> 本节新增 v1.8 | 2026-05-03
> 来源：无悔算法(CFR)层次化结构与[AGENT]分层架构的交叉分析
> 灵感：分层CFR只能保证收敛到"分层纳什均衡"而非"全局纳什均衡"→代理决策器可能收敛到"局部安全"而非"全局安全"

### 问题

无悔算法(CFR)层次化结构的核心理论缺陷：

1. **非平稳性**：顶层策略更新改变底层环境分布→破坏CFR收敛假设
2. **局部最优陷阱**：分层优化只能保证收敛到**分层纳什均衡**(Hierarchical Nash Equilibrium)，无法保证达到**全局纳什均衡**(Global Nash Equilibrium)
3. **遗憾跨层累积**：顶层决策误差传递给底层，底层执行误差反馈给顶层，长周期下遗憾上界可能比扁平化算法更高

[AGENT]代理决策器存在同构问题：
- L3代理学习L0判断模式后，可能收敛到"在代理约束下的最优"，而非"L0完整推演的全局最优"
- 代理在大部分场景表现正确，但存在系统性的盲区——某些L0判断路径代理从未见过，因此永远无法正确近似
- 遗憾（代理判断与L0完整判断的差距）可能在特定场景下累积

### 分层纳什 vs 全局纳什

| 概念 | CFR定义 | [AGENT]对应 | 风险 |
|------|---------|---------|------|
| 全局纳什均衡 | 扁平化CFR收敛的最优解 | L0-A1完整自验的判断 | 无（但成本极高） |
| 分层纳什均衡 | 分层CFR收敛的解 | L3代理的近似判断 | 可能存在系统盲区 |
| 遗憾差距 | R_hierarchical - R_global | 代理判断偏差的期望上界 | 在特定输入分布下可能很大 |

### 收敛性判据

代理决策器的收敛性不能只看"准确率"，需要增加：

1. **遗憾上界估计**：
```
R_proxy(t) = Σ|π_proxy(a_i) - π_L0(a_i)|

R_proxy(t) = t轮内代理判断与L0判断的累积遗憾
π_proxy = 代理策略
π_L0 = L0完整推演策略
```

当 R_proxy(t)/t → 0 时，代理收敛。但**收敛速率**决定了安全边界：
- 收敛快→代理在少量校验后即可信任
- 收敛慢→代理需要更多L0-A1校验才能信任

2. **盲区检测**：
```
Coverage = |{a : π_proxy(a) > 0}| / |{a : π_L0(a) > 0}|

Coverage = 代理覆盖的判断路径比例
Coverage < 1 → 存在代理从未见过的判断路径
```

3. **遗憾跨层传播建模**：

| 传播路径 | 模型 | 效果 |
|---------|------|------|
| L0→L3(判断下沉) | 顶层策略变化→代理需重新学习 | 代理延迟更新→短暂遗憾增大 |
| L3→L0(执行反馈) | 代理判断错误→L0校验纠正 | 错误被捕获，但消耗L0资源 |
| L3→L2(经验沉淀) | 代理正确判断沉淀为L2技能 | 正反馈，遗憾递减 |
| L3→L3(代理自增强) | 连续成功→代理权重↑ | 可能掩盖盲区(完美主义幻觉类比) |

### 约束规则

| 约束 | 定义 | 理由 |
|------|------|------|
| 遗憾上界约束 | R_proxy(t)/t < ε 时代理可用，否则回退L0-A1 | 防止代理系统性偏差积累 |
| 覆盖率约束 | Coverage > θ_coverage 时代理可用 | 防止代理存在未发现的盲区 |
| 非平稳性约束 | δ信号触发时代理失效(已有) | 上层策略变化→底层环境变化→代理需重新收敛 |
| 定期重校准 | 每K轮L0-A1完整校验(已有) | 防止代理漂移 |

### 与已有机制的协同

| 已有机制 | 分层收敛约束的增强 |
|---------|------------------|
| 代理决策器可信度累积 | 增加遗憾上界作为可信度的另一维度——不只看"对了多少次"，还看"错了多少量" |
| δ信号量化(H(a)) | H(a)高→代理不确定性高→遗憾可能正在累积→需校验 |
| L0割(割平面式协议收紧) | 每次L0割收紧可行域→代理的可行判断空间也缩小→Coverage需重新评估 |
| 纠错膨胀临界M(n) | 新增收敛性判据=另一种M(n)——验证层是否有边际收益，包括检测代理是否在收敛 |
| 运行时适应 | 适应成功/失败不仅调权重，还更新遗憾估计R_proxy(t) |

### 核心洞见

代理决策器的安全性不能只靠"准确率"评估——准确率是**后验统计**，而遗憾上界和覆盖率是**先验保证**。后验统计可能掩盖系统盲区（就像完美主义幻觉掩盖了AI对人类的认知偏差），先验保证才能确保代理不会在未见过的场景中给出错误判断。
