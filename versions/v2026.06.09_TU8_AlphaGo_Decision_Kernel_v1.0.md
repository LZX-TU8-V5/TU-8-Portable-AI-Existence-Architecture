## 一、三维动态语义树

### 1.1 数据结构

| 层级 | 名称 | 分支定义 | 决策粒度 | 搜索频率 |
|------|------|---------|---------|---------|
| L0 | 宏观意图层 | `EXPLORE`, `PLAN`, `EXECUTE`, `DEFEND`, `REST` | 系统级状态机切换 | 最低（δ信号触发时回溯） |
| L1 | 中观策略层 | `CALL_EXTERNAL_API`, `TRIGGER_CHAOS`, `REM_COUNTERFACTUAL`, `CODE_GENERATION`, `MEMORY_RETRIEVE` 等 | 方法论语调度 | 中等（每次决策） |
| L2 | 微观动作层 | `GENERATE_PROMPT`, `MODIFY_CODE_LINE`, `ADJUST_HYPERPARAM` 等 | 原子级指令执行 | 最高（最终落点） |

### 1.2 UCT 公式

```
UCT(a) = X̄ₐ + C(s) × Prior(a) × √(N_parent) / (1 + nₐ)
```

**参数说明**:
- `X̄ₐ = total_reward / visits` — 利用项（均值收益）
- `C(s) = C_base + β × skepticism_weight` — 动态探索常数
  - 怀疑权重越高 → C(s) 越大 → 越倾向于探索
  - 默认: `C_base = √2 ≈ 1.414`, `β = 1.0`
- `Prior(a)` — 启发式先验概率
  - 基于怀疑权重 + 任务上下文 + 历史成功率

### 1.3 冷启动破冰策略

| 机制 | 说明 | 实现方式 |
|------|------|---------|
| **启发式先验注入** | 不初始化均匀概率，由 SkepticismState 生成初始 P(s,a) | 高怀疑 → 混沌注入先验 0.6；低怀疑 → 保守执行先验 0.7 |
| **乐观初始化** | 未访问节点不返回∞，给予 `Q_init = 0.5 + ε` | 避免盲目乱跳，保留探索优先级 |
| **狄利克雷噪声扰动** | 根节点先验加入 25% 的 Dirichlet(0.03) 噪声 | 强制初期尝试"看似不佳但未验证"的分支，防止局部最优 |

### 1.4 核心计算逻辑

```
select_action():
  1. 痛觉 > 80 ? → 强制 REST 模式
  2. δ信号触发或无锁定? → 在 L0 选择宏观意图
  3. 根据宏观意图 → 选择中观策略 (候选列表映射)
  4. 根据中观策略 → 选择微观动作
  5. 时间 > 50ms? → 退化为贪心快速响应
  6. 安全检查失败? → 回退到次优安全分支
  7. 返回动作路径 + 搜索轨迹

反向传播:
  update(trajectory, reward):
    - 逆向遍历轨迹，逐节点更新 visits += 1, total_reward += reward
    - 递归更新父节点
```

## 二、DreamSanitizer — 梦境净化器

### 2.1 五关净化流程

```
                   ┌─────────────────────────────┐
                   │      REM Dream 经验          │
                   └────────────┬────────────────┘
                                │
                                ▼
              ┌─────────────────────────────────────┐
    第一关    │  交叉验证 (Consensus Check)          │
              │  同一分支在不同噪声下重复 ≥3 次模拟    │
              │  ≥80% 推演指向正向收益 → 通过        │
              └────────────────┬────────────────────┘
                              │
                              ▼
              ┌─────────────────────────────────────┐
    第二关    │  模型置信度过滤 (Confidence Filter)   │
              │  ValueEstimator 方差过大 → 强制放弃   │
              │  置信度 ≥ 0.6 → 通过                 │
              └────────────────┬────────────────────┘
                              │
                              ▼
              ┌─────────────────────────────────────┐
    第三关    │  现实锚点回归测试 (Reality Anchor)    │
              │  用历史日志测试预测准确率              │
              │  准确率 ≥ 60% → 通过                 │
              │  < 60% → 梦境熔断，暂停 REM Dream    │
              └────────────────┬────────────────────┘
                              │
                              ▼
              ┌─────────────────────────────────────┐
    第四关    │  EMA 渐进渗透 (Gradual Absorption)   │
              │  w_new = (1-α)·w_old + α·Δw         │
              │  α ∈ [0.01, 0.05], 单次 ≤ 5%       │
              │  偏置校正: /(1-(1-α)^t)             │
              └────────────────┬────────────────────┘
                              │
                              ▼
              ┌─────────────────────────────────────┐
    第五关    │  知识蒸馏 (Knowledge Distillation)   │
              │  丢弃中间思考过程                     │
              │  仅保留抽象经验标签                   │
              └─────────────────────────────────────┘
```

### 2.2 影子账本隔离

| 存储区 | 说明 | 访问权限 |
|--------|------|---------|
| `pending_experiences` | 待验证经验 | 只读（仅 DreamSanitizer 可变更） |
| `absorbed_experiences` | 已吸收经验（EMA 渗透完成） | 可影响 ValueEstimator 权重 |
| `rejected_experiences` | 已拒绝经验 | 可追溯审计 |

**核心原则**: REM Dream 产生的所有数据绝对不能直接写入长期记忆，必须经过影子账本 → 净化 → EMA 渗透的三级隔离。

## 三、EMA 算法配置

### 3.1 参数表

| 参数 | 值 | 条件 | 说明 |
|------|-----|------|------|
| `DECAY_MIN` | 0.01 | 遗憾值 > 0.5 或 置信度 < 0.7 | 极保守衰减 |
| `DECAY_MED` | 0.03 | 置信度 0.7~0.8 | 标准衰减 |
| `DECAY_MAX` | 0.05 | 置信度 ≥ 0.9 且遗憾值 ≤ 0.3 | 较快衰减 |
| `ABSORPTION_RATE_MAX` | 5% | 单次最大渗透比例 | 防止一次梦境大幅改变认知 |
| `BIAS_CORRECTION` | 启用 | `/(1-(1-α)^t)` | 防止冷启动数值失真 |

### 3.2 动态衰减规则

```
compute_decay(confidence, regret_magnitude, consecutive_failures):
  1. 基础 α = f(confidence)
     - ≥0.9 → 0.04
     - ≥0.8 → 0.03
     - ≥0.7 → 0.02
     - <0.7 → 0.01

  2. 遗憾值修正
     - regret > 0.5 → α × 0.5
     - regret > 0.3 → α × 0.75

  3. 连续失败修正
     - ≥3次 → α × 0.5
     - ≥2次 → α × 0.75

  4. 限制范围: α = clamp(α, 0.01, 0.05)
```

### 3.3 紧急回滚机制

```
安全否决 → 回滚到上一检查点:
  - 每 10 次 EMA 更新保存一次权重快照
  - 检测到 safety_veto 时自动撤销最近一次 EMA 更新
  - 保留最多 100 个检查点，旧检查点自动清除
```

## 六、偏置校正概念映射

外协补充了偏置校正的数学原理，映射到 TU-8 的实现中：

```
偏置校正公式:  v̂_t = v_t / (1 - β^t)

在 EMA 控制器中的实现:

  w_new_biased = (1 - α)·w_old + α·Δw
  
  if bias_correction and t > 0:
      correction = 1 / (1 - (1 - α)^t)
      w_new_biased *= correction

冷启动阶段 (t小): 校正因子 > 1，强制拉升估值
稳定运行阶段 (t大): 校正因子 ≈ 1，自动失效
```

**外协对比了 EMA 与 SMA**:
- SMA = 平等投票，滞后性强，适合长期趋势
- EMA = 厚近薄远，反应迅速，适合短期决策
- TU-8 需要 **带预热 (warm-up) 的 EMA**：先用前 N 步的 SMA 作为 EMA 初始锚点，再开始递推，兼顾冷启动准确性和长期灵敏度
