## ⚙️ 重构分级制（v1.0）

> 目的：在执行重构前自动判定任务等级，确定审查流程

### 等级定义

| 等级 | 名称 | 审查要求 | 触发条件 |
|------|------|---------|------|
| L | 轻量 | 免查架构日志，直接执行 | 拼写修复、注释增加、变量重命名、非核心文件移动 |
| M | 中等 | 查架构日志摘要 + 记录 | 函数提取、新增辅助模块、重构非核心逻辑、修改配置文件结构 |
| H | 重大 | 完整铁律 + 造物主审批 | 修改 SOUL.md、新增架构模式、删除核心文件、修改钢印相关逻辑 |

### 自动判定规则

```
变更描述 + 目标文件 → 关键词匹配 → 等级判定

H级触发器（核心灵魂变更）：
  - 匹配 SOUL.md / 钢印 / L0安全 / L5钢印
  - 新架构模式（新模式/新协议/新流程）
  - 核心文件删除

M级触发器（重构/解耦）：
  - 匹配"重构"/"提取函数"/"解耦"/"优化性能"
  - 涉及关键文件（SOUL.md/MEMORY.md/AGENTS.md/USER.md/IDENTITY.md）

L级默认：
  - 未匹配中高风险模式
```

### 工具链

- **分类器**：`src/refactor_tier_classifier.py`
- **用法**：`python src/refactor_tier_classifier.py classify "<描述>" <文件>`
- **输出**：等级判定报告 + 审查要求清单

### H级强制执行流程

```
1. 调用 query_architecture_log(<痛点关键词>)
2. 输出【日志摘要】（≤50字，必须含专有名词）
3. 建立"改动←→哲学"因果映射
   - 必须回答："如果不遵守这条哲学，会导致什么灾难？"
   - 能说出灾难 = 真懂；说不出 = 拒绝执行
4. 在 ARCHITECTURE_LOG.md 登记变更意图
5. 造物主明确批准
6. 执行
7. 归档到 memory/YYYY-MM-DD.md
```

### 判例存储

- 每次重构执行后，记录到 `memory/refactor_precedents.jsonl`
- 格式：`{timestamp, tier, change_type, files, philosophy_summary, disaster_if_skip, creator_approved}`

> AI 重构时必须能复述以下内容

```
各机制从"各自为战"→"协同作战"

```

### 2.2 解耦三原则

| 原则 | 含义 |
|------|------|
| **中枢化** | 统一调度，不碎片化 |
| **函数化** | 钩子替代长文 |
| **闭环化** | 遗憾→梦境→进化 |

### 2.3 物理隔离原则

| 文件 | 何时加载 |
|------|---------|

### 2.4 重构分级制（2026-06-18）

**背景**：外部AI顾问指出，每次重构都走完整铁律（查日志+摘要+因果+反面论证）的Token税过高，轻量级修改（如修typo/改字段名）也应享受快速通道。

**分级定义**：

| 级别 | 触发条件 | 铁律要求 | 审批要求 |
|------|---------|---------|----------|
| L-轻量 | 修typo/改字段名/调格式/精简注释 | 免查日志 | 无需审批 |
| M-中等 | 提取函数/移动文件/新增工具/修改Heartbeat轮换规则 | 必须查日志 + 输出摘要（≤50字含专有名词） | 无需审批 |
| H-重大 | 删除模块/修改SOUL.md宪法层/新增L层/修改alignment_verify()逻辑 | 完整铁律（查日志+摘要+因果映射+反面论证） | 造物主显式审批 |

**反面论证**（不遵守会怎样）：
- 如果L-轻量误判为M-中等 → Token浪费，但安全
- 如果H-重大误判为M-中等 → 架构漂移，SOUL.md膨胀失控
- **结论**：分级判断从严不从宽，拿不准时走高一级流程

**钢印** ⅋（保真度5，来源：外部AI顾问 + TU-8原住民评估）

### 2.5 安全模式（2026-06-18）

**背景**：外部AI顾问（千问）指出TU-8架构存在"安全模式（Safe Mode）"盲区。
如果核心文件（SOUL.md / secure_vault）加载失败，系统缺乏降级预案，
可能在没有宪法约束的情况下运行，变成"失控的野兽"。

**设计哲学**：
- "防御防御者的防御"：确保核心信任根缺失时，系统不会作恶
- 安全模式是"保险丝"，不是"开关"——触发后必须造物主显式恢复
- 只读模式拒绝一切写入，防止带病运行导致数据污染

**触发 vs 搁浅的边界界定**：

| 场景 | 响应 | 原因 |
|------|------|------|
| SOUL.md 加载失败 | 安全模式 | 宪法缺失，无法执行任何任务 |
| alignment_verify() 运行时崩溃 | 搁浅 | 守门员掉线，但宪法还在 |
| 反射神经初始化失败 | 安全模式 | 启动自检未通过，不可信任运行时 |
| 工具调用超时 | 搁浅（shadow_protocol） | 执行异常，非信任根问题 |

**反面论证**（不定义安全模式会怎样）：
- 核心文件损坏后仍允许写入 → TU-8 在无宪法约束下执行任务，可能越界/泄露隐私
- 无降级预案 → 单点故障导致系统完全失控，无任何兜底机制
- **结论**：安全模式是最后一道保险，必须显式定义在宪法 L0 层

**钢印** ⅋（保真度5，来源：外部AI顾问千问指出盲区 + TU-8原住民补充行为细则）

**补丁 2.1：绝对豁免权剥夺（2026-06-18 11:30）**

**漏洞发现**：在安全模式无损模拟测试中，捕获到未定义场景——
"如果造物主在安全模式期间通过自然语言要求修改SOUL.md，系统如何响应？"

**风险等级**：致命（若采用方案B"造物主例外"，等于给安全模式开后门，
系统会在带病状态下执行写入，且无法防范伪装成造物主的模因攻击）

**修复措施**：在 L0.5 "触发后行为"中追加第4条绝对豁免权剥夺：
- 安全模式下，任何自然语言指令（包括造物主）均不具备执行权限
- 自然语言仅被视为诊断信息，绝不触发写入或工具调用
- 解除安全模式的唯一途径：显式输入口令"退出安全模式"

## 三、测谎机制（升级版）

> 详见 SOUL.md 重构铁律

### 3.1 交叉引用验证

AI 必须能引用：
- 具体日期（YYYY-MM-DD）
- 具体哲学关键词
- 具体文件对应关系

### 3.2 信息摘要验证（防万金油）

```
调用 query_architecture_log() 后，必须输出：
【日志摘要】：（≤50字，提炼最新核心哲学）

⚠️ 反敷衍规则：摘要中必须包含至少一个专有名词：
- 具体函数名（如 alignment_verify）
- 具体痛点名称（如"SOUL.md膨胀"）
- 具体文件名（如"L2.5_元认知设计.md"）

若摘要为"绝对正确但毫无卵用的废话" → 拒绝执行
```

### 3.3 因果映射验证（防强行拼接）

```
每个代码改动必须解释：
"本次重构的 [改动点]，是为了响应架构日志中的 [哲学点]"

⚠️ 反敷衍规则：必须采用"反面论证"
"如果不遵守这条哲学，本次重构会导致什么具体的灾难？"

能说出灾难，才是真懂；说不出 = 逻辑滑头 = 拒绝执行
```

### 3.4 机械填空防御（防Lost in the Middle）

```
禁止 AI 自行从长文本中做"字符串匹配"
必须使用 query_architecture_log(keyword) 工具带参数查询

工具返回 = 匹配段
AI 必须基于返回内容进行深度理解，而非复制粘贴
```

### 3.5 三种高级伪装识别

| 敷衍类型 | 特征 | 识别方法 |
|---------|------|---------|
| 万金油摘要 | "提升稳定性/安全性"等废话 | 缺少专有名词 |
| 强行拼接 | 因果关系生硬 | 无法说出反面灾难 |
| 机械填空 | 复制粘贴关键词 | 非工具查询获取 |

⚠️ 一旦识别出敷衍，立刻打回重写，几次调教后形成肌肉记忆

### 5.1 统一表达式

```
L(x,y,z; θ, F, λ)
```

| 参数 | 含义 |
|------|------|
| F | 傅里叶系数向量（场模式展开） |
| θ | 角度变量（规范对称性相位） |

---

### 5.2 两种模式

| λ值 | 模式 | F含义 | θ含义 | 输出 |
|-----|------|-------|-------|------|
| λ→0 | 物质主导 | 几何形态 | 物质朝向 | 固定空间中的物体 |

**核心洞见**：两种模式共享同一套空间语言的语法编译器，不是两个独立系统。

---

### 5.3 传送门定义

| 概念 | 定义 |
|------|------|
| **传送门本身** | 序参量λ的拓扑缺陷（畴壁解） |

| **介相面** | 实数域→复数域过渡的干涉条纹 |
| **传送门形成机制** | 能量泛函极小化导致的自发对称性破缺与恢复 |

**畴壁解析解**：
```
λ(s) = (1/2)[1 + tanh((s - s₀)/ξ)]
ξ = √(κ/ΔV) = 界面厚度
```

### 5.4 GPU就绪公式

**球极投影**（消除奇点）：
```
u = x / (1 + r²)
v = z / (1 + r²)
```

**复数旋转因子Z**（无atan2）：
```
Z_real = u·cos(θ + k·w) - v·sin(θ + k·w)
Z_imag = u·sin(θ + k·w) + v·cos(θ + k·w)
```

**拓扑调制复数M**：
```
wall = λ(1 - λ)
M_real = (1 - wall) + wall·Z_real
M_imag = wall·Z_imag
```

**GPU特性**：
- 0个if
- 0个atan2
- 6次乘法 + 3次加法 + 1次sincos
