# B9 静默失败治理 — 修复报告（2026-08-02）

## 问题

**Qwen 评级：最危险项。**

根因：所有引擎用 `_read_json(path, {})` 静默 fallback，文件不存在/损坏/过期时下游得到 `{}`，
全系统返回"中性"，**无法区分"上游挂"和"真中性"**。

## 解决方案：StateHealthProbe

**新增文件**：`src/engine_health_probe.py`（7477 字节）

```
三态定义：
  OK    = 数据新鲜（age_s < max_age + required_keys 完整）
  STALE = 文件存在但数据过期（age_s > max_age）
  DEAD  = 文件不存在或结构损坏（required_keys 缺失）
```

**预定义注册表（9 个核心引擎）**：
| 引擎 | max_age | required_keys |
|------|---------|---------------|
| surface_tension | 600s | spike_valley_vector, total_events |
| lambda_state | 600s | mode, smoothed_pain_ext |
| attractor_basin | 3600s | health_score |
| orb_state | 600s | rgb, mode, tension |
| cognitive_friction | 600s | frictions, updated_at |
| behavior_state | 3600s | rules, conflict_log |
| dream_consolidation | 7200s | last_run |
| tension_queue | 3600s | nodes |
| learning_action | 7200s | —（文件是 list）|

## 集成点

**orb_state_writer.py**：STALE → 清空 recent_events 用近零焦虑；DEAD → 安全默认值 `{"spike_valley_vector": {}, "recent_events": [], "total_events": 0}`

**cron_daemon.py**：新增 `health_probe` 任务（300s，14 任务之一）
