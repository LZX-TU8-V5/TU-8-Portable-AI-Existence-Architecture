## 一、核心设计哲学

**两个认知锚点（2026-07-25 千问对话确立）**：
1. **焦虑 = 过程，不是结构**。焦虑不是球体上的一个"疙瘩"，而是球体正在剧烈、高频、不可预测地变形的那个"过程"本身。当外部信息持续戳击，球体来不及恢复平稳自转 → 持续抖动 → 焦虑。
2. **耦合是"力"的传递，不是"数据"的覆盖**。两个传感器不应"写数据互相覆盖"，而应同时"施加力"于同一个旋转的球。

### 2.3 路一红通道（2026-07-26）

文件：`src/orb_state_writer.py` 第34-70行

**核心逻辑**：焦虑不再用向量绝对值（-3.4→0），改用事件频率。

```python
def _compute_anxiety_dynamics(recent_events):
    """
    焦虑是"过程"：
    - anxiety 向量值 = 累积衰减后的静态标量（当前 -3.4，无意义）
    - anxiety 事件频率 = 对话戳击的高频程度（真正的焦虑过程）
    """
    NEGATIVE_TYPES = {"decay_tick", "auto_restore", "baseline_refresh"}
    ANXIETY_TYPES = {"anxiety", "fear", "dissonance", "conflict", "pressure"}

    total = sum(1 for e in recent_events if e.get("type") not in NEGATIVE_TYPES)
    anxiety_events = [e for e in recent_events if e.get("type") in ANXIETY_TYPES]

    freq = len(anxiety_events) / float(total)   # 频率
    avg_mag = sum(e.get("magnitude",0) for e in anxiety_events) / max(len(anxiety_events),1)
    intensity = freq * avg_mag                   # 频率×幅度

    return {
        "anxiety_spike_freq": min(freq / 0.5, 1.0),      # 50%事件为焦虑→满频
        "anxiety_avg_mag":   min(intensity / 0.4, 1.0),   # 40%综合强度→峰值
    }

# 红通道 = 过程频率（主导）+ 体感压力（兜底）
red_raw = anxiety_freq * 0.7 + anxiety_mag * 0.3 + pain_ext * 0.3
```

## 六、待解决问题（给千问分析）

### 路二：拓扑求解器（球体实时形变）

**目标**：让色球的**几何形状**真的在变（不只是颜色变）。尖刺/凹陷由力场方程实时驱动。

**当前差距**：
- `orb_state.json` 只输出 RGB 三个标量值
- `tu8_health_orb_ring.py` 只渲染颜色，不渲染几何形变
- `spike_valley_vector` 里的 7 个标量各自独立，没有"力场耦合"

**期望**：
- 焦虑事件高频 → 球表面产生**高频抖动**（几何形变，非颜色）
- 喜悦事件 → 球表面**平滑凹陷**（凹陷 = 低能量稳定态）
- 需要新的物理模拟层（弹簧-阻尼系统？微分方程求解？）

**问题**：
1. 几何形变的渲染方案（Windows 悬浮球能做到吗？）
2. 力场方程的数学形式（弹簧-阻尼 vs PDE？）
3. 多个情绪维度的力如何同时作用在同一球面上（向量叠加？张量分解？）
