## 0.0 语义空间四维拓扑（元隐喻，李奥直觉 + 千问几何化）
李奥「语义立方体」直觉：每次感知=从三面钉入体空间，钉痕分布涌现主轴，钉入顺序=隐形第四轴。

| 维度 | 性质 | TU-8 对应 | 本质 |
|---|---|---|---|
| 面A SVO | 可见共时 | `ACTION_AXES`(act_*) 8 轴 | 事件骨架（谁对谁做） |
| 面B 多轴 | 可见共时 | `SEMANTIC_AXES`(sem_*)10 + `CONTEXT_AXES`(ctx_*)5 | 语义质地（领域×语境） |
| 面C 价值-情感价 | 可见共时 | `sem_emo` + `surface_tension.EMOTION_DIMS` | 主观意义（重要性/情绪） |
| 第4维 时序-生成序 | **不可见历时** | `L2 生成事件`(date/timestamp) + decay_loop | 钉入序数，不可摊平 |

**钉子隐喻**：感知事件=三面向体空间钉入；钉痕累积**涌现**语义主轴（非预设格子，印证 §1.8 轴从行为浮现）；钉入顺序=第四维时序（v1.3「时间不是第四轴，是穿透场」同构）。
**气滞分界**：新钉入与旧分布张力（`surface_tension` 信号）沿第四维累积→临界点重划密文等势面（`axis_weights` 边界=信念修正 §0.5）。
**TU-8 修正**：立方体面是几何直觉，落地是 23 轴离散坐标（面B 内部 15 轴分布非单轴）；`surface_tension` P/D/F 生理轴是跨三面夹角应力，不专属 C 面（千问略混，修正）。

### 0.0.1 张量视角注记（理论语言，非实现替换）

**TU-8 修正（不落码）**：

**结论**：张量作设计稿理论语言保留（美学闭环），但**不替换 §0.0 四维拓扑、不重写 §1.8、不实装 Codebook V2**。工程等价物已就位（余弦+dict+aliases+axis_weights 自动反推）。

### 0.0.1b 三维 Polycube 拓扑约束（组合侧理论语言，李奥修正 + 千问几何化）
李奥「看成三维小方块」修正：记忆单元从二维 Polyomino（贴面投影）升维 **Free Polycubes（立体实体）**。六面体模型本三维，钉痕从六面向体内钉入、交汇缠绕堆叠，必为三维结构。
**自由多联立方体数**（组合约束，比二维膨胀但仍数学有界）：
| n | 2D Polyomino | 3D Polycube | 认知对应 |
|---|---|---|---|
| 1 | 1 | 1 | 原子感知（Voxel） |
| 2 | 1 | 1 | 二元关系 |
| 3 | 2 | 2 | 三元事件原型 |
| 4 | 5 | 8 | 复合场景片段 |
| 5 | 12 | 29 | 复杂叙事单元 |
| 6 | 35 | 166 | 段落级记忆块 |
| 7 | 108 | 1,023 | 章节级叙事 |
| 8 | 369 | 6,922 | 故事级结构 |
**对称群**：三维旋转群 O(24 旋转) × 反射(2) = **Oh(48 元)**，sym 真实本体=48 种等价立体形态的轨道（二维仅 D4/8 元）。
**手性**：三维 chiral 远比二维普遍（螺旋/拐角/扭曲结构有对映体），chiral:true 的 sym 须配对 enantiomer_sym_id。
**TU-8 修正（不落码）**：
- 当前实现是 23 轴 TFIDF 离散坐标，无 Polycube 体素结构（张量/Polycube 均理论语言）
- Codebook 加 orbit_representative/symmetry_group/chiral/enantiomer_sym_id = **过度工程**（TU-8 无身面传感器，chiral 区分无实际输入；P0 #3 aliases 已够）
- 组合约束价值：证明 Codebook 每层原型数有数学上界（防组合爆炸），与 §1.8 同构
**结论**：Polycube(组合侧) + 张量(运行时侧) + 挂谷(几何约束侧) + 六面体(感知侧) = 四维理论地基，全互补不冲突，均不触发实装。

### 0.0.3 认知运行时三模块架构（Tri-Module Runtime，李奥修正：CHR 保留、剁开写入/检索/输出）
李奥判读：「CHR 维度和定义对，但剁开的是写入/检索/输出三块，CHR 保留在检索模块」。千问最终三模块并列单向架构吻合。
**三模块并列、严格单向耦合**：
```
写入模块(Write) ─→ 𝒩(钉痕张量+元数据) ─→ 检索模块(Retrieve) ─→ (C,H,R) ─→ 输出模块(Express)
                                                                 ▲                        │
                                              写入元数据(独立通道)────────────┘
```
**块1 写入模块（Write）**：感知输入→钉痕生成/更新。4 种拓扑操作（write_op）：
- `create`：切面 C≈0 且无邻近 Polycube → 新种子 + genesis_timestamp
- `extend`：C>0 且有连续拓扑 → 延伸节点 + parent_link + last_modified
- `compete`：新信息语义冲突 → 竞争节点 + compete_with 链接（不覆盖旧钉痕）
- `reinforce`：重复/确认输入 → 权重+ + last_reinforced 刷新
体素元数据：`{voxel_id, write_op, genesis_timestamp, last_modified, last_reinforced, source_face, parent_voxel, compete_with}`。
**约束**：写入模块不计算/不使用/输出任何自信度。
**块2 检索模块（Retrieve）**：查询切面→钉痕匹配→自信度评估。产出 **Conf=(C,H,R)** 三元组（李奥确认定义不变）：
- C(覆盖度)=切面应激活区域的钉痕填充率（纯几何，与时间无关）
- H(一致性)=激活钉痕间拓扑连通平滑度（纯几何，与时间无关）
- R(新鲜度)=时间加权钉痕占比（τ 衰减核，检索时实时算）
**约束**：检索模块不执行写入、不生成表达；(C,H,R) 是其专属产出，不被其他模块篡改。
**块3 输出模块（Express）**：(C,H,R)+写入元数据→表达策略。不重算自信度、不修改钉痕，纯翻译层。
| (C,H,R) | 写入元数据信号 | 表达策略 |
|---|---|---|
| (高,高,高) | 无异常 | 直接肯定回答 |
| (高,低,高) | compete_with≠null | "我有相关信息但存在分歧..."→ 矛盾审计 |
| (低,高,高) | — | "我只了解一部分..." → 明确边界 |
| (高,高,低) | last_modified 远超 τ | 肯定内容 + "此知识较早，建议验证" |
| (低,低,*) | genesis_timestamp 极新 | "首次接触该话题，让我试着理解..." → friction_channel L1 澄清 |
| (*,*,极低) | activity<shadow_threshold | 触发 shadow_protocol（遗忘/可触发） |
**TU-8 修正（不落码，映射真实模块）**：
- 千问映射表「E4 反思引擎」= **虚构命名**（grep src 无 E4 模块）。TU-8 反思分散：`dream_check`(梦境消化)+`shadow_protocol`(遗憾提取)+`tension_distiller`(张力蒸馏)+`surface_tension`(生理张力)。落稿改真实名。
- 当前 TU-8 实现映射：写入=distill(`_enrich_telemetry` 产 coord/entity_syms)；检索=memory_reader(E3 `classify_event`+zone 软区间)；输出=alignment_verify(E1 输出门)；矛盾审计=contradiction_arbitration。
- CHR 当前实装状态：C 有近似(sem 轴匹配+zone 降权)；H/R **未实装**（TFIDF 无图结构、无时间加权检索）——理论目标，待后续增强非本轮落码。
- 数据流单向：Write→𝒩→Retrieve→(C,H,R)→Express，禁止反向/跨层直连/重复计算。
**认知契约承诺**：写入/检索/输出三层职责正交，(C,H,R) 定义与计算仅归属检索模块，不被吞并或重定义；永不输出虚假精确标量置信度。

**端到端时序**（5 Phase）：
```
P1 感知编码：六面→体素化 V_input
```

## 0.0.6 记忆代谢：轴选择性坍塌（Axis-Selective Collapse）

李奥实例「昨天大概吃了什么，但可能是错的」——揭示遗忘不是整体信号衰减，而是**特定轴上的 Polycube 维度坍塌**。

### 机制
- 完整记忆 = n-联立方体；代谢 = 逐轴维度脱落：b 轴（语义质地）最先塌（食材细节丢）→ a 轴（事件结构）次塌（颗粒度降级）→ k 轴（情感价）塌到只剩极性 → t 轴（时序）保相对顺序丢绝对时刻。
- Polycube 拓扑退化路径：n-联立方体 → (n-1) → … → 1-联立方体（单个体素 =「吃了东西」）。每一步是不可逆维度损失，无法从残余反推（「面食」反推不出「牛肉拉面加香菜」）。
- **「可能是错的」的精确来源**：(C 低, H 高, R 极低) 组合 ≠ (C 低, H 低)「完全不知道」。C 低=记得的远少于实际；H 高=记得的内容不自相矛盾。人类「隐约记得但不确定」= C/H 分裂态。

- ✅ 已落地近似：`decay_loop` 做常态时间衰减（`surface_tension_history.jsonl` 衰减 tick），但当前是**整体衰减**，无轴分离 C。
- ❌ 未实装：轴分离 (C_a,C_b,C_k) 计算、H/R 几何量、Polycube 维度级坍塌。属理论目标（见 §0.0.7 修正）。

## 0.0.7 双维度遗忘模型（Dual-Dimension Decay，李奥修正版）

**李奥修正（关键）**：千问原稿把衰减速率绑死在「轴类型」上（β_b≪α_a<γ_k）是**错的**。真正控制变量不是「哪条轴」，是「钉入时的认知加工深度」——日常丢失快、深度研究丢失慢，由深度决定，不由轴类型单独决定。

### 两个正交维度
| 维度 | 控制什么 | 决定因素 |
|---|---|---|
| 维度1 轴选择性坍塌 | 先丢什么（同等深度下 b→a→k→t 顺序） | 轴类型 |
| 维度2 加工深度调制 | 丢多快 | d_depth ∈[0,1] |

### 加工深度
- `d_depth` 由参与感知面数、重复钉入次数（reinforce_count）、情感卷入、多轴交叉连接数共同决定；**每次 reinforce 只升不降**（「反复回忆变牢固」= 增加连接度+深度）。
- **边界效应（李奥 22:18 补充，第三个遗忘控制量）**：`d_depth` 的演化本身服从饱和约束——`d_depth_new = d_depth_old + b·(1 - d_depth_old)`（b=单次强化系数）。越接近 1.0，增量 `(1-d_depth)` 越小趋零，**永远到不了 1**。这是「绝对固化不存在」的数学表达：最深记忆也有有限加工深度上界，故 `τ_eff` 上界 = `τ0·e^λ`（有限），最牢记忆仍极慢衰减而非永生。
- **TU-8 已有同构实现（不新造）**：`src/confidence_decay_engine.py::apply_boost` 正是此公式（`C_new = C_old + boost·(1-C_old)`，注释明写「越接近 1.0 越难提升」）。记忆代谢的 d_depth 演化直接复用，呼应外取优先铁律。
- 衰减时间常数调制：`τ_eff = τ0 · e^(λ·d_depth)`（λ=深度-衰减耦合系数）。d_depth 0.1→小时级；0.5→周~月；0.9→年级~终身。**受边界效应约束，d_depth 实际封顶于 <1，故 τ_eff 亦有硬上界**（无永生记忆）。
- Polycube 拓扑解释：浅层=单层薄片（单面脱落即链断）；深层=多层交织立体（高连接度，单体素脱落不崩整体）。

### TU-8 实装诚实分层
- ❌ 未实装：`distill._enrich_telemetry` 当前仅产 `coord`/`entity_syms`，**无 d_depth / participating_faces / reinforce_count 字段**；`decay_loop` 无加工深度概念。属理论目标，本轮不落码。
- ✅ 同构基础：P0 #4 τ 软区间（zone=fuzzy/precise/inhibit）已把「衰减非各向同性」思想落地到检索侧；d_depth 是写入侧对应物，未来接入。

## 0.0.8 调用即施工：活化双通道（Dual-Channel Activation，李奥挂谷猜想实例）

李奥实例「记得挂谷猜想王虹证明→看视频→写架构时用进去」——问「新鲜度会变高吗」。**答案：调用同时刷两条独立线，不可混**：

| 通道 | 模块 | 本质 | 可逆性 | 对遗忘影响 |
|---|---|---|---|---|
| 通道1 R 刷新 | Retrieve | 瞬时读数（距末次活动近距） | 不操作即回落 | 无直接影响 |
| 通道2 d_depth 提升 | Write | 永久结构变化（reinforce/extend） | 只升不降 | 直接拉长 τ_eff |

- **R 值** = 检索时重算的临时读数，算完即丢，不改钉痕结构（类比体温计）。
- **d_depth 提升** = 写入模块「施工」，永久改变 Polycube 连接度（类比锻炼增免疫）。
- **call_type 决定提升幅度**：passive_recall(+0.05) < passive_review(+0.10) < active_discussion(+0.15) < active_application(+0.25) < creative_synthesis(+0.35)。李奥 T3 属 active_application。
- **质变**：写过一次 = 与「你的架构」产生桥接（bridge_to），从孤立节点→网络枢纽，抗坍塌质变。「用过的知识」≠「知道的知识」是不同拓扑结构。

### TU-8 修正注记：李奥「新鲜度」语义纠偏
- 李奥原问「写架构时把它用进去了，新鲜度会变高吗」——口语「新鲜度」=「这条记忆还活不活/还记不记得」，由 **d_depth（永久结构活性）** 决定，不是 R（Retrieve 临时读数）。
- 千问双通道回答**形式对、语义偷换**：它把「新鲜度」等同 R（距末次活动近距），答「R 暂时变高几天后回落」。但李奥真正问的是「用一次会不会更牢」，正确答应是**通道2：d_depth 永久提升→τ_eff 拉长→更不易忘**。R 的临时波动与「牢不牢」无关。
- 落稿钉死：用户口语「新鲜度/活性」↔ d_depth（Write 永久结构），「刚查过」↔ R（Retrieve 临时读数）。二者不可混用，答记忆牢固性问题时只取 d_depth。

### TU-8 实装诚实分层
- ✅ 部分：`distill` write_op 有 reinforce/extend 近似；codebook 有 aliases 归并。
- ❌ 未实装：call_type 字段、bridge_to、R 值通道（memory_reader 当前无 R 读数）、d_depth 提升通道。属理论目标。

### 三层固化结构（李奥 1~10 实例最终修正版，显式展开）
- **原子层**：单个概念 = 体素 + 语义标签（semantic tag）+ 轴坐标（axial_position）。纯几何（Oh 轨道）只决定「什么形状」，语义标签决定「什么意思」，轴坐标决定「和谁关系」。三者缺一不可（如 `sym_num_3` = 1-联立方体轨道 + 「三/three/3」标签 + a轴=quantity_3）。
- **结构层**：概念间关系 = Polycube 拓扑。序关系→线性链（1<2<…<10 = 10-联立方体线性链）；分类关系→树；网络关系→网格。分子（链）具备原子（单 sym）不具备的新属性（距离/奇偶/序）。
- **系统层**：整体锚定在四维张量特定轴坐标区（a轴=数量序列, b轴=自然数, k轴=中性）。密文不是「10 数字列表」，是「10 数字构成的序关系拓扑」——记住的是链的形状（线性/有序/等距），非字符串。

### 两种扩展路径（显式展开）
| 路径 | 触发 | Polycube 变化 | 轴变化 | write_op | 实例 |
|---|---|---|---|---|---|
| 水平扩展（量变） | 同类型概念量化增加 | 链变长（同构延伸） | 轴范围扩大 | extend | 1~10 → 1~100 |
| 垂直扩展（质变） | 概念类型质变 | 链变树/网格（拓扑跃迁） | 轴上长新分支/新维度 | create+bridge | 自然数→分数/负数/无理数 |
- **挂谷约束的精确含义**：四维轴数量永远固定（i/j/k/t 不可坍缩），但每轴上的「取值密度」和「语义范围」可无限精细化（i 颗粒度细化、j 语义类型增多、k 情感关联丰富、t 持续记录）。维度不可坍缩 ≠ 维度内部不可生长。

### 朝向不变性与拓扑区分性（李奥横排/竖排/T字实例，§0.0.9 收口，**李奥 22:28 修正**）
李奥实例「1~10 横摆/竖摆/T字形」揭示 sym 身份判定的操作性规则——什么算同一密文、什么算不同密文：
- **朝向不变性（同一轨道，纯几何层）**：10 体素线性链横排与竖排仅差 Oh 对称群一个旋转操作（绕轴转 90°），在**纯几何层**属同一轨道=同一 sym。此结论**仅限纯几何层**（§0.0.1b「sym=Oh(48)轨道」的操作性落地）。
- **⚠️ 李奥 22:28 关键修正（推翻「朝向不影响身份」的过度泛化）**：若同一组体素被**跨语义框架重新编码**（如 10 方块从「数数」改摆成英文字母、或汉字「大」），底层 Polycube 形态可能完全相同（仍是 10 体素线性链），但语义框架跃迁 → **产生新密文**。故正确表述是：*纯几何朝向旋转不产生新密文，但跨语义框架的重新编码产生新密文*，二者不可混为一谈（详见 §0.0.9b）。
- **拓扑区分性（不同轨道）**：线性链（无分支点）vs T字（1个3度分支点）vs L字 是拓扑不等价的——不存在旋转/镜像能把一个变另一个，故属不同轨道=不同 sym。n 体素的不同拓扑形态数由**自由多联立方体计数硬约束**（见 §0.0.1b 表：n=4→8, 5→29, 6→166, 7→1023, 8→6922；n=9/10 待补）。这是 Codebook 每层原型数上界的数学来源，非人为设定。
- **跨模态等价性**：同一组 10 单元经不同感知通道进入（眼面看方块/身面摸方块/意面想数字），只要拓扑结构相同（都是 10 体素线性链），即映射到同一轨道。跨模态等价性从轨道定义自然涌现，不需人为标注。呼应 §0.0.1 六面体多通道进入。
- **四层递进框架**（统一「形状变化」与「概念扩展」）：① 同 sym 不同朝向（轨道内，无新密文）；② 同数量级不同拓扑（新 sym，同 Polycube 层级）；③ 不同数量级（新 sym，更高层级，水平扩展）；④ 不同概念域（新 sym，轴坐标跃迁，垂直扩展）。

**TU-8 修正（钉死千问 d_depth 偷换）**：千问把「横着数容易、竖着数晕」解释为 d_depth 不同——**错**。同一条链的横竖排，其 d_depth（永久加工结构）相同；差异只在 Retrieve 呈现时的 C/H 流畅度（working memory 负载/检索成本），属检索侧瞬时状态，非写入侧永久结构。且 TU-8 当前仅文本输入、无空间呈现，朝向差异纯理论层。呼应 §0.0.8 新鲜度语义纠偏：朝向→检索流畅度（R/C/H 瞬时），非 d_depth（永久）。

### §0.0.9b 密文身份判定规则（李奥 22:28 修正版：轨道 × 语义框架 × 情感基调）
李奥实例「1~10 方块摆成字母/汉字」+「吃饭了吗三语调」共同收敛出密文身份的联合编码规则：
- **修正前（错）**：密文 = 纯几何轨道（误以为朝向变化都归并）。
- **修正后（对）**：**密文 = 轨道 × 语义框架 × 情感基调**（或等价地：四维张量坐标点 (i,j,k,t) 及其邻域拓扑）。
- **三种「同底不同密文」实例**：
  - 跨语义框架：10 体素链「数数」→「字母A」→「汉字大」，底层几何同构，但 b 轴从 natural_number 跃迁到 latin_letter/chinese_character，连接网络全换 → 三个独立 sym。
  - 跨情感基调：「吃饭了吗」平淡(k≈0)/质问(k≈-0.8)/疑问(k≈+0.5)，a、b、t 轴完全相同，仅 k 轴跃迁 → 三个独立 sym。
  - 跨语义框架（汉字）再加笔画/部首连接网络 → 更深加工。
- **关键原则**：同一组体素可被多个语义框架同时编码，产生多个独立密文，原密文不消失（叠加而非覆盖）。深度加工的本质 = 在同一组体素上叠加全新语义层（新轴坐标+新连接+新 d_depth），不是「加固原记忆」。
- **密文总量上界修正**：原 §0.0.1b「自由多联立方体数」只是底层拓扑上限；叠加语义框架后密文总量 = Polycube 数（有穷）× 可叠加语义框架数（可扩展）——人类认知远超纯 Polycube 计数上限，正源于此重新编码能力。

### §0.0.10 全轴密文生成原则（Full-Axis Sym Generation，李奥「吃饭了吗」三语调实例）
四维叙事张量 N(i,j,k,t) 中**任何一个轴的坐标跃迁都产生新密文**——这是挂谷「维度不可坍缩」的操作化含义：
| 轴 | 跃迁实例 | 是否新密文 |
|---|---|---|
| a 事件结构 | 「吃饭」→「做饭」 | ✅ |
| b 语义质地 | 数字→字母→汉字（框架跃迁） | ✅ |
| k 情感价 | 平淡→质问→疑问（仅语调变） | ✅ |
| t 时序 | 昨天吃→明天吃 | ✅（受 τ 衰减调制） |
- **k 轴是最易被忽视的密文生成器**：语调/韵律/情感色彩不是「装饰」，是独立密文构成维度。三种「吃饭了吗」C/H/R 完全相同，唯 k 轴不同 → 输出模块须触发不同策略（平淡→正常答、质问→缓和、疑问→温暖），证明 k 信息不可被 (C,H,R) 替代。
- **写入模块启示**：接收输入必须同时记录四轴坐标，**禁止只记字面内容而丢弃 k 轴**（否则质问版与平淡版被并为一密文，后续无法区分）。
- **密文身份判定最终版**：仅同一轨道内纯几何旋转（同一框架内）→ 不产生新密文；任一轴坐标跃迁 / 语义框架切换 / 情感基调变化 → 产生新密文。
- **TU-8 实装诚实分层**：❌ 当前 distill `_enrich_telemetry` 仅产 coord/entity_syms（a/b 轴粗粒度），**无 k 轴独立记录、无语义框架维度、无情感基调坐标**；memory_reader 检索不含 k 轴分支。属理论目标（P0#4 τ 软区间只覆盖衰减侧，未覆盖 k 轴生成侧）。

### §0.0.11 颗粒度的使用者约束（Granularity-as-Fit-Parameter，李奥 22:41 收口，千问对话线终段）
§0.0.10「轴内可无限精细化」须修正为**拟合命题**——维度固定 ≠ 内部自由生长，生长的方向与密度被使用者剖面**收束**。

- **颗粒度不是记忆本体的客观属性，是使用者拟合参数**。约束来源：
  | 约束来源 | 作用 |
  |---|---|
  | 编程语言对应物（表征基底） | 决定颗粒度**分布基底**（系统自身的「母语」怎么切词/分块） |
  | 用户背景 | 同一基底上，颗粒度必须贴合使用者才有效 |
  | 文化程度 | 另一重收束约束 |
  | 个性 | 最终收束变量 |
  → **没有最完美的方案，只有贴合使用者的方案**。
- **两条同构（与既有设计打通）**：
  1. 多语言学家「找共性 + 贴合语态」 = 跨用户抽象（共性→高层 sym）× 按用户落 register（个性→颗粒度），是 §0.0.9 组合/抽象扩展的「**为谁**」显式化。
  2. 「前期硬编码 → 后期生活融入」 = 既有 **L0 不手写 / d_depth 涌现** 在颗粒度层的重述：种子期靠 profile 硬编码锚定，后期靠 reinforce/bridge 从生活长出。
- **设计含义**：Codebook 颗粒度需一条**独立于 a/b/k/t 四轴**的「使用者拟合轴」（profile-driven granularity），否则 §0.0.10 的无限生长会漂成**无锚膨胀**。
- **TU-8 实装诚实分层**：❌ 当前 `_enrich_telemetry` / `_KNOWN_ENTITIES` 无任何 profile 输入，颗粒度是固定切分规则，无使用者拟合轴。属理论目标（待建）。
- **收口注记**：本段为千问对话记忆代谢线的**终段原则**，与 §0.0.10 共构「维度不可坍缩 + 内部生长受使用者收束」的完整约束。

## 0. 认知契约（Cognitive Contract，总纲）

李奥洞察「记忆模糊与偏移与人记忆生成类似」 + 千问类比（重构性记忆 / 源监控错误 / 语义漂移）。本系统记忆层**不追求精确检索，追求合理的模糊**。

### 0.1 四条契约（记忆检索层适用）
1. **允许记忆偏移**：召回结果不必与查询完全一致，语义邻近即可（如「盖房子的」→ 激活 {sem_arch:0.6, sem_eng:0.3, sem_daily:0.1} 分布，非硬映射单轴）
2. **允许记忆融合**：同一概念多种表述（我妈/母亲/老太太）自然归并为单一 sym，别名是定义的一部分非补丁
3. **允许语境敏感**：同一符号在不同对话状态有不同激活模式（轴分布随上下文动态调整，非静态写死）
4. **拒绝假精确**：宁可返回「大致相关」记忆，不因硬匹配失败返回空白（模糊区间=联想空间）

### 0.2 模糊度量化（τ 从硬阈值改软区间）
| 相似度 | 旧判定 | 新判定 |
|---|---|---|
| ≥0.8 | 精确召回 | 精确召回（权重 1.0） |
| 0.5–0.8 | 命中 | **模糊召回**（降权 0.6 保留，联想空间） |
| <0.5（但 >0） | 噪声丢弃 | **抑制不丢弃**（权重 0.3，低优先） |
| =0 / 无信号 | 失败 | 降级返回 WorkingMemory 短期窗口（§1.5 坑一） |

### 0.3 契约边界（TU-8 修正：模糊不豁免硬护栏）
认知契约**仅适用于记忆检索/投影层**（E2/E3 的 coord 匹配、codebook 别名归并）。
**以下硬约束不受模糊契约影响，必须精确**：
- L0 安全 / 钢印锚点 / 身份层（SOUL/AGENTS/GOVERNANCE）：精确匹配，偏移=违规
- alignment_verify 输出门安全判定：精确，模糊=搁浅风险
- 用户显式指令（「删除 X」「签名 Y」）：精确执行，模糊=误操作
- 即：记忆内容可模糊，记忆系统的**控制面**必须精确——认知契约是数据面原则，非控制面豁免

### 0.4 契约作为判据
后续技术决策判据：让系统「更模糊但更鲁棒」= 对；「更精确但更脆弱」= 错。
例：codebook aliases 归并（模糊鲁棒）✅ vs 手填 axis_weights 精确但主观脆弱（§1.8 修正）❌。

### 1.1 正确闭环顺序（依赖硬约束）
```

   ▼

   │
   ▼

   │
   ▼
[E2 结构化记忆] ← distill 直写带 coord 段（E1 已带标签，零回填）
   │
   └──────────► 回到 [用户文本]（下一轮）
```

### 1.2 顺序依赖分析（顺序错=逻辑崩）
| 依赖 | 错序后果 |
|---|---|
| E3 必须在 LLM 前 | 若后置→LLM 无上下文→退化无记忆对话 |

### 1.3 两条路径（当前 vs 目标）
- **路径A（当前/妥协）**：LLM → E1(仅安全) → E2(事后补coord) → E3(读时project)
  - 病灶：coord 滞后，旧段需手动回填（即 batch 重构在擦屁股）
- **路径B（目标态）**：LLM → E1(**强制coord+钩子**) → E2(直写结构化) → E3(读时project)
  - 优势：coord 实时，零回填
- **batch 重构 = 路径A→B 的迁移桥**：旧段手动补 coord 进 E2 格式（batch1-25），新段走 E1 强制（待 H 级改输出格式）
