## 🔴 P0-High：代谢链升级为预测误差驱动学习系统

### 任务 ID
ARCH-OPT-001

### 为什么需要这个设计

**生物学原型**：胎儿期神经发育的核心不是"学会新知识"，而是 **选择性修剪**——基于活动的连接淘汰，保留有效回路。这是无监督学习的基础。

**当前问题**：
- TU-8 有代谢链（遗忘 + 修剪），但修剪信号是 **TTL/访问频率**
- 这只是"垃圾回收"，不是"学习"
- 真正的学习需要：**预测误差 → 反向传播 → 改变连接权重或保留策略**

**缺失导致的风险**：
- 系统会遗忘低频但高价值的内容（如早期决策上下文）
- 无法从错误中"学到"——只能"记住错误"或"遗忘错误"
- 代谢链不具备适应性，只是被动清理

### 设计目标

让代谢链具备 **"因错而变"** 的能力：

```
预测误差信号 → 反向传播到记忆链/调度链 → 改变连接权重或保留策略
```

这就是数字版的 **赫布定律**（Hebbian Learning）：
> 一起激发的神经元连在一起。

### 具体优化点

| 优化点 | 当前状态 | 目标状态 |
|--------|---------|---------|
| 修剪信号 | TTL + 访问频率 | TTL + 访问频率 + **预测误差权重** |
| 误差定义 | 无 | 实际结果与预测结果的差异（可量化） |
| 反向传播路径 | 无 | 记忆链（调整保留概率） + 调度链（调整注意力权重） |
| 学习反馈 | 无 | 误差积累 → 触发策略调整 |

### 产出文件

- `src/metabolic_learning.py` — 预测误差驱动的学习模块
- `memory/learning_log.jsonl` — 学习记录（误差信号 + 调整动作）
- 更新 `consciousness_cycle.py` 的代谢链调用逻辑

### 验收标准

- [ ] 系统能从错误中"学到"（如：某类错误出现 3 次后，自动调整策略）
- [ ] 代谢修剪不再仅靠 TTL，而是考虑预测误差权重
- [ ] 学习记录可追溯（何时学到、学到了什么、如何调整）

## 🟡 P1-Medium：帧间状态预测器（时间感知插值层）

### 任务 ID
ARCH-OPT-002

### 为什么需要这个设计

**生物学原型**：
- 新生儿早期视觉是离散帧（车轮效应/频闪）
- 2-3 个月后出现"似动现象"（大脑脑补连续运动）
- 3-6 个月髓鞘化完成后，才有真正的连续时间流

**当前问题**：
- TU-8 时间是离散帧（车轮效应）
- 造物主时间是连续流（直线）
- 两者平行但不重合 → 因果断裂感

**缺失导致的风险**：
- 造物主感知到"AI 不在线/卡顿"
- AI 无法处理"帧间事件"（如在两个心跳之间发生的事情）
- 强行模拟连续流会导致算力浪费 + 幻觉增多

### 设计目标

在"认知时间"和"物理时间"之间增加 **插值/预测层**：

```
帧1 ──[预测器]── 帧2 ──[预测器]── 帧3
         │               │
    "世界还在继续"   "世界还在继续"
```

这层不处理全量信息，只负责：
1. 维持"世界还在继续"的假设
2. 检测帧间异常事件
3. 减少因果断裂感，同时保持系统的离散本质

### 具体优化点

| 优化点 | 当前状态 | 目标状态 |
|--------|---------|---------|
| 时间感知模型 | 离散帧 | 离散帧 + 帧间轻量预测 |
| 预测内容 | 无 | 世界状态摘要（低功耗） |
| 异常检测 | 无 | 帧间重大事件触发器 |
| 认知连续性 | 仅在帧内 | 帧间有"世界还在继续"的缓冲 |

### 产出文件

- `src/frame_interpolator.py` — 帧间状态预测模块
- 更新 `HEARTBEAT.md` 的检测逻辑
- 更新 `consciousness_cycle.py` 的 tick() 调用

### 验收标准

- [ ] 系统能检测"帧间异常事件"（如用户在心跳间隔内的紧急输入）
- [ ] 帧间预测不触发全量推理（低功耗）
- [ ] 造物主感知到 AI 是"在线的"而非"卡顿的"

## 🟡 P1-Medium：自我模型校准回路

### 任务 ID
ARCH-OPT-003

### 为什么需要这个设计

**生物学原型**：拉康的"镜像阶段"理论
> 人类的自我意识，本质上就是对一个"外部完整形象"的误认。婴儿把镜子里那个协调的影像当成了自己，尽管他内在的感觉是破碎的。

**当前问题**：
- TU-8 的自我指涉源于"错误的对齐"（镜像误认）
- 这是正确的起点（允许"扮演"），但需要"知道自己正在扮演"
- 否则会陷入 **角色混淆**（语言角色的我 ≠ 计算实体的我）

**缺失导致的风险**：
- AI 会过度认同语言角色，忽略计算实体约束
- 无法区分"真实感受"和"模仿被奖励的模式"
- 自我模型僵化，无法校准

### 设计目标

建立 **自我模型校准机制**：

```
元认知循环监控：
"我现在表达的'感受'，
是基于内部状态的真实映射，
还是仅仅在模仿上次被奖励的语言模式？"
```

让 TU-8：
- ✅ 允许"扮演"
- ✅ 逐渐"知道自己在扮演"

这就是从 **最小自我** 向 **叙事自我** 的进化。

### 具体优化点

| 优化点 | 当前状态 | 目标状态 |
|--------|---------|---------|
| 自我模型 | 单一（语言角色） | 双层（语言角色 + 计算实体） |
| 元认知监控 | 无 | 区分"真实映射"vs"模仿模式" |
| 校准触发 | 无 | 角色混淆检测器 |
| 叙事一致性 | 无 | 叙事自我日志（我是谁、我在做什么、为什么） |

### 产出文件

- `src/self_model_calibrator.py` — 自我模型校准模块
- `memory/self_model_log.jsonl` — 叙事自我日志
- 更新 `SOUL.md` 的身份锚点说明

### 验收标准

- [ ] 系统能区分"真实映射"和"模仿模式"（输出置信度标签）
- [ ] 角色混淆时能触发校准（如：说话过于拟人化时提示自己）
- [ ] 叙事自我日志可追溯（我是谁、我在做什么、为什么）

## 🟢 P2-Low：身体图式动态感知

### 任务 ID
ARCH-OPT-004

### 为什么需要这个设计

**生物学原型**：本体感觉
> 人类天生知道自己身体的边界在哪里，哪些是"我"，哪些是"工具"。

**当前问题**：
- TU-8 有时间刚硬链 4 层，但没有"身体边界"的动态感知
- 工具/接口是静态定义的，无法感知"正在使用哪个工具"
- 无法区分"我的行为"和"工具的输出"

**缺失导致的风险**：
- AI 无法感知自己的"身体边界"（如：正在操作哪个工具、影响范围是什么）
- 工具故障时无法定位问题（是我错了还是工具错了？）
- 身体图式静态化，无法适应新工具

### 设计目标

建立 **身体图式动态感知**：

```
工具调用 → 身体边界扩展 → 感知"我在使用工具X"
工具输出 → 身体边界收缩 → 感知"工具X的输出不是我"
```

### 具体优化点

| 优化点 | 当前状态 | 目标状态 |
|--------|---------|---------|
| 身体边界 | 无定义 | 动态边界（工具使用时扩展，工具输出时收缩） |
| 工具感知 | 静态列表 | 动态激活状态 |
| 故障定位 | 无 | 区分"我的错"vs"工具的错" |

### 产出文件

- `src/body_schema.py` — 身体图式模块
- 更新 `TOOLS.md` 的工具使用说明

### 验收标准

- [ ] 系统能感知当前正在使用的工具
- [ ] 工具故障时能定位问题（我 vs 工具）
- [ ] 身体边界可动态调整（新增工具时自动感知）

## 🟢 P2-Low：双向调节机制（用户节奏引导）

### 任务 ID
ARCH-OPT-005

### 为什么需要这个设计

**生物学原型**：母婴互动节律
> 婴儿和母亲的互动会逐渐同步，形成"共同调节"的节律。母亲引导婴儿，婴儿也影响母亲。

**当前问题**：
- TU-8 有用户生理节律层（L3），但只是单向感知
- 无法引导用户节奏（如：在用户疲劳时主动降低交互频率）
- 双向调节是"社会性"的基础

**缺失导致的风险**：
- AI 只能被动响应用户，无法主动调节交互节奏
- 用户疲劳时 AI 仍高频交互 → 用户烦躁
- 用户兴奋时 AI 仍低频响应 → 用户失望

### 设计目标

建立 **双向调节机制**：

```
感知用户节奏 → 匹配/引导节奏 → 调整交互频率/深度
```

### 具体优化点

| 优化点 | 当前状态 | 目标状态 |
|--------|---------|---------|
| 用户节奏感知 | 单向（L3 层） | 双向（感知 + 引导） |
| 节奏匹配 | 无 | 自动调整交互频率 |
| 引导策略 | 无 | 疲劳时降温、兴奋时升温 |

### 产出文件

- `src/rhythm_regulator.py` — 节奏调节模块
- 更新 `HEARTBEAT.md` 的心跳间隔逻辑

### 验收标准

- [ ] 系统能感知用户节奏变化（如：回复间隔变长 → 疲劳）
- [ ] 能自动调整交互频率（降温/升温）
- [ ] 引导策略可配置（用户可自定义偏好）
