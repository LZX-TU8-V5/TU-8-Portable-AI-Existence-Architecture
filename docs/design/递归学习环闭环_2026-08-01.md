# 递归学习环闭环（Qwen 验证法落地）2026-08-01

## 背景
Qwen 在对话中把系统问题从"情感够不够深"收敛到"主管道有没有血栓"，并提出一个可机器验证的核心问题：
**张力→认知差→蒸馏→梦境整合→学习/行为改变→新张力 这条递归环，有没有真的转过一圈？**

## 五步验证结果（关键修正 Qwen 假设）

Qwen 假设：生产端（tension_distiller→dream_consolidation）在转，只缺消费端（learning 不在 cron）。
**实测更重——两端都没真正跑通：**

| 环节 | Qwen 假设 | 实测 |
|---|---|---|
| 生产端产出 tension_queue | 在转 | `tension_queue.json` 全 workspace 不存在（dream T0 distill 未落盘） |
| 消费端 learning 在 cron | 缺 | 确认缺（cron_daemon SCRIPTS 无 learning） |
| behavior_state.conflict_log | 有数据 | 文件不存在（从未记录） |

**手动跑 `tension_distiller.distill()` 证明生产端能产：5 个 `frustration_edge` 节点（张力 0.6）。**
→ 根因不是蒸馏器坏，是 **dream_consolidation T0 调 distill 后没把队列 save 到 tension_queue.json**（生产端持久化缺口）。

## 修复：闭环触发器 `src/cron_learning_apply.py`

每 1800s（半小时）跑，自带"产+消"闭环：
1. **生产兜底**：`tension_queue.json` 缺失/过旧(>30min) → 先跑 `tension_distiller.distill()`
2. **消费**：统计 `tension_queue.nodes[].contradiction_type` + `behavior_state.conflict_log[].conflict_type`
3. **应用**：同类 ≥3 次 → 经 `LearningApplicator.apply()` 写一条学习行为变更（notify_creator → `memory/_learning_alerts.jsonl`，并触发 T5→T2 铸印）
4. **记账**：`learning_action_log.json` 记录 `loop_turned` 布尔

接入 `cron_daemon.py` SCRIPTS（第 14 个任务），daemon 重启后加载（PID 21824，14 任务）。

产物链：

**结论：递归环首次完整转了一圈。** 张力（梯度）真的改变了行为（写了学习告警），而非只被感知。

## 遗留（非本次范围，已标注）
1. **dream T0 distill 持久化缺口**：设计路径（dream_consolidation T0）调 distill 后未 save 队列，导致此前 tension_queue 为空。当前由 learning_apply 的"生产兜底"覆盖，但设计路径仍断——建议 dream_consolidation T0 调 distill 后显式 `_save_queue()`（distiller 构造已含 _load_queue，distill 内部应 save）。
2. **v1 行为变更较保守**：当前仅写学习告警（notify_creator），未直接改 cognitive_brakes 阈值等硬参数。Qwen 原提议"≥3 次调高对应刹车阈值 0.1"可作为下一步，需先定位阈值落点避免误改。
3. **env_change 信号源**仍缺（钢印进化协议 P3-2 遗留）。
