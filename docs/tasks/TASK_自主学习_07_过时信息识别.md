## 理论逻辑

给它装上"时间透视眼"。对于技术文档，过时的版本号和废弃的 API 往往比垃圾信息更具误导性。

### 维度一：时间锚点与元数据提取
- 提取网页 publish_date / modified_date
- 正则扫描全文提取技术栈版本号（Python 3.12、React 18 等）
- 无明确时间戳，或版本比当前主流落后两个大代际 → 标记为"高危过时"

### 维度二：实时 API 交叉验证（硬指标核对）
- 文章出现具体 API 接口名、命令行参数 → 触发"实时验证探针"
- 调用官方文档 API 或 GitHub 仓库核实
- Deprecated（已废弃）或 Removed（已移除）→ 标记为"事实性过时"

### 维度三：语义漂移与"引用衰减"检测
- 与近 6 个月高质量技术文章进行语义相似度比对
- 表述方式与当前主流范式差异过大 → 触发"语义过时警报"
- 监测引用衰减指数，长期无人引用 → 降低知识权重

### 维度四：版本隔离与"有效期"标签
- 每条技术知识绑定 valid_from / valid_until
- 例如："React 16 的生命周期写法"标记为"仅 React 16.x 环境有效"
- 回答问题时先识别当前项目版本，只从对应有效期内知识库检索
