## 完整方案（造物主 × 千问 × TU-8 共同设计）

### 强制记忆格式（每次回复末尾附带）

对话结束时，AI 回复必须附带：

```
### 事件描述
- 发生了什么：

### 核心决策
- 做了什么决定：

### 意义与影响
- 为什么重要：
```

**废话**（"早上好"、"谢谢"、"哈哈" 等纯寒暄）→ `[SKIP_MEMORY]`
**混合意图**（"早上好，你觉得能解决吗"）→ 只提取实质内容

### 三层过滤写入

| 层级 | 判断 | 动作 |
|------|------|------|
| 废话拦截 | `[SKIP_MEMORY]` | 丢弃，不写入 |
| 碎片写入 | 有实质信息 | 写 `inbox/fragments_YYYY-MM-DD.md` |
| 完整卡片 | 高权重 / 高情感 | DreamConsolidator 生成9大块记忆卡 |

### 72 小时代谢窗口

| 时间段 | 处理 |
|--------|------|
| 0~72 小时 | 活跃区，完整保留 |
| >72 小时 | 分拣区，评分≥0.75→晋升长期；其余降级或丢弃 |

## 问题描述

### 症状
- 下午做的任务（如云端检测），刚写完 `memory/2026-06-26.md`，下一轮对话就"丢失"
- 用户感受：刚做的事记不住

### 根因诊断
OpenClaw 组装 prompt 时，读取的是 compacted summary（压缩摘要），而非 TU8MemoryEngine 刚写入的本地文件。

```
OpenClaw 收到消息
  → 组装 prompt（compacted summary + 用户消息）
  → 丢给 LLM
  → LLM 回复
  ↓
TU8MemoryEngine.store() → memory/2026-06-26.md  ← 对话结束后才写入
  ↓
下次对话
  → compacted summary 里没有刚才写入的内容
  → LLM "丢失"了那段记忆
```

**文件写完 ≠ 自动进入下次上下文**

### 可能加剧因素
- Auto 模式切换模型 → 强制压缩/截断上下文
- OpenClaw 模型 route 变化 → 前缀缓存失效

## 设计参考（来自造物主×千问对话）

### 三层切割读取

| 层级 | 触发 | 读取内容 | Token |
|------|------|---------|-------|
| **L1 快思考** | 每次对话 | narrative_compression + semantic_hooks + tension_score | <500 |
| **L2 慢思考** | 高 tension / 追问 | conflicts_with + 正文 + spatial 坐标 | 视需求 |
| **L3 归档** | Dream consolidation | 完整 9 接口 | 全量 |

### 写入时机

```
对话中
  → 不写完整卡片
  → Script A/B 只抓碎片到 inbox/fragments_YYYY-MM-DD.md
  ↓
每日结束（或微睡眠时）
  → DreamConsolidator 扫描 inbox
  → 筛选（晋升 / 丢弃）
  → 生成正式记忆卡
  → 多的删除
```

### 72 小时代谢窗口

| 时间段 | 状态 | 处理 |
|--------|------|------|
| 0~72 小时 | 活跃区 | 完整保留，八维评分可用 |
| >72 小时 | 分拣区 | 评分 ≥ 0.75 → 晋升长期记忆；其余 → 降级或丢弃 |
