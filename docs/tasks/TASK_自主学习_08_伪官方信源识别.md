## 理论逻辑

仿冒官方文档、伪造 GitHub 仓库、域名钓鱼等手段层出不穷。给它装上"数字火眼金睛"。

### 维度一：DNS 指纹与域名"照妖镜"
- 核心项目建立官方域名白名单
- 重点防御"形近字欺骗"（docker-docs.com vs docs.docker.com）
- WHOIS 注册时间极短（<1年）或高度隐私隐藏 → 触发"高危仿冒预警"

### 维度二：跨模态"引用溯源"验证
- 提取文中所有超链接，验证目标页面是否真实存在
- 检测"标题篡改"或"404死链"（伪官方维护不善的典型症状）
- 架构图、Logo 反向图片搜索：图片最早出现在官方仓库但当前域名陌生 → "盗图仿冒"

### 维度三：技术元数据与"数字签名"核查
- 提取代码变量命名习惯、缩进模式，与官方源码 Diff 比对
- 代码高度雷同但注释被篡改，或缺失官方特有安全校验逻辑 → "洗稿伪官方"
- 网页底部版权声明、ICP 备案号、SSL 证书颁发机构核查
- 非正规 CA 颁发的证书 → 一票否决

### 维度四：信源"时间密度"与社区共识异常检测
- "重磅官方更新"只在某孤立网站出现，主流技术社区零声量 → "人造共识警报"
- GitHub Issues / Stack Overflow / Hacker News 搜索验证
