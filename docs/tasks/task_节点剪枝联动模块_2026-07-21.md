## 完成内容

### 1. `src/forget_prune_linkage.py`（遗忘-剪枝联动协议）
- 将 `DreamDecay`（自然遗忘衰减）的 `prune_ready` 信号转译为 `ConstraintLifecycle`（节点剪枝）的实际删除动作。
- 规则① 能量=0 + 无新连接 → 调用 `prune_node(reason="energy_depleted")` 自动删除节点，并同步清除 decay 快照（遗忘完成闭环）。
- 规则② 崩溃级张力（`surface_tension_state.json` 的 `tension ≥ 0.85`）→ 对所有 PEEL/RECURSE 阶段节点 `trigger_truncate(reason="crash_tension")` + 留痕日志。
- 本地状态：`_agent_memory/forget_prune_linkage_state.json`（累计 auto_pruned / crash_pruned / crash_events）。

### 2. `src/prune_thermal_guard.py`（剪枝热保护）
- 将 `TopologyThermalMonitor`（拓扑热保护）分级信号转译为 `ConstraintLifecycle` 保护动作。
- NORMAL → 正常通行（恢复节点接入）。
- L1_WARNING → 标记 `admission_paused`（减速新节点接入，不删节点）。
- L2_OVERLOAD → 对弱连接节点 `prune_node(reason="weak_connection")` 卸载。
- L3_CRITICAL → 对所有活跃节点 `trigger_truncate(reason="thermal_emergency")` 强制切断。
- 本地状态：`_agent_memory/prune_thermal_guard_state.json`。

## 关键技术决策与坑点

- **`or` 陷阱（P0 级）**：`ConstraintLifecycle` 定义了 `__len__`，空实例 `bool()` 返回 `False` → 原 `self._lifecycle = lifecycle or ConstraintLifecycle()` 会把传入的空生命周期误判为 falsy，新建一个实例并从旧状态文件加载脏数据（node_auto_1 残留）。已改为 `lifecycle if lifecycle is not None else ConstraintLifecycle()`。两模块均已修。
- **`prune_node` reason 枚举约束**：合法值为 `{manual, weak_connection, energy_depleted, overload}`，L2 卸载必须用 `weak_connection`（曾误用 `thermal_unload` 触发 `ValueError`）。`trigger_truncate` 的 reason 不校验，故 `crash_tension`/`thermal_emergency` 可用。
- **测试等级驱动**：`guard_once()` 依赖 `monitor.check()` 实时计算，直接改 `_accumulated_tension` 不生效；测试改用 fake `ThermalReport` 驱动分级，干净验证响应逻辑。
