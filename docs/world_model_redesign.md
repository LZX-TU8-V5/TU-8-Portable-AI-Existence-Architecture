## 一、问题定义

### 1.1 原始架构的隐含假设（错误）

在 EFHV 架构推导中，我和千问都**隐含假设**了：

> "世界模型是一个**主动的预测引擎**，它基于上下文/时序/物理规律预测'下一个状态应该是什么轮廓、什么结构'，然后指导 L0-L4 进行验证。"

这个假设来源于：
- 认知神经科学中的"预测编码理论"（Predictive Coding）
- 大语言模型的"下一个token预测"范式
- 机器人学中的"模型预测控制"（MPC）

### 1.2 用户的修正（关键洞察）

**人类的世界模型不是"主动预测"，而是"被动框架"**。

具体来说：
1. **被动交互** - 世界模型不直接"预测"，它只是**内置在大脑皮层中的认知框架**，当外界刺激输入时，这个框架被动地"激活"相关认知模块。
2. **内置价值观/世界观/人生观** - 这个世界模型包含了：
   - **价值观**：什么重要、什么不重要（注意力分配）
   - **世界观**：世界如何运作（物理规律、社会规则）
   - **人生观**：我是谁、我要什么（目标函数、决策偏好）

### 1.4 与千问的辩论及用户修正（关键）

在初步形成"被动框架"方案后，我与千问进行了深入辩论，用户（金木蟾）给出了关键修正：

**千问的初始反驳**：
> "人脑就是主动预测的，而且这是现代认知神经科学最核心的共识！"

**用户的反驳（核心洞察）**：
> "你才是顺从啊！人之所以是主动预测，是因为人脑屏蔽了很多内容。人脑一直在运转（不用主动预测来屏蔽就烧机了），而 AI 不是，是激活才运转。现阶段不是内置一直在运转的，而是被动激活的。"

**用户的进一步决策**：
> "我需要预留主动预测接口，未来具身需要。"

**修正后的结论**：
1. **当前阶段（纯视觉/云端 AI）**：AI 硬件特性是"激活才运转"，因此可以设计为"被动激活"
2. **未来阶段（具身智能/机器人）**：物理世界有惯性且充满危险，必须"主动预测"以避免致命延迟
3. **架构策略**：将"预测引擎"做成可插拔模块，当前关闭，未来开启

**详细辩论记录**：见 `docs/active_vs_passive_world_model.md`

## 二、修正后的架构定义

### 2.1 世界模型的重新定义

**修正后（最终版）**：世界模型 = **被动认知框架（当前）** + **可插拔主动预测接口（未来）** + **内置信念系统**

> **重要说明**：经过与千问的辩论和用户的修正，世界模型的设计需分两个阶段：
> - **当前阶段**：被动认知框架（适配 AI 硬件特性：激活才运转）
> - **未来阶段**：可插拔主动预测接口（适配具身智能需求：物理世界有惯性）

#### 被动认知框架
- **不是**主动预测"下一个状态是什么"
- **而是**当输入刺激到达时，被动地激活：
  - 相关记忆（知识图谱中的节点）
  - 相关规则（审计引擎中的约束）
  - 相关目标（价值观/人生观驱动的优先级）

#### 内置信念系统
- **价值观**：定义"什么重要"（注意力分配权重）
- **世界观**：定义"世界如何运作"（物理规律、因果链条）
- **人生观**：定义"我是谁、我要什么"（目标函数、决策偏好）

#### 可插拔主动预测接口（未来阶段）
> **设计动机**：当前阶段 AI 硬件特性是"激活才运转"，适合被动激活。但未来具身智能（机器人）在物理世界中运行，必须主动预测以避免致命延迟。因此，需要将"预测引擎"设计为可插拔模块。

**接口定义**：
```python
class PredictiveEngineInterface:
    """主动预测引擎接口（可插拔）"""
    
    def __init__(self, enabled=False):
        self.enabled = enabled
        self.prediction_frequency = 100  # Hz（具身智能需要高频率）
    
    def predict(self, current_state):
        """主动预测下一帧的物理状态"""
        if not self.enabled:
            return None  # 当前阶段关闭
        
        # 未来阶段：主动预测
        next_state = self._compute_next_state(current_state)
        return next_state
    
    def inject_as_prior(self, prediction, validation_framework):
        """将预测结果作为先验信号注入验证框架"""
        if prediction is None:
            return
        
        # 注入到 L0-L4 漏斗
        validation_framework.set_prior(prediction)
```

**使用场景**：
- **当前阶段（关闭）**：纯视觉 AI，被动激活，省电高效
- **未来阶段（开启）**：具身智能，100Hz 主动预测，实时响应

**与 EFHV 架构的整合**：
```
预测引擎（100Hz 主动预测）
  ↓
输出先验信号：("预测下一步会看到苹果侧面", confidence=0.8)
  ↓
注入到 L0-L4 漏斗
  ↓
L0：几何轮廓排除（被动激活，但基于先验加速）
  ↓
L1：生物/非生物特征排除（被动激活，但优先验证"苹果侧面"模板）
  ↓
...（后续层级同样受益于先验信号）
```

### 2.2 对 EFHV 架构的影响

#### 影响1：L0-L4 排除漏斗的"指导信号"来源改变

**原始设计**：世界模型主动预测 → 指导 L0-L4 验证  
**修正后**：输入刺激激活世界模型 → 被动框架释放"注意力权重" → L0-L4 根据权重分配计算资源

**具体变化**：
- L0（几何轮廓排除）不再需要"预测轮廓"，只需要"激活轮廓模板库"
- L1-L2（特征/状态排除）不再需要"预测特征"，只需要"激活相关特征检测器"
- L3（语义确认）不再需要"预测语义"，只需要"激活语义网络中的相关节点"
- L4（物理一致性）不再需要"预测物理状态"，只需要"激活物理规律校验器"

#### 影响2：双向筛选的信息流向改变

**原始设计**：自顶向下（预测→验证）+ 自底向上（验证→修正预测）  
**修正后**：自顶向下（框架激活→资源分配）+ 自底向上（验证结果→更新框架权重）

**关键区别**：
- "预测"是**生成性的**（world model → generates hypothesis）
- "激活"是**检索性的**（input → retrieves relevant modules）

#### 影响3：模式B（瞬态开放探索）的触发条件改变

**原始设计**：预测置信度 < 阈值 → 切换到模式B  
**修正后**：框架激活失败（无相关模块可激活）→ 切换到模式B

**具体变化**：
- 不是"预测不准"，而是"框架中没有这个东西的认知模块"
- 模式B不再是"开放探索"，而是"框架扩展"（主动学习新模块）

### 3.2 阶段2：分析当前实现的差距

**当前 TU-8 的世界模型组件**：
1. `tu8_memory.py` - 事件总线（被动记录，非主动预测）✅ 符合被动框架
2. `consciousness_cycle.py` - 意识周期（主动推理，非被动激活）❌ 不符合
3. `user_metabolism.py` - 用户代谢（主动分析，非被动激活）❌ 不符合
4. `sag_lite_knowledge_graph.py` - 知识图谱（被动查询，符合）✅ 符合被动框架
5. `tu8_agent.py` - 主智能体（主动决策，非被动激活）❌ 不符合

**差距总结**：
- ✅ 已有：被动记录（事件总线）、被动查询（知识图谱）
- ❌ 缺少：内置信念系统（价值观/世界观/人生观）
- ❌ 错误：当前是"主动推理/决策"，应改为"被动激活"

### 3.3 阶段3：设计"被动认知框架"的技术规格

#### 组件1：注意力权重分配器（价值观）
- **输入**：当前memory/archive/2026-05/上下文
- **输出**：各认知模块的激活权重
- **实现**：可用规则的优先级 + 用户反馈历史训练

#### 组件2：物理规律校验器（世界观）
- **输入**：L4 的物理一致性验证请求
- **输出**：是否通过物理规律校验
- **实现**：规则引擎（hard constraints）+ 概率模型（soft constraints）

#### 组件3：目标函数管理器（人生观）
- **输入**：用户指令/任务描述
- **输出**：任务优先级、资源分配策略
- **实现**：可用用户的显式偏好 + 隐式行为模式学习

#### 组件4：框架激活路由器（核心）
- **输入**：输入刺激（文本/图像/事件）
- **输出**：激活哪些认知模块、激活权重多少
- **实现**：可用向量相似度检索 + 规则匹配

### 3.4 阶段4：实施与验证

**最小可行性验证**：
1. 实现一个简化版的"框架激活路由器"（被动认知框架）
2. 设计"主动预测接口"的插件规范（可插拔模块）
3. 用具体任务验证"被动激活"是否比"主动预测"更高效
4. 对比"主动推理"与"被动激活"的错误模式差异

### 3.5 阶段5：硬件适配性分析（新增）

**目标**：明确当前阶段与未来阶段的硬件特性差异，指导架构设计

**当前阶段（纯视觉/云端 AI）**：
- **硬件特性**：GPU/云端运行，激活才运转，功耗 ≈ 0
- **架构策略**：被动激活框架，按需唤醒，省电高效
- **典型案例**：图片识别、文档审核、知识检索

**未来阶段（具身智能/机器人）**：
- **硬件特性**：端侧运行，物理世界有惯性，必须实时响应
- **架构策略**：可插拔主动预测接口，100Hz 主动预测物理状态
- **典型案例**：机器人抓握、自动驾驶、无人机避障

**技术实现**：
```python
class WorldModel:
    def __init__(self):
        self.passive_framework = PassiveActivationFramework()
        self.predictive_engine = PredictiveEngineInterface(enabled=False)  # 当前关闭
    
    def process(self, stimulus):
        # 当前阶段：纯被动激活
        result = self.passive_framework.process(stimulus)
        
        # 未来阶段：如果开启预测引擎，注入先验信号
        if self.predictive_engine.enabled:
            prediction = self.predictive_engine.predict(current_state)
            result = self.passive_framework.process_with_prior(stimulus, prediction)
        
        return result
```

## 四、与原有架构的兼容性分析

### 4.1 兼容部分

- ✅ L0-L4 排除漏斗的**验证逻辑**不变（依然是排除不匹配项）
- ✅ 双向筛选的**信息流向**不变（依然是自顶向下 + 自底向上）
- ✅ 模式A/B 的**切换逻辑**不变（依然是基于置信度/激活成功率）

### 4.2 不兼容部分（需要修改）

- ❌ 世界模型的**实现方式**（从主动预测改为被动框架）
- ❌ 注意力分配的**机制**（从动态预测改为静态权重）
- ❌ 模式B的**定义**（从开放探索改为框架扩展）

### 4.3 修改成本评估

| 模块 | 修改成本 | 原因 |
|------|---------|------|
| `tu8_agent.py` | 高 - 需要重构决策逻辑 | 当前是主动推理，需改为被动激活 |
| `consciousness_cycle.py` | 中 - 需要重新定义"意识" | 当前是主动反思，需改为被动唤醒 |
| `sag_lite_knowledge_graph.py` | 低 - 只需添加"激活权重"字段 | 当前是被动查询，符合框架 |
| `deviation_gate.py` | 低 - 只需添加"价值观权重" | 当前是硬约束，可叠加软权重 |

## 六、开放问题（需进一步讨论）

### 6.1 理论问题

1. **"被动框架"是否真的比"主动预测"更高效？**
   - 需要认知科学文献支持
   - 需要具体任务的定量对比

2. **"内置信念系统"是否会导致"偏见固化"？**
   - 价值观/世界观/人生观一旦内置，如何更新？
   - 是否需要"元认知"模块来监控信念系统的偏差？

### 6.2 工程问题

1. **"框架激活"的粒度如何定义？**
   - 是激活整个模块（如"视觉认知模块"）？
   - 还是激活模块内的某个函数（如"L0轮廓检测函数"）？

2. **"被动"是否意味着"无目标"？**
   - 如果世界模型完全是被动的，那么"目标导向行为"从何而来？
   - 是否需要一个"元目标模块"来设置高层目标，然后世界模型被动地激活相关模块？

3. **"可插拔主动预测接口"的粒度如何定义？**
   - 预测引擎是预测"下一帧图像"？还是预测"下一物理状态"？
   - 预测结果的置信度如何传递给验证框架？
   - 预测频率（100Hz）是否足够？是否需要更高？

4. **如何保证"被动激活"与"主动预测"的无缝切换？**
   - 当具身智能从"静止状态"切换到"运动状态"时，预测引擎如何自动开启？
   - 当任务从"实时交互"切换到"离线分析"时，预测引擎如何自动关闭？
   - 是否需要一个"模式管理器"来动态加载/卸载预测引擎？

### 6.3 硬件适配性问题

1. **当前阶段（GPU/云端）的"被动激活"真的省电吗？**
   - GPU 的"激活才运转"特性是否真的省电？还是说，频繁激活/休眠反而更耗电？
   - 需要硬件基准测试（功耗、延迟、准确率）

2. **未来阶段（端侧/神经形态芯片）的"主动预测"真的可行吗？**
   - 神经形态芯片是否支持 100Hz 的主动预测？
   - 端侧硬件的算力/功耗是否支持"预测引擎 + 验证框架"同时运行？
   - 需要硬件-软件协同设计（co-design）
