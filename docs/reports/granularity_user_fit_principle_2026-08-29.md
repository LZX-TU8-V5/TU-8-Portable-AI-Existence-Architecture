# 颗粒度的使用者约束（Granularity-as-Fit-Parameter，李奥 22:41 设计反思）

- 记录：2026-08-29 22:41 GMT+8
- 性质：设计层原则，修正 §0.0.10「轴内可无限精细化」的绝对化表述

## 核心论断

颗粒度问题（记忆单元切多粗/多细）不是记忆本体的客观属性，而是**使用者拟合参数**。其约束来源：

1. **编程语言对应物（表征基底）**：系统自身的表征"母语"（Codebook/Polycube 怎么分块）决定颗粒度分布的基底。
2. **用户背景**：同一基底上，颗粒度必须贴合使用者才有效。
3. **文化程度**：另一重约束。
4. **个性**：最终收束变量。

→ **没有最完美的方案，只有贴合使用者的方案。**

## 与既有设计的耦合

- 修正 §0.0.10：维度不可坍缩 ≠ 内部不可生长（对）；但内部生长的方向/密度不是自由的，是被使用者剖面收束的（补）。
- 「多语言学家找共性 + 贴合语态」= 跨用户抽象（共性→高层 sym）+ 按用户落 register（个性→颗粒度），与 §0.0.9 组合/抽象扩展同构，但显式化"为谁"。
- 「前期硬编码 → 后期生活融入」= 既有 L0 不手写 / d_depth 涌现 的颗粒度层重述：种子期靠 profile 硬编码锚定，后期靠 reinforce/bridge 从生活长出。

## 设计含义（开放）

- Codebook 颗粒度需要一条独立于 a/b/k/t 四轴之外的「使用者拟合轴」（profile-driven granularity），否则 §0.0.10 的"无限生长"会漂成无锚膨胀。
- 落到实现：用户 profile（语言/背景/文化程度/个性）应作为颗粒度选择的输入，而非固定切分规则。
