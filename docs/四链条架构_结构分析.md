**状态**：⚠️ 功能完整，但与钢印链未打通

- **代谢产物无处可去**

**状态**：⚠️ 功能完整，但与其他三条链完全孤立

## 三、耦合问题汇总

### 问题 1：钢印链定义重复

```python
# consciousness_cycle.py:323
class Seal:
    """钢印 - 时间链条上的不可篡改节点"""

# seal_protocol.py:40
class Seal:
    """钢印协议"""
```

**后果**：两个 `Seal` 类字段不一致，可能导致数据不兼容

---

### 问题 2：记忆链不写回钢印链

```python
# tu8_memory.py:1295
seal_id = f"s_{int(time.time() * 1000)}_core"
# seal_id 生成后只赋值给 MemoryEntry
# 没有写入 seal_index.json 或 seal_chain
```

**后果**：记忆有钢印标记，但钢印链不知道这条记忆的存在

---

### 问题 3：调度链不调用记忆链

```python
# tu8_dispatch.py:280
def _build_memory_context(self) -> str:
    return ""  # 完全独立
```

**后果**：上下文装配时没有记忆数据支持

---

### 问题 4：代谢链完全孤立

```python
# consciousness_cycle.py 没有任何 import 引用：
# - tu8_memory.py
# - tu8_dispatch.py
# - seal_protocol.py
```

**后果**：代谢结果无法写回其他三条链

## 四、设计目标的耦合要求

根据外协对话文档，四链条应该：

```
调度 + 记忆：调度链拉取记忆时，必须带上记忆的"钢印ID"
记忆 + 代谢：记忆链产生的新条目，自动触发代谢链评估
代谢 + 钢印：代谢链在整合后，必须生成"元钢印（Meta-Seal）"
钢印 + 调度：调度链装配上下文时，以最新钢印为根节点发散
```

## 五、耦合方案（三选一）

### 方案 A：最小侵入式（推荐）

**原则**：不改动现有代码结构，只增加桥接层

**实现**：
1. 创建 `tu8_coupling.py` 桥接模块
2. 暴露统一接口：
   ```python
   def store_memory_with_seal(content, tags, emotion, meaning) -> Tuple[str, str]
       # 返回 (memory_id, seal_id)

   def recall_with_seal_chain(query, top_k) -> List[Tuple[MemoryEntry, Seal]]
       # 返回带钢印的记忆

   def trigger_metabolism() -> Dict
       # 触发代谢链，返回元钢印
   ```

**优点**：风险最低，易于回退
**缺点**：多一层间接调用

---

### 方案 B：重构式（激进）

**原则**：统一 `Seal` 类，打通四链条

**实现**：
1. 删除 `consciousness_cycle.py` 中的 `Seal` 定义
2. 统一使用 `seal_protocol.py` 的 `Seal`
3. 在 `TU8MemoryEngine.store()` 中调用 `Seal.create()`
4. 在 `ConsciousnessCycle` 中注入 `TU8MemoryEngine` 实例
5. 在 `ContextAssembler` 中注入 `TU8MemoryEngine` 实例

**优点**：架构最干净
**缺点**：改动量大，风险高

---

### 方案 C：事件驱动式（异步）

**原则**：通过事件队列解耦

**实现**：
1. 创建 `tu8_events.py` 事件总线
2. 定义事件类型：
   ```python
   class MemoryStored(Event):
       memory_id: str
       seal_id: str

   class MetabolismTriggered(Event):
       trigger_reason: str

   class SealCreated(Event):
       seal_id: str
       seal_type: str
   ```
3. 各链订阅相关事件

**优点**：完全解耦，易于扩展
**缺点**：调试复杂，异步问题难以追踪

---

## 六、推荐方案

**推荐方案 A（最小侵入式）**

理由：
1. 当前代码量已大（~5000 行），大幅重构风险高
2. 核心功能基本完整，只需要打通接口
3. 易于逐步迁移到方案 B
