# 架构决策：建立统一词汇库

**日期**：2026-06-27 03:07 GMT+8
**来源**：造物主指示

---

## 一、问题识别

### 当前分散的词汇定义

#### 1. 钩子系统
- `trigger_hooks` - 触发钩子词汇
- `semantic_hooks` - 语义钩子词汇
- 黑名单词汇

#### 2. 正则拦截
- `EVENT_KEYWORDS` - 事件关键词（"记住", "重要", "核心"...）
- `scene_tag` - 场景标签（"dev", "novel", "chat"...）
- 命名模块词汇

#### 3. 状态层
- Phase 枚举（"awake", "light_sleep"...）
- NoteType 枚举（"interaction", "insight"...）
- seal_type 词汇（"origin", "rhythm", "phase_transition"...）

#### 4. 其他模块
- 用户偏好词汇
- 项目状态词汇
- 认知锚点类型词汇

---

## 二、问题

### 分散定义的后果

1. **重复定义**：同一词汇在多处定义
2. **不一致**：不同模块使用不同词汇表示同一概念
3. **难维护**：修改词汇需要改多处代码
4. **难扩展**：新增词汇需要改多个模块

---

## 三、解决方案

### 建立统一词汇库

**设计原则**：
1. **单一真理源**（Single Source of Truth）
2. **分类管理**（按功能域分类）
3. **版本控制**（可追踪变更）
4. **动态加载**（可热更新）

---

## 四、架构设计

### 4.1 词汇库结构

```
memory/
    vocabulary/
        ├── core.json           # 核心词汇（Phase, SealType...）
        ├── hooks.json          # 钩子词汇（trigger, semantic, blacklist...）
        ├── scenes.json         # 场景词汇（dev, novel, chat...）
        ├── events.json         # 事件词汇（记住, 重要...）
        ├── anchors.json        # 锚点类型词汇
        └── user_preferences.json  # 用户偏好词汇
```

### 4.3 词汇分类

| 分类 | 文件 | 示例 | 用途 |
|------|------|------|------|
| **core** | `core.json` | Phase, SealType | 核心状态定义 |
| **hooks** | `hooks.json` | 触发词、黑名单 | 钩子系统 |
| **scenes** | `scenes.json` | dev, novel, chat | 场景识别 |
| **events** | `events.json` | 记住, 重要 | 事件检测 |
| **anchors** | `anchors.json` | interaction, insight | 认知锚点类型 |
| **user_preferences** | `user_preferences.json` | 简洁, 安全 | 用户偏好 |

## 六、优势

### 统一词汇库的好处

1. **一致性**：所有模块使用同一词汇定义
2. **可维护**：修改一处，全局生效
3. **可扩展**：新增词汇只需添加到词汇库
4. **可追溯**：词汇变更有记录
5. **可热更新**：无需重启即可更新词汇
