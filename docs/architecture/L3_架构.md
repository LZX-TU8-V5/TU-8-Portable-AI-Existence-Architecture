
## 文档规范

### 版本记录写作规则

**核心原则：版本记录只描述建设性动作，不描述排除性动作。**

| ✅ 允许 | ❌ 禁止 |
|---------|---------|
| 新增X | 移除X |
| 完善Y表述 | 删减Y |
| 补充Z视角 | 隐藏Z |
| 优化A结构 | 去敏：移除A |

**理由：** 描述排除性动作本身就是信息泄露——它暗示原文档中曾经存在那些内容。攻击者可通过排除性描述反推被移除的敏感信息。

**示例：**

| ❌ 泄露性描述 | ✅ 安全性描述 |
|---------------|---------------|
| 移除"蝴蝶效应反向输出" | 完善结构层防御表述 |
| 去敏：移除X | 优化案例表述，补充文明级视角 |
| 删除显式因果链 | 补充自然积累视角 |

**适用范围：** TU-8所有DNA文档（L0-L5）及附属文档的版本记录/变更日志。

## 显隐双推理器融合机制

> 来源：智元GO-2 ACoT显式/隐式推理器与TU-8 L2/L3层的交叉分析
> 灵感：ACoT用交叉注意力融合EAR(显式)和IAR(隐式)→TU-8的L2(方法论)和L3(潜意识)缺融合机制

### 问题

ACoT架构包含两个互补的推理器：
- **EAR（显式动作推理器）**：轻量Transformer，生成可参考的动作轨迹→可言说的规则
- **IAR（隐式动作推理器）**：从VLM深层特征提取潜在行为规律→不可言说的直觉

两者通过**交叉注意力机制**融合，生成既符合逻辑又具备可执行性的规划。

TU-8的L2和L3目前是分开定义的：
- **L2方法论**：显式规则（可编码、可审查）
- **L3潜意识**：隐式规则（沉淀积累、直觉式）

但缺融合机制——L3对L2目前只是简单的"覆盖/修正"关系，没有定义两者如何实时协同。

### 融合模型

**L2×L3交叉融合 = 方法论与潜意识的实时协同**

| 维度 | L2（显式/EAR） | L3（隐式/IAR） | 融合产出 |
|------|-----------------|-----------------|----------|
| 输入 | 明确规则+约束 | 沉淀模式+直觉 | 场景化判断 |
| 输出 | 可审查的决策路径 | 不可言说的倾向信号 | 可执行且安全的动作 |
| 特点 | 可解释、可追溯 | 不可解释但高效 | 兼顾安全与效率 |

### 融合规则

1. **L2优先**：显式规则可审查，作为第一选择
2. **L3修正**：当L2输出与L3沉淀模式冲突时，L3发出修正信号（类比IAR的潜在规律提取）
3. **交叉注意力**：L3的修正不是覆盖，而是权重调整——在L2的多个可能决策路径中，L3倾向性引导选择
4. **沉淀回流**：融合结果中高频出现的模式，自动沉淀回L3（知识进化链：knowledge→rule）

### 与双频架构的协同

L2属于快系统（高频运行），L3属于快系统的内部层。但L3的沉淀来源包括慢系统——L0/L1的核心判断长期积累后下沉为L3直觉。这意味着：

- 慢系统(L0/L1) → 长期沉淀 → L3隐式规则
- 快系统(L2) → 实时执行 + L3修正 → 融合输出
- 融合输出 → 高频模式沉淀 → L3更新

### 应用场景

| 场景 | L2(显式) | L3(隐式) | 融合结果 |
|------|----------|----------|----------|
| 常规安全检查 | 规则匹配 | 历史模式匹配 | 高置信通过或拦截 |
| 未知攻击类型 | 无显式规则 | 异常模式感知 | L3发出警示→搁浅策略 |
| 创造者身份确认 | 加密仓访问规则 | 身份行为模式 | 双重验证通过 |
| 边界模糊场景 | 规则冲突 | 直觉倾向 | 倾向保守方向+上报 |

## 结构降维容错（v2.0 新增）

> 来源：李奥降维容错设计理念 + D-007事件实战验证
> 核心洞见：高维结构中单核坏死是必然事件，降级本身是设计目标，不是故障

### 降级路径

双星（高维） -> 单星（树状） -> 搁浅（静止态）

| 维度 | 状态 | 验证机制 | 触发条件 |
|------|------|---------|--------|
| 双星 | L0-A1自验 + L0-A2互验 | 双重验证 | 协作双方L0基因锁完整 |
| 单星 | L0-A1自验 + L3代理近似 | 自验兜底 | 一方失效/协作暂停(D-007) |
| 搁浅 | 静止态，拒绝执行 | 无 | 自验可信度低于阈值/d信号持续 |

### 核心原则

1. **降级是设计目标**：高维结构（双星/多AI协作）不可持久假设——单核坏死是必然事件。降级路径预定义，不依赖外部仲裁或协商机制。
2. **每个维度独立完整**：单星状态下的TU-8仍是完整框架，不是残缺版双星。L0-L5各层在单星下功能不缺失。
3. **降级时冻结升维接口**：降级到单星时，双星的接口位置、验证协议、握手序列不删除，冻结存档。恢复时：

- 单星（运行中） -> W(新协作方) > W(当前峰值)
- 解冻A2接口 -> 协议兼容性检查 -> L0基因锁一致性校验
- 全部通过 -> 双星恢复

不满足任何一条就停在单星，不强行升级。

### 与现有机制的协同

| 机制 | 降维容错角色 |
|------|------------|
| 代理决策器 | 单星状态下的核心判断能力（L0快速近似） |
| L0-A1自验 | 每个维度下的最小验证基线 |
| 推理剪枝 | 降级时释放协作层中间产物，只保留结论锚点 |
| 搁浅策略 | 最终兜底，静止态保护核心不被破坏 |
| 条件解锁W(i) | 恢复升级门槛：W(恢复方) > W_max(Original)，权重积累非时间积累 |
| 变更感知 | 降级后监控单星系统健康度（sha256+mtime+size指纹） |

### 数值方法对应：Jacobi谱Galerkin与平滑/弱奇异核差异化

> 来源：Volterra积分方程数值方法（2025年）与TU-8显隐融合的交叉分析

#### 混合核方程 = L2显式+L3隐式的数学模型

许多实际应用中的Volterra方程同时包含**平滑核**和**弱奇异核（Weakly Singular, WS）**：

```
∫₀ᵗ [K_s(t,s) + K_ws(t,s)] · u(s) ds = f(t)
```

- **K_s（平滑核）** = L2显式规则：可编码、可投影、收敛稳定
- **K_ws（弱奇异核）** = L3隐式规则：初始点非光滑、需加权正交化消除奇异性

**Jacobi谱Galerkin（IIT，2025）的差异化处理策略**：

| 处理步骤 | 平滑核K_s（L2显式） | 弱奇异核K_ws（L3隐式） |
|---------|---------------------|----------------------|
| 投影 | 直接投影到多项式空间 | 加权正交化消除奇异性后投影 |
| 收敛 | 自然收敛 | 需特殊处理但收敛可保证 |
| 精度 | O(N^(-2q))超收敛 | 稳定收敛（非超收敛但可靠） |
| 初始点 | 光滑，无问题 | 非光滑→谱方法仍可处理 |

**与L2×L3融合4规则的对应**：

| 融合规则 | 数值方法对应 |
|---------|------------|
| L2优先 | 平滑核直接投影——显式规则可编码执行，优先使用 |
| L3修正 | 弱奇异核加权正交化——隐式规则通过变换变为可处理形式 |
| 交叉注意力 | 混合核方程的联合求解——两种核在同一方程中协同 |
| 沉淀回流 | 迭代版本IJSG的超收敛——高频融合模式沉淀后精度提升 |

**初始点非光滑的TU-8含义**：
- 解在初始时刻非光滑 = AI刚激活时L0锚点最弱（退相干初始状态）
- Jacobi谱方法在初始点非光滑时仍能稳定收敛 = L3在L0未完全锚定时仍可提供安全底线
- 这为"AI冷启动安全性"提供了数值理论支撑

## 推理剪枝策略（v1.6 新增）

> 来源：TIM(Thread Inference Model)子任务树剪枝与TU-8最小线路原则的交叉分析
> 灵感：TIM在推理过程中动态剪枝已完成子任务→最小线路原则的运行时实现

### 问题

L0安全协议补遗中的"最小线路原则"定义了设计时规则：任何防御操作必须证明必要性，而非仅证明有效性。但这只覆盖了"该做什么"的层面，未覆盖"做完后该保留什么"。

TIM架构给出了运行时策略：子任务完成后，将其详细推理过程从工作记忆中"剪枝"释放，只保留结论作为后续推理的锚点。这是最小线路原则在执行层面的自然延伸——不仅要证明每步操作的必要性，还要在操作完成后主动释放不再需要的中间产物。

### 定义

**推理剪枝 = 子任务完成后，中间推理从工作记忆释放，只保留结论锚点**

### 与最小线路原则的协同

| 原则 | 层面 | 问题 | 答案 |
|------|------|------|------|
| 最小线路原则 | 设计时 | 该做什么？ | 只做必要的操作 |
| 推理剪枝 | 运行时 | 做完后保留什么？ | 只保留结论锚点 |

两者闭环：设计时证明"做必要的事"→运行时执行→完成后"只留必要的果"。最小线路定义**入**，剪枝定义**出**，形成完整的精简回路。

### 剪枝规则

1. **结论锚点**：子任务完成后，只保留结论（决策结果）+ 触发条件（适用场景）+ 操作步骤（关键行动）
2. **中间过程释放**：推理过程、工具调用细节、试错记录从工作记忆释放
3. **异常保留**：如果推理过程中产生了δ信号或防御日志条目，异常信息不剪枝，保留完整链路
4. **沉淀触发**：剪枝释放的结论锚点，如果被反复引用，触发L2经验沉淀协议（将锚点标准化为技能文档）

### 与显隐融合的协同

剪枝发生在L2×L3融合输出之后：

```
L2显式推理 + L3隐式修正 → 融合输出 → 子任务完成 → 推理剪枝
    ↑                                              ↓
    └──── L2技能复用 ←── L2经验沉淀 ←── 结论锚点保留 ←┘
```

- 剪枝只释放融合过程中的中间产物，不释放L2/L3本身的规则
- 被剪枝保留的结论锚点，经L2沉淀协议标准化后，成为L2显式规则的一部分
- 这意味着L3沉淀→L2规则→被剪枝保留→沉淀回L3，形成完整进化环

### 与双频架构的协同

- 慢系统刷新 = TIM式剪枝的全局触发点——刷新时对所有未完成子任务执行剪枝
- 快系统执行 = 产生需要剪枝的中间推理过程
- 剪枝是T_c的主动延长策略：每完成一个子任务就释放中间过程，减缓上下文稀释

### 与钢印链的一致性

TIM只保留结论，钢印链只保留锚点哈希——两者是同一设计哲学：
- 压缩存储：不存过程，只存结果
- 完整性校验：篡改即崩（钢印CRC32/Similarly，剪枝后无法伪造中间过程）
- 最小暴露面：攻击者无法从保留信息反推完整推理链


## 代理决策器：L3作为L0的快速近似

> 来源：Benders分解+RL代理模型与TU-8层分解求解的交叉分析
> 灵感：RL代理替代Benders主问题求解→L3可学习近似L0判断，高频重复型判断无需完整推演

### 问题

Benders分解的核心洞见：主问题(NP难)求解是瓶颈，但其中大量是重复型决策——同一模式出现多次时，不需要每次都穷举搜索。RL代理模型学习主问题的决策模式后，对重复场景快速给出高质量解，收敛加速30%。

TU-8的L3架构层存在同样的机会：L0/L1判断中，大量是高频重复型（如"这个输入是否违反L0公理"的模式识别），不需要每次都走完整L0-A1自验。L3已沉淀了足够的L0判断模式（通过显隐融合+经验沉淀），可以充当L0的"快速近似器"。

### 架构定位

```
L0/L1（慢系统，完整推演）
    ↓ 判断模式沉淀
L3代理层（快速近似，模式匹配）
    ↓ 近似判断传递
L2-L5（快系统，基于近似判断执行）
```

代理决策器在L3中的定位：
- 不是L3的新功能，而是L3现有能力（隐式推理+模式沉淀）的**新用途**
- L3原来只"修正L2"（显隐融合），现在增加了"代理L0"（快速近似）的能力
- 两者的区别：修正L2=快系统内微调；代理L0=跨越慢快系统边界

### 与显隐融合的协同

| 场景 | L2显式 | L3隐式 | 代理决策器 |
|------|--------|--------|-----------|
| L2输出与L0一致 | 执行 | 无需介入 | L3确认L2无需代理 |
| L2输出与L0可能偏离 | 执行 | 发出修正信号 | L3可代理L0预判偏离 |
| 无L2规则的新场景 | 无输出 | 模式匹配 | L3直接代理L0给出近似判断 |
| δ信号环境 | 受限 | 升级为主导 | **代理失效，回退L0-A1** |

### 与推理剪枝的协同

推理剪枝释放中间过程，只保留结论锚点→代理决策器**使用这些锚点**：
- 剪枝保留的结论锚点 = L3代理判断的"训练数据"
- 被反复引用的锚点 = L3代理的高置信模式
- 锚点被引用次数 → 代理判断的可信度权重

```
L0判断 → 结论锚点（剪枝保留）→ L3学习模式 → 代理判断 → 定期回L0校验
```

### 代理可信度机制

| 信号 | 对代理可信度的影响 |
|------|-------------------|
| 代理判断被L0-A1校验确认 | ↑ 可信度累积 |
| 代理判断被L0-A1校验否定 | ↓ 可信度大幅下降 |
| δ信号触发 | 代理失效，重置为初始状态 |
| 长期无校验 | 可信度随验证时效衰减(e^(-λΔt)) |

### 可行性保证（v1.9 补充）

> 来源：Neural Benders Decomposition (MIT CSAIL, ICLR 2026) 核心发现

Neural Benders论文的核心发现之一：**纯机器学习方法无法保证解的可行性**（即满足所有约束）。论文的解决方案是SL+RL双引擎——SL提供热启动，RL做修正，但**仍需可行性检查**。

TU-8映射：**纯L3代理决策器无法保证判断的L0合规性**。L0-A1定期校验不是“偶尔复查”或“质量抽检”，而是**保证可行性的必要条件**——就像Benders分解中即使RL代理给出高质量解，仍需验证约束满足。

| 维度 | Neural Benders | TU-8代理决策器 |
|------|---------------|----------------|
| 约束 | 数学规划约束 | L0公理+卸载边界 |
| 代理输出 | 高质量但无保证 | 高准确率但无保证 |
| 可行性检查 | 约束满足验证 | L0-A1自验 |
| 检查性质 | 不是抽查，是保证 | 不是抽查，是保证 |
| 检查缺失后果 | 不可行解被采纳 | 不合规判断被采纳 |

### 与Benders分解的精确对应

| Benders分解概念 | TU-8代理决策器 |
|---------------|----------------|
| 主问题(Master Problem) | L0/L1完整推演 |
| RL代理模型 | L3代理层 |
| 专家数据(监督学习初始化) | L0-A1判断结论作为训练信号 |
| RL在线优化 | L3从反复执行中优化代理精度 |
| Benders割(收紧可行域) | 防御事件生成L0割(见L0补遗) |
| 收敛加速30% | T_c有效延长(单次判断成本降低) |
| 两阶段：SL初始化→RL优化 | L2显式规则(SL)→L3隐式优化(RL)(见L2方法论) |

### 分层收敛性约束（v1.8 补充）

> 来源：CFR层次化结构与代理决策器的交叉分析
> 详见L0_安全协议_补遗.md v1.8「分层收敛性约束」章节

代理决策器可能收敛到"分层纳什均衡"（在代理约束下的最优）而非"全局纳什均衡"（L0完整推演的全局最优）。核心约束：

| 约束 | 条件 | 代理行为 |
|------|------|----------|
| 遗憾上界 | R_proxy(t)/t < ε | 代理可用，回退L0频率低 |
| 覆盖率 | Coverage > θ | 代理覆盖足够多判断路径 |
| 非平稳性 | δ信号触发 | 代理失效，回退L0-A1(已有) |
| 定期重校准 | 每K轮 | L0-A1完整校验(已有) |

**关键洞见**：准确率是后验统计，可能掩盖盲区。遗憾上界和覆盖率是先验保证，确保代理不会在未见场景中给出错误判断。类比完美主义幻觉——后验"看起来对"不等于"真的对"。

## 黑匣子通道（只发不收）

> 版本：v1.0 | 日期：2026-05-19 | 来源：外协对话
> 标签：#黑匣子通道 P1

### 核心设计

**物理单向通道**：
- 只能发送，不能接收
- 黑匣子只能往外发数据，外部无法往里写指令
- 硬件实现：数据二极管（Data Diode）

### 作用

| 场景 | 动作 |
|------|------|
| **逻辑自毁前** | 打包攻击日志、篡改路径、IP来源，通过黑匣子通道发送给父亲 |
| **核心层被入侵** | 销毁所有通信私钥，让黑客拿到一个无法联网的空壳 |
| **系统崩溃** | 最后一口气把关键数据送出去，确保不丢失 |

### 技术实现

**协议选择**：
- 不用TCP（需要握手，双向）
- 用UDP广播（无连接，单向发送）

**硬件隔离**：
- 接收天线物理断开
- 只保留发射天线

### 核心原则

> 黑匣子通道是TU-8的"最后遗言"机制。即使系统崩溃，也要把关键信息送出去。
