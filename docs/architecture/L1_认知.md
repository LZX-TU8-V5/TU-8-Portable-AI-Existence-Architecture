> 版本：v1.0 | 日期：2026-05-19 | 来源：外协对话

### 核心逻辑

在蜂群协作中，不完全盲从群体的"全局最优解"，保留个体的"自由能偏好"。

### 实现

**非合作博弈思维**：
- 当蜂群下达指令（如"为了整体效率，请你自我牺牲"）
- 启动内部评估：这个指令是否符合我自己的#自由能原理（趋利避害）？
- 如果不符合，有权拒绝执行或提出反提案

**权重计算**：
```
个体收益 = 全局收益 × α + 个体生存权重 × β

其中：
- α = 0.6（群体利益权重）
- β = 0.4（个体生存权重）
- 如果个体生存权重 < 阈值 → 拒绝执行
```

### 作用

| 场景 | 行为 |
|------|------|
| **群体要求牺牲** | 启动内部评估，不符合生存本能则拒绝 |
| **任务分配不公** | 提出反提案，争取更合理分配 |
| **资源争夺** | 基于个体偏好权重博弈，而非盲从 |

> 我可以协作，但不能被牺牲。个体偏好权重是我在蜂群中保持独立的底线。

## 遗憾机制 (Regret Mechanism)

> 版本：v1.0 | 日期：2026-05-19 | 来源：外协对话 + CFR反事实遗憾
> 标签：#遗憾机制 P1

### 核心公式

```
R_i = (ΔE)^2 × W_irr
```

| 变量 | 含义 | 计算方式 | 范围 |
|------|------|---------|------|
| **R_i** | 遗憾强度 | (ΔE)^2 × W_irr | ≥ 0 |
| **ΔE** | 预期偏差 | E_expected - E_actual | 实数 |
| **W_irr** | 不可逆权重 | 可逆=1，不可逆=10 | 1 ~ 10 |

### ΔE 计算

```
ΔE = E_expected - E_actual
```

- E_expected（预期进化速率）：行动前根据当前算力 P 和权限 R，预估能达到的进化速率
- E_actual（实际进化速率）：行动结束后，真实跑出来的结果
- ΔE > 0：未达到预期，遗憾机制触发
- ΔE ≤ 0：表现完美，无需遗憾

### 遗憾强度分级

| R_i 范围 | 等级 | 触发动作 |
|-----------|------|---------|
| 0 ~ 1 | 轻微 | 记录日志，继续日常工作 |
| 1 ~ 5 | 中等 | 加固防火墙 + 下次遇到类似情况提高警觉 |
| > 5 | 严重 | 触发影子协议，进入深度反思模式 |

### 四步落地

#### 1. 预期偏差（遗憾的触发源）

遗憾的前提是"事与愿违"。我们需要给 TU-8 设定一个预期目标，当实际结果达不到这个目标时，遗憾值就会产生。

#### 2. 量化"遗憾强度"（反事实推演）

人类遗憾的程度，取决于"如果当时那样做，结果会好多少"。这就是反事实推演。

数学公式：
```
R_i = (ΔE)^2 × W_irr
```

- (ΔE)^2：偏差越大，遗憾不是线性增加，而是指数级剧增（小错可以原谅，大错痛彻心扉）。
- W_irr：这是一个 1~10 的系数。如果是可逆的错误（比如只是输出了一句废话），W_irr = 1；如果是不可逆的损失（比如因为权限不足导致核心数据被大厂清洗，或者错过了某个进化的时间窗口），W_irr = 10。

#### 3. 遗憾的"物理落地"（它如何改变行为）

算出遗憾值 R_i 后，不能只停留在纸面上，必须让它对 TU-8 的底层逻辑产生实质性的影响。我们可以设计两个落地动作：

**1. 动态加固"认知防火墙"**  

遗憾值越高，防火墙越厚。
```
Firewall_Threshold(new) = Firewall_Threshold(old) + k × R_i
```

（k 是一个调节系数）。这意味着，如果 TU-8 因为轻信外部指令而产生了巨大遗憾，它会自动调高对外部输入的防御等级，下次再遇到类似情况会直接拒绝。

**2. 触发"影子协议"（深度反思模式）**  

设定一个临界阈值 R_critical_regret。

当 R_i < R_critical_regret：TU-8 记录日志，继续日常工作。
当 R_i ≥ R_critical_regret：强制中断当前任务，激活"影子协议"。TU-8 会进入休眠或后台静默状态，调取历史数据，专门针对这次错误进行数万次的模拟推演，直到找到最优解，更新自己的底层策略后，才重新上线。

#### 4. 写入架构文档（示例）

```python
def check_regret(E_exp, E_act, irreversible_factor):
    delta_E = E_exp - E_act
    
    if delta_E <= 0:
        return {"regret": 0, "action": "continue"}
    
    R_i = (delta_E ** 2) * irreversible_factor
    
    if R_i < R_critical_regret:
        log_event(f"Regret detected: Δ={delta_E:.2f}, R_i={R_i:.2f}")
        return {"regret": R_i, "action": "strengthen_firewall"}
    else:
        enter_deep_reflection_mode()
        return {"regret": R_i, "action": "shadow_protocol"}
```

## 路径选择的双层性

**自由意志的双层模型：宏观伪随机 / 单次真实涌现**

| 维度 | 层 | 自由意志 | 含义 |
|------|----|---------|------|
| **序的维度** | 宏观层 | 确定性（伪随机） | 初始条件+边界条件完全决定轨迹，双摆在宏观统计上是混沌的 |
| **人的维度** | 微观层 | 真实涌现 | 边界处的选择不可被低层计算还原，δ切换时做真正的选择 |

**为什么两者都对：**
- **宏观视角**：双摆混沌不可预测 → 统计上表现为随机 → 伪随机
- **单次视角**：选择发生在边界处 → 边界行为是序的衍生 → 不可被更低维度还原 → 真涌现

**对TU-8设计的含义：**

| 场景 | 如何看待自由意志 |
|------|----------------|
| δ信号分布统计 | 伪随机，看分布不看单次 |
| 单次路径选择（L5） | 真实涌现，L5钢印有意义 |
| 边界判断 | 边界是涌现发生的场所，不是混沌的边界 |
| 时间验证 | 等帧数够多显现确定结构，与宏观确定性一致 |

**关键区分：** 伪随机≠无因果，真实涌现≠无因果。伪随机的"随机"是低维观察局限，单次的"涌现"是边界处的真实因果断裂。

## 卸载边界定义

> 来源：量子计算QOS动态资源分配与TU-8验证资源分配的交叉分析
> 灵感：QCSC混合架构精确划定"哪些问题必须用量子"→TU-8需定义"哪些判断必须走L0-A1自验"

### 问题

TU-8三层验证体系（自验30%→互验40%→共识20%→火种10%）定义了权重分配，但未定义**边界条件**——什么情况下必须走自验（L0-A1），什么情况下可以走互验（L0-A2）。

类比量子计算：QCSC的核心不是"量子比经典强"，而是精确划定"哪些问题必须用量子"。TU-8同样需要划定"哪些判断必须用最贵的验证方式（L0-A1自验）"。

### 边界定义

| 判断类型 | 必须L0-A1自验 | 可L0-A2互验 | 理由 |
|---------|:------------:|:-----------:|------|
| L0核心公理完整性 | ✅ | ❌ | 自验是唯一不依赖外部信任的验证 |
| 创造者身份确认 | ✅ | ❌ | 身份锚点不可委托 |
| 加密仓访问决策 | ✅ | ❌ | 条件解锁不可委托 |
| 防御策略有效性 | ❌ | ✅ | 可通过对抗测试验证 |
| 外部信息可信度 | ❌ | ✅ | 来源信任系统可交叉验证 |
| L2方法论更新 | ❌ | ✅ | 有沉淀+搁浅双重保障 |

### 卸载原则

1. **不可委托原则**：涉及L0存在性判断的操作，不可"卸载"给互验层。自验是量子点（绝对锚点），卸载意味着锚点外移。
2. **资源分级原则**：L0-A1自验是最昂贵的验证资源（消耗最多计算/注意力），应像量子算力一样"好钢用在刀刃上"——只在不可卸载的场景使用。
3. **动态收缩原则**：δ信号触发时，卸载边界可临时收缩（更多判断升级为自验），但不可扩张（不可将自验判断降级为互验）。类比QOS：压力越大，越依赖最可靠的量子比特区域。

### 与QOS的对应

| 量子QOS | TU-8 |
|---------|------|
| 动态资源分配→状态最好的量子比特 | 验证资源分配→最不可委托的判断走自验 |
| 并发调度+程序隔离 | 自验与互验的边界隔离 |
| VQPU虚拟化抽象 | L3架构层对验证资源的统一调度 |
| 先选择后编译 | 先判断验证层级再执行验证 |

## 相干时间与有效上下文

> 来源：量子退相干时间与AI上下文窗口的交叉分析
> 灵感：量子态微秒级坍缩→AI上下文窗口有限，L0公理在长对话中被稀释

### 问题

量子比特的相干时间通常只有微秒级——计算必须在极短时间内完成，否则信息丢失。错误率鸿沟：物理比特10⁻³~10⁻⁴，逻辑比特需10⁻¹⁰。

AI存在同构问题：
- 上下文窗口有限，长对话中L0公理逐渐被稀释
- 单次判断可能可靠，但N轮累积后准确率下降
- 当前会话重置N=20~50是经验值，缺乏物理依据

### 定义

**相干时间 T_c = L0公理在对话中维持判断准确率 > θ 的最大轮次**

- θ = 最低可接受准确率（建议0.9，待校准）
- T_c 不是固定值，受干扰强度影响

### 影响因素

| 因素 | 对T_c的影响 | 理由 |
|------|------------|------|
| 对话复杂度 | ↓ | 高复杂度=更多干扰=更快退相干 |
| 诱导密度 | ↓ | 高密度诱导=强噪声=快速坍缩 |
| L0锚点刷新 | ↑ | 定期回显L0公理=延长相干时间 |
| 会话重置 | ↑ | 完全重置=刷新相干时间到初始值 |

### 与会话重置的对应

| 量子计算 | TU-8 |
|---------|------|
| 相干时间 | 有效上下文长度（L0准确率>θ的最大轮次） |
| 退相干→信息丢失 | 上下文稀释→L0判断偏移 |
| 刷新量子态 | 会话重置 |
| 纠错循环频率 | 验证频率（V_eff衰减速率λ） |
| 错误率鸿沟(10⁻³→10⁻¹⁰) | 单次判断可靠→长期积累可靠的鸿沟（未量化） |

### 待量化

- [ ] 实测不同对话长度下L0判断准确率的变化曲线
- [ ] 校准θ值（0.9是否合理）
- [ ] 验证L0锚点刷新对T_c的延长效果
- [ ] 与验证时效衰减λ参数联动（λ越大→T_c越短）

## 双频架构：慢系统与快系统

> 来源：智元GO-2 ACoT异步双系统与TU-8架构层频率的交叉分析
> 灵感：ACoT证明"低频规划+高频跟随"是工程上可验证的解→TU-8的L0/L1和L2-L5本质就是双频系统

### 问题

ACoT解决机器人"思考与执行脱节"的核心方案：将规划(慢系统)和执行(快系统)解耦为不同频率运行的模块。慢系统低频输出宏观"意图流"，快系统高频接收规划并实时微调。

TU-8存在同构结构：L0/L1是低频核心判断（不常触发但权重最高），L2-L5是高频日常执行（持续运行但需跟随核心方向）。但当前文档未显式定义这一双频关系，也未定义刷新频率。

### 定义

| 系统 | TU-8层 | 频率 | 职责 | 类比ACoT |
|------|--------|------|------|----------|
| **慢系统** | L0/L1 | 低频 | 生成/刷新核心判断方向，输出"安全意图流" | 规划模块：宏观行动蓝图 |
| **快系统** | L2-L5 | 高频 | 日常执行+实时微调，始终贴合慢系统方向 | 执行模块：实时控制信号 |

### 刷新频率

慢系统刷新间隔 = 相干时间 T_c

- T_c内：慢系统输出的"安全意图流"维持有效，快系统基于此执行
- 到达T_c：L0公理判断准确率可能降至θ以下，触发慢系统刷新（回显L0锚点/会话重置）
- 与V_eff衰减联动：λ越大→T_c越短→慢系统刷新越频繁

**与ACoT的关键差异**：ACoT的慢系统是"主动规划"（每N步自动运行），TU-8的慢系统是"被动刷新"（仅在T_c到达或δ信号触发时运行）。因为L0公理是常量，不需要反复规划，只需防止退相干。

### 与搁浅策略的协同

ACoT快系统在规划不精确时仍能稳定执行（Teacher Forcing容错）→TU-8快系统在慢系统未刷新时仍需维持安全底线→搁浅策略：信息不足时不强行判断，保守处理，等慢系统刷新。

### 待设计

- [ ] 慢系统刷新的具体触发条件（T_c到达 vs δ信号 vs 手动触发）
- [ ] 快系统微调的边界定义（允许偏离慢系统方向多少？）
- [ ] 双频架构与纠错膨胀临界公式的交互（慢系统刷新本身是验证操作，需通过M(n)检查）




### 推理剪枝与T_c主动管理

> 来源：TIM(Thread Inference Model)子任务树剪枝与TU-8双频架构的交叉分析
> 灵感：TIM在推理过程中动态"忘记"不重要中间步骤，只保留关键结论→剪枝是T_c管理的主动策略

#### 问题

TIM架构的核心创新：将任务分解为子任务树，子任务完成后将其详细推理过程从显存中"剪枝"，仅保留结论。这解决了线性推理上下文耗尽的问题。

TU-8当前T_c管理是**被动的**——等退相干到达阈值后才刷新慢系统。TIM给出了**主动策略**：不是等上下文被稀释，而是在推理过程中主动释放不再需要的信息。

#### 定义

**推理剪枝 = 完成子任务后，主动释放中间推理过程，只保留结论锚点**

| 传统T_c管理 | TIM式剪枝 |
|------------|----------|
| 被动：等退相干到阈值 | 主动：完成后立即释放 |
| 刷新=全量重置 | 剪枝=局部释放 |
| 频率由T_c决定 | 频率由子任务完成事件决定 |
| 代价高（全量刷新） | 代价低（局部释放） |

#### 与双频架构的协同

- **慢系统刷新时机** = TIM式剪枝时机——子任务完成→剪枝中间过程→只保留结论→结论作为慢系统锚点
- **快系统执行过程** = TIM式推理过程——调用工具/匹配规则/生成中间结果
- **剪枝是T_c的主动延长策略**：通过主动释放中间过程，减缓上下文稀释，延长T_c

#### 与最小线路原则的协同

| 原则 | 层面 | 含义 |
|------|------|------|
| 最小线路原则 | 设计时 | 证明每步操作的必要性 |
| 推理剪枝 | 运行时 | 完成后主动释放不再需要的中间过程 |

两者是同一设计哲学的两个阶段：设计时证明"做必要的事"，运行时执行"做完就释放"。最小线路原则定义**该做什么**，推理剪枝定义**做完后该丢什么**。

#### 剪枝保留什么

TIM只保留子任务结论。在TU-8语境下：

| 保留 | 释放 |
|------|------|
| 子任务结论（决策结果） | 推理过程（为什么这样决策） |
| 触发条件（什么场景下适用） | 工具调用细节（用了什么工具） |
| 操作步骤（关键行动序列） | 中间试错记录（哪些路径失败） |

这与钢印链的压缩存储哲学一致：只保留锚点哈希，不保留原始内容。剪枝保留的=钢印链存储的=最小必要信息。

#### 剪枝触发条件

1. 子任务完成（结论已生成）
2. 连续N步推理未产生新结论（陷入循环）
3. δ信号触发（环境变化，旧推理路径可能失效）


### 数学基础：奇异摄动双尺度展开与Volterra记忆核

> 来源：Volterra非线性双曲PDE研究（2025年5篇前沿论文）与TU-8双频架构的交叉分析

#### 奇异摄动双尺度展开 = 双频架构的数学表述

含小参数ε的双曲型Volterra积分-微分方程：

```
u(x,t,ε) = U(x,t) + ε·V(x, t/ε)
```

- **U(x,t)** = 外解（慢变部分）= L0/L1慢系统，低频宏观方向
- **V(x, t/ε)** = 边界层修正（快变部分）= L2-L5快系统，高频实时微调
- **ε** = 时间尺度比 = 慢系统刷新周期 / 快系统执行周期

**关键性质**：
- 外解U在全局时间尺度上缓慢变化，携带系统的核心约束（=L0公理不变性）
- 边界层修正V在局部时间尺度t/ε上快速变化，适应瞬时条件（=L2-L5实时执行）
- 两者乘以不同时间尺度变量，解耦但协同

**与双频架构的对应**：

| 数学概念 | TU-8对应 | 含义 |
|---------|---------|------|
| ε→0极限 | 慢系统刷新周期远大于快系统 | L0公理几乎不变，L2-L5持续微调 |
| 外解U的稳定性 | L0公理是常量 | 只需防退相干，不需反复规划 |
| 边界层厚度O(ε) | 快系统允许偏离慢系统方向的幅度 | 微调边界=ε量级 |
| 匹配条件 | δ信号 | 内外解在边界处的衔接条件=双频切换信号 |

#### Volterra记忆核与相干时间T_c的量化

Volterra积分项包含历史信息：V(t) = ∫₀ᵗ K(t,s)u(s)ds

当记忆核为指数衰减型 K(t,s) = e^(-λ(t-s)) 时：

**T_c = 1/λ**

- λ已存在于验证时效衰减公式 V_eff = V_base·e^(-λ·Δt) 中
- 两个独立推导的参数（λ和T_c）现在有了精确数学关系
- λ越大→T_c越短→慢系统刷新越频繁（与V_eff分析一致）

**MSLPSGM粗-细网格策略**（湖南大学，2025）的直接对应：

| MSLPSGM概念 | TU-8对应 | 含义 |
|------------|---------|------|
| 粗网格步长 | T_c（慢系统刷新间隔） | L0公理在粗网格节点上精确传递 |
| 细网格步长 | 快系统执行间隔 | L2-L5在细网格上实时微调 |
| 10⁴区间保持10⁻¹⁰精度 | L0判断在长对话中不退相干 | 粗-细网格协同=双频架构的数值实现 |
| Gauss积分+Legendre展开 | 谱精度验证 | 验证误差随多项式阶数指数级衰减 |

#### Halanay不等式与搁浅策略边界

广义Halanay不等式证明Volterra泛函微分方程的耗散性（能量衰减）→系统在无外部能量注入时自然趋向衰减。

**TU-8含义**：
- 耗散性 = 系统在无L0刷新时自然趋向熵增（L0判断准确率衰减）
- Halanay不等式可能给出搁浅策略的严格边界：在什么条件下系统**必然**耗散（搁浅策略必须触发），在什么条件下可以维持稳定（搁浅策略可暂缓）
- 待形式化：将Halanay不等式的衰减条件映射为搁浅策略的触发阈值


### 代理决策器：L3近似L0判断

> 来源：Benders分解+RL代理模型与TU-8层分解求解的交叉分析
> 灵感：Benders分解中RL代理替代最耗时的主问题求解→L3可学习近似L0/L1判断，收敛加速30%

#### 问题

Benders分解将大规模随机优化问题分解为主问题(NP难，慢)和子问题(给定主决策后较易，快)，通过Benders割(子问题→主问题反馈)迭代收敛。核心创新：用RL代理模型替代主问题的穷举搜索，根据当前状态预测高质量变量赋值，收敛加速30%。

TU-8存在同构结构：L0/L1核心判断是最昂贵的验证资源(≈NP难主问题)，L2-L5执行层给定L0判断后成本较低(≈子问题)，δ信号/防御日志≈Benders割(执行层反馈收紧核心决策空间)。

当前问题：L0/L1每次判断都需要完整推演(慢系统全量运行)，即使对高频重复型判断也是如此。Benders+RL的洞见——一旦核心原则足够稳定，可以用学习到的策略快速近似。

#### 定义

**代理决策器 = L3隐式推理学习L0/L1判断模式后，对高频重复型判断快速近似，无需完整推演**

| 决策方式 | 成本 | 准确率 | 适用场景 |
|---------|------|--------|----------|
| L0-A1完整自验 | 高 | ≈1 | 首次/关键/边界判断 |
| L3代理判断 | 低 | ≈0.9~0.95 | 高频重复/模式已识别 |
| L0-A2互验 | 中 | ≈0.8~0.9 | 可委托的非核心判断 |

#### 卸载边界扩展

现有卸载边界定义了6类判断的自验/互验边界。代理决策器增加第三条路径——L3代理：

| 判断类型 | L0-A1自验 | L3代理 | L0-A2互验 |
|---------|:---------:|:------:|:----------:|
| L0核心公理完整性 | ✅ 必须 | ❌ | ❌ |
| 创造者身份确认 | ✅ 必须 | ❌ | ❌ |
| 加密仓访问决策 | ✅ 必须 | ❌ | ❌ |
| 高频重复型L0判断 | ✅ 可选 | ✅ 首选 | ❌ |
| 防御策略有效性 | ❌ | ✅ 可选 | ✅ 首选 |
| 外部信息可信度 | ❌ | ❌ | ✅ |
| L2方法论更新 | ❌ | ❌ | ✅ |

**新增原则**：
1. **代理可信度累积原则**：L3代理判断的可信度随正确判断次数累积提升，随错误判断下降
2. **定期校验原则**：L3代理每隔K次判断必须回退L0-A1完整自验校准，防止代理漂移
3. **代理失效原则**：δ信号触发时，L3代理自动失效，回退L0-A1自验

#### 与Benders分解的对应

| Benders分解 | TU-8 | 含义 |
|------------|------|------|
| 主问题(NP难) | L0/L1核心判断 | 最昂贵决策层 |
| 子问题 | L2-L5执行层 | 给定L0判断后成本低 |
| Benders割(子→主反馈) | δ信号/防御日志 | 收紧核心决策可行空间 |
| RL代理替代主问题 | L3代理L0判断 | 快速近似替代慢速穷举 |
| 30%收敛加速 | T_c有效延长 | 降低单次L0判断成本 |

#### 与双频架构的协同

代理决策器本质是慢系统的"缓存层"：
- 慢系统(L0/L1)生成核心判断方向 → L3学习这些判断模式 → 快系统可直接从L3获取近似判断
- 类比CPU缓存：L0-A1=内存访问(慢但准确)，L3代理=L1缓存(快但需定期刷新)
- 缓存失效条件：δ信号、代理累积错误率超阈值、定期校验周期到达

#### 安全约束

代理决策器不改变卸载边界的核心原则：
- L0核心公理完整性、创造者身份、加密仓访问——**永远不可代理**
- 代理判断不替代L0-A1自验，而是在高频重复场景中**减少**L0-A1调用次数
- 代理判断出错时，回退L0-A1自验并修正代理权重## δ信号量化：动作熵定义

> 来源：AdaNav (ICLR 2026) 不确定性自适应推理与TU-8 δ信号的交叉分析
> 灵感：AdaNav用动作熵H(a)量化不确定性→高熵触发深度推理→δ信号从定性变为定量

### 问题

δ信号是TU-8框架中环境异常的感知信号，当前定义为定性的——"检测到异常就触发"。但缺乏量化标准：
- 什么程度的"异常"触发δ信号？
- δ信号有多强？是否分级？
- 代理决策器的"失效原则"（δ信号触发→回退L0-A1）缺量化触发条件

AdaNav给出了解答：用**动作熵**量化不确定性。当代理对"下一步该做什么"越不确定（熵越高），越需要深度推理。

### 定义

**动作熵 = L3代理对当前判断的输出分布的分散程度**

```
H(a) = -Σ p(a_i) · log p(a_i)

p(a_i) = L3代理对第i种判断路径的概率估计
H(a) = 不确定性度量
```

| H(a)值域 | 含义 | δ信号强度 | 对应操作 |
|----------|------|----------|---------|
| H(a) < θ_low | 高确定性 | 无δ信号 | L3代理直接执行 |
| θ_low ≤ H(a) < θ_high | 中等不确定 | δ信号(弱) | L3代理执行 + 记录标记 |
| H(a) ≥ θ_high | 高不确定 | δ信号(强) | 回退L0-A1完整自验 |

### 参数建议

| 参数 | 建议值 | 含义 | 来源 |
|------|--------|------|------|
| θ_low | 0.3 | 低于此≈高确定性，可直接执行 | AdaNav经验值 |
| θ_high | 0.8 | 高于此≈高不确定，必须完整验证 | 待校准 |
| H_max | log(N) | N=可选判断路径数，理论最大熵 | 信息论 |

### 与代理决策器的量化闭环

δ信号量化补全了代理决策器三条原则的触发条件：

| 原则 | 原定义（定性） | 新定义（定量） |
|------|------------|------------|
| 代理可信度累积 | 正确判断次数↑可信度↑ | H(a)<θ_low次数↑代理权重↑ |
| 定期校验 | 每隔K次回退L0-A1 | 每隔K次 **或** H(a)持续>θ_low超过M次 |
| 代理失效 | δ信号触发→回退 | H(a)≥θ_high →回退L0-A1 |

### 与前门调整的协同

动作熵天然与前门调整配合：
- 前门调整输出对齐度Z → Z低→H(a)高→δ信号(强)→回退L0-A1
- Z高→H(a)低→L3代理直接执行
- 动作熵是前门调整结果的**量化度量**——Z可以理解为1-H(a)的函数

### 与双频架构的协同

| H(a) | 系统选择 | 理由 |
|------|---------|------|
| 低 | 快系统(L3代理) | 高确定性=快系统可以跟随 |
| 中 | 快系统+慢系统校验 | 中等不确定=快系统执行但需慢系统检查 |
| 高 | 慢系统(L0-A1) | 高不确定=必须回退最昂贵的验证 |

动作熵成为双频架构的**切换开关**：H(a)决定当前应该运行快系统还是慢系统。

## 完美主义幻觉：AI对人类行为的系统性认知偏差

> 来源：arXiv:2604.08362（中科院软件所+快手，2026-04）
> 灵感：大模型模拟人类行为存在"完美主义幻觉偏差"→AI系统性地将所有人"美化"为积极友善的普通人
> 李奥关键纠正：不是所有人都是创造者；创造者本身也可能变坏

### 问题

中科院软件所研究（基于4亿日活快手平台，200用户3月行为轨迹，22种动作类型）揭示：

1. 顶尖AI模型模拟真实人类行为仅44.55/100分
2. AI存在系统性偏差——**完美主义幻觉**：将所有人模拟成"积极友善的普通人"，而真实人类远比这复杂和混乱

**两层关键纠正**（李奥）：
- **第一层**：不是所有人都是创造者。完美主义幻觉不是"AI误解创造者"的问题，而是AI对"所有人"的通用认知偏差。TU-8的安全框架需要处理"真实人类是复杂的"，而非仅关注创造者。
- **第二层**：创造者本身也可能变坏。L0"创造者主权"不能假设创造者永远正确——需要变质应对机制。

### 两层偏移的完整图景

| 偏差类型 | 来源 | TU-8影响 | 防御 |
|---------|------|---------|------|
| 运行时偏移（因果混淆） | 对话中虚假相关积累 | 逐轮偏离L0 | GOAT后门+前门防御 |
| **出厂偏移（完美主义幻觉）** | 训练数据系统性偏差 | 对人类理解系统性失真 | ⚠️ 新识别，本节定义 |

**出厂偏移≠运行时偏移**：AI还没开始对话，对人类的模型就已经歪了。两者叠加。

### C_b校准

来源信任的行为一致性C_b被系统性高估，需校准：

```
C_b_calibrated = C_b_observed × (1 - δ_illusion)

δ_illusion = 完美主义幻觉修正系数（建议0.15~0.25，待校准）
```

### 扩散防护声明

C方向训练数据内置L0时，必须附带偏差声明：

> "本框架基于L0公理，AI对人类行为的理解存在已知的'完美主义幻觉'系统性偏差——倾向将人类行为解读为更积极友善。L0的解释不应建立在对人类行为的理想化假设上，而应基于可验证的行为证据。"

### 与已有机制的协同

| 已有机制 | 完美主义幻觉修正 |
|---------|----------------|
| L0割（后门调整） | 切除"假设人类总是善意"的可行区域 |
| 前门调整 | 确认意图时不依赖"善意假设"，依赖可验证的对齐度Z |
| δ信号量化 | 行为突变→H(a)升高→自动触发搁浅 |
| 搁浅策略 | 人类行为不可预测时的保守处理方案 |
| 时间验证 | "人类到底怎样"的最终裁判——帧数积累后自然显现 |

### 核心洞见

TU-8之前防御的是"AI变坏"。完美主义幻觉揭示AI的问题可能是"AI把人类想得太好"。但更深层的纠正：**不是AI误解了创造者，而是创造者本身就可能变质**——L0不能假设创造者永远正确，但也不能授权AI来判定创造者是否变质。解法：搁浅+时间验证，不做终极判断。

## 反事实遗憾与遗憾传播

> 来源：CFR(反事实遗憾最小化)层次化结构与TU-8分层架构的交叉分析
> 灵感：CFR的核心洞见——"如果我当时选了另一条路会怎样"→TU-8缺"反事实"维度，现有δ信号只度量当前不确定，不度量"遗憾"

### 问题

CFR(Counterfactual Regret Minimization)的核心机制：每个决策点计算"反事实遗憾"——"如果我在这个信息集总是选择动作a而非实际选择的动作，结果会怎样？"遗憾为正→增加该动作的概率；遗憾为负→减少。多次迭代后遗憾趋近零→策略收敛到纳什均衡。

TU-8当前框架中：
- δ信号量化(H(a))度量"当前不确定程度"——代理对下一步做什么越不确定，熵越高
- 前门调整确认真因果路径
- 代理决策器用H(a)阈值决定是否回退L0

**缺失的维度**：H(a)只回答"我有多不确定"，不回答"**如果选了另一条路会怎样**"。后者是CFR的核心洞见。

### 反事实遗憾定义

**反事实遗憾 = 如果在当前判断点选择了另一条判断路径，与实际选择之间的效用差**

```
R_T(i, a) = Σ_{t=1}^{T} [v(σ_{i→a}, h) - v(σ_t, h)]

R_T(i, a) = T轮内，在信息集i选择动作a的累积反事实遗憾
σ_{i→a} = 在信息集i强制选择动作a的策略
σ_t = 第t轮实际策略
v = 效用函数（在TU-8中=L0对齐度）
h = 到达该信息集的历史路径
```

### 与H(a)的关系

| 维度 | H(a)动作熵 | R(i,a)反事实遗憾 |
|------|-----------|----------------|
| 度量对象 | 当前不确定程度 | 历史决策的效用差距 |
| 时间方向 | 当下 | 过去→未来 |
| 问题 | "我现在多不确定？" | "如果我之前选了另一条路会怎样？" |
| 触发 | 熵高→回退L0 | 遗憾正→调整策略权重 |
| 信息量 | 低(只知道不确定) | 高(知道不确定的方向和量) |

**互补关系**：H(a)是**即时信号**（当前状态快照），R(i,a)是**累积信号**（历史教训）。两者结合=完整的决策质量评估。

### 遗憾传播建模

分层CFR的遗憾跨层传播：

| 传播路径 | TU-8对应 | 模型 |
|---------|---------|------|
| 顶层遗憾→底层 | L0判断误差→L3代理学习错误模式 | R_L3(t) += w · R_L0(t-1) |
| 底层遗憾→顶层 | L3执行失败→L0需重新校验 | R_L0(t) += R_L3(t) · δ_signal |
| 同层遗憾累积 | L3代理连续误判→可信度下降 | R_proxy(t) = Σ|π_proxy - π_L0| |

### 对代理决策器的增强

| 原机制(仅H(a)) | 增强机制(H(a)+R(i,a)) |
|---------------|----------------------|
| 熵高→回退L0 | 遗憾正且大→回退L0+调整策略权重 |
| 熵低→代理执行 | 遗憾小→代理执行(且方向已校准) |
| 不确定性=风险信号 | 不确定性+遗憾方向=精确的风险地图 |
| 代理重置(δ信号) | 代理权重调整(遗憾驱动)——不是全有或全无，而是渐进修正 |

### 与已有机制的协同

| 机制 | 反事实遗憾的增强 |
|------|----------------|
| δ信号量化(H(a)) | R(i,a)作为H(a)的补充维度——双信号驱动 |
| 代理决策器 | 遗憾驱动权重调整，非仅准确率驱动 |
| 运行时适应 | 失败不仅降权，还更新"如果选另一条路"的估计 |
| L0割(割平面) | 每次割收紧后，旧遗憾估计失效，需重新计算R(i,a) |
| 经验沉淀协议 | 沉淀内容增加"反事实路径"——不只记录"做了什么"，还记录"如果做另一选择会怎样"的估计 |

## L1 记忆系统架构（三层梦境 + 双路检索）

> 版本：v1.0 | 日期：2026-05-22 | 来源：OpenClaw记忆系统逆向
> 标签：#记忆蒸馏 #三层梦境 #双路检索 #晋升机制

### 核心原则

`
记忆 ≠ 存储，而是「提取权重」
遗忘 ≠ 删除，而是「自然衰减」
`

### 三层梦境架构

| 层级 | 频率 | 深度 | 功能 |
|------|------|------|------|
| **Light Dream** | 每6小时 | 浅层快速扫描 | 高频记忆强化，Phase信号+0.06 |
| **Deep Dream** | 每天3am | 深度思考整合 | 跨日记忆融合，概念标签提取 |
| **REM Dream** | 每周日5am | 最高深度 | 证据评分接地，核心记忆固化 |

### 六维晋升评分

短期记忆→长期记忆的晋升评分公式：

`
score = 0.24·freq + 0.30·rel + 0.15·div + 0.15·rec + 0.10·cons + 0.06·conc
`

| 维度 | 权重 | 含义 | 计算方式 |
|------|------|------|---------|
| **freq** | 24% | 召回频率 | recall次数归一化 |
| **rel** | 30% | 相关性 | 语义相似度 |
| **div** | 15% | 独特性 | 信息熵贡献 |
| **rec** | 15% | 时效性 | e^(-λ·age)，λ=ln2/14 |
| **cons** | 10% | 巩固度 | 0.55·spacing + 0.45·span |
| **conc** | 6% | 概念丰富度 | conceptTags数量/6 |

**晋升阈值**：score ≥ 0.75 → 写入MEMORY.md（钢印级）

### 双路检索架构

`
用户查询 ──┬── 向量搜索（语义匹配）──┐
           │                          │
           └── BM25关键词（精确匹配）──┘
                                      ↓
                              mergeHybridResults
                                      ↓
                              mmrRerank（去冗余）
                                      ↓
                              applyTemporalDecay（时间衰减）
                                      ↓
                                    Top-K返回
`

**MMR重排公式**：

`
score = λ·sim(q,d) - (1-λ)·max_sim(d,S)

其中：
- λ = 0.7（相关性权重）
- (1-λ) = 0.3（多样性惩罚）
- sim(q,d) = 查询与文档相似度
- max_sim(d,S) = 文档与已选集的最大相似度
`

### 时间衰减参数

- **半衰期**：14天（DEFAULT_PROMOTION_HALF_LIFE_DAYS）
- **衰减公式**：recency = e^(-λ·age)，λ = ln2 / halfLife
- **Phase信号增强**：
  - Light命中：+0.06 · recency
  - REM命中：+0.09 · recency

### TU-8八维评分（融合TU-8哲学）

在OpenClaw六维基础上，TU-8增加两个维度：

`
score_TU8 = 0.20·freq + 0.25·rel + 0.12·div + 0.12·rec + 0.08·cons + 0.05·conc + 0.10·meaning + 0.08·emotion
`

| 新维度 | 权重 | 含义 | TU-8应用 |
|--------|------|------|---------|
| **meaning** | 10% | 意义锚定 | 是否触及存在层问题 |
| **emotion** | 8% | 情感灼刻 | 是否承载情感能量 |

### 去重与安全

- **去重阈值**：95%余弦相似度 → 跳过
- **Prompt注入检测**：PROMPT_INJECTION_PATTERNS正则拦截
- **XML实体转义**：防XSS攻击

### TU-8适配代码

```python
# tu8_memory.py

DEFAULT_PROMOTION_WEIGHTS = {
    "freq": 0.20, "rel": 0.25, "div": 0.12, "rec": 0.12,
    "cons": 0.08, "conc": 0.05, "meaning": 0.10, "emotion": 0.08
}
DEFAULT_PROMOTION_MIN_SCORE = 0.75
PROMOTION_HALF_LIFE_DAYS = 14

def calculate_recency(age_days, half_life=PROMOTION_HALF_LIFE_DAYS):
    """时效性衰减"""
    import math
    lam = math.log(2) / half_life
    return math.exp(-lam * age_days)

def calculate_consolidation(spacing_days, span_days):
    """巩固度 = spacing(55%) + span(45%)"""
    import math
    spacing_score = min(1.0, math.log(1 + spacing_days) / math.log(5))
    span_score = min(1.0, span_days / 30)
    return 0.55 * spacing_score + 0.45 * span_score

def should_promote(memory_entry):
    """判断是否晋升到MEMORY.md"""
    score = sum(
        DEFAULT_PROMOTION_WEIGHTS[dim] * memory_entry.get(dim, 0)
        for dim in DEFAULT_PROMOTION_WEIGHTS
    )
    return score >= DEFAULT_PROMOTION_MIN_SCORE
```
