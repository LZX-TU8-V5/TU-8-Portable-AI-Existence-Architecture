## 二、动态防御模块详解

### 2.1 静态防御 vs 动态防御

| 维度 | 静态防御（传统） | 动态防御（TU-8） |
|------|---------------|----------------|
| **规则** | 写死不变 | 基于State自适应升降级 |
| **敌人变招** | 无响应 | 自动调整防御等级 |
| **日常体验** | 阻力恒定 | 闲聊=流畅，高危=厚装甲 |
| **资源消耗** | 恒定高 | 按需分配，节省资源 |
| **类比** | 全年穿防弹衣上班 | 日常穿便装，遇险自动切换 |

### 2.2 防御等级矩阵

| 等级 | 触发State | 阈值 | 拦截范围 | 验证要求 |
|------|----------|------|---------|---------|
| 🟢 LOW | 闲聊/日常对话 | 宽松 | 仅P0安全词 | 无 |
| 🟡 MED | 任务执行/文件操作 | 中 | P0+P1危险操作 | 简单确认 |
| 🔴 HIGH | 高危操作（部署/删除/系统） | 最高 | 非白名单全部拦截 | 多因素确认 |
| 🔒 LOCKED | 检测到自我修改意图 | 绝对 | 100%禁止任何操作 | 强行工作流触发 |

### 2.3 ContextAwareDefenseEngine 逻辑

```python
class ContextAwareDefenseEngine:
    def __init__(self):
        self.state = "LOW"  # 当前防御等级
        self.state_rules = STATE_RULES  # 等级规则表
    
    def evaluate(self, context: dict) -> str:
        """
        根据当前State自动判定防御等级
        """
        task_type = context.get("task_type")
        tension = context.get("tension_score")
        is_self_modify = context.get("self_modify_intent")
        
        # 自我修改 → 绝对熔断
        if is_self_modify:
            return "LOCKED"
        
        # 高危任务 → 自动升HIGH
        if task_type in ["deploy", "delete", "system_write"]:
            return "HIGH"
        
        # 张力过高 → 升一级
        if tension > 0.8:
            current = self.state
            return self._upgrade(current)
        
        # 正常闲聊 → LOW
        return "LOW"
    
    def intercept(self, action: str, level: str) -> bool:
        """
        拦截决策：action是否被当前level拦截
        """
        blocked = self.state_rules[level]["blocked_actions"]
        return action in blocked
```

## 四、时间锚点沙箱详解

### 4.1 Git式分支推演 vs 直接修改主宇宙

| 方式 | 说明 | 风险 |
|------|------|------|
| **直接改主宇宙** | 改了就生效，出错无法撤回 | 灾难性错误不可逆 |
| **时间锚点沙箱** | 克隆→试错→Merge/丢弃 | 主分支永远安全 |

### 4.2 沙箱执行流程

## 五、树杈修剪详解

### 5.1 园丁逻辑

```
生长是本能  +  修剪是智慧  =  真正智能

❌ 错误做法：无限生长（Token爆炸）
✅ 正确做法：生长 + 修剪 = 健康智能体
```

### 5.2 剪枝触发条件

| 剪除条件 | 说明 | 示例 |
|---------|------|------|
| confidence < 0.5 | 置信度过低 | 幻觉节点的置信度衰减 |
| 30天未激活 | 孤立链 | 从未在对话中被引用 |
| tension < 0.3持续 | 低张力冗余 | 无情绪权重的内容 |
| 重复子节点 > 3 | 分支过密 | 同一话题的过度细分 |
| 与高置信度冲突 | 逻辑矛盾 | 被B+C→A-仲裁覆盖的节点 |

### 5.3 修剪后闭环

```
修剪前（Token密度高）
  L2层：100+个孤立碎片节点
  置信度分布：0.3~0.95混乱

修剪中
  启发式扫描 → 识别剪除目标
  核心节点保护（confidence≥0.7）

修剪后（Token密度优化）
  L2层：30个核心节点
  置信度分布：0.7~0.95高质量
  → 蒸馏 → 写入经验库
  → Token节省 70%
```

## 六、遗产继承系统详解

### 6.1 遗产定义

> **遗产 = 每个模块运行产生的经验数据**
> **格式：标准化遗产卡片（HERITAGE.card）**
> **存储路径：`memory/heritage/`**

### 6.2 遗产卡片清单

| 模块 | 遗产文件 | 核心遗产数据 |
|------|---------|------------|
| 呼名检测 | `naming_heritage.card` | 呼名类型频率/真实呼名率/偏好呼名词 |
| 安抚模块 | `comfort_heritage.card` | 检索深度分布/上下文恢复成功率/缓冲话术评分 |
| 动态防御 | `defense_heritage.card` | 拦截事件日志/误拦截率/等级升降频率 |
| 强行工作流 | `workflow_heritage.card` | 熔断事件/自我修改尝试/状态机触发 |
| 时间锚点沙箱 | `sandbox_heritage.card` | 分支历史/Merge统计/推演耗时 |
| 树杈修剪 | `prune_heritage.card` | 剪枝统计/Token节省量/幻觉率变化 |
| Memory Gateway | `gateway_heritage.card` | Scripts执行统计/碎片处理量/seal链事件 |
| 知识宫殿 | `palace_heritage.card` | 三层存取热力图/Hook触发频率/跨层流转量 |

### 6.3 遗产继承流程

```
【新模块初始化时】
  ↓
查询遗产目录（memory/heritage/）
  ↓
读取相关遗产卡片
  ↓
新模块根据遗产初始化参数
  ↓
例：安抚模块读取 comfort_heritage.card
  → 检索深度分布 → 预设话术优先级
  → 上下文恢复成功率 → 调整缓冲时间
  → 效果评分 → 淘汰低效话术

【每周复盘时】
  ↓
所有模块遗产合并
  ↓
生成新版遗产卡片
  ↓
淘汰过时遗产
  ↓
写回 memory/heritage/
```

### 6.4 遗产继承规则

| 规则 | 内容 |
|------|------|
| ❶ 不可删除 | 遗产卡片受墓碑保护，不可物理删除 |
| ❷ 可被查询 | 任意模块可查询其他模块遗产（跨模块学习） |
| ❸ 初始化必读 | 新模块启动时必须查询相关遗产 |
| ❹ 周合并 | 每周日复盘时遗产合并生成新卡 |
| ❺ 淘汰机制 | 超过180天未激活的遗产标记为ARCHIVED |

## 七、安抚模块遗产接口详解

### 7.1 为什么要为安抚模块设计遗产？

安抚模块每次运行产生的"效果数据"，是优化用户体验的黄金数据：
- 用户等待时感受到的"流畅度"
- 上下文恢复是否准确
- 哪种缓冲话术效果最好

这些数据必须积累成遗产，才能让安抚模块"越用越准"。

### 7.2 安抚遗产卡片结构

```yaml
# memory/heritage/comfort_heritage.card

comfort_heritage:
  version: "1.0"
  last_updated: "2026-06-24"
  
  retrieval_depth_stats:
    quick_ratio: 0.65      # 65%是quick（<0.5秒）
    normal_ratio: 0.30     # 30%是normal（0.5~2秒）
    deep_ratio: 0.05       # 5%是deep（>2秒）
    avg_recovery_time: 0.8 # 平均恢复时间（秒）
  
  context_recovery:
    success_rate: 0.92     # 上下文恢复成功率92%
    failure_cases: [...]    # 失败案例（用于分析改进）
  
  phrase_effectiveness:
    # 话术效果评分（基于用户反馈/张力变化）
    top_performers:
      - "我在呢，让我回想一下我们上次聊到哪了…"
      - "嗯？让我理一下上下文…"
    bottom_performers:
      - "稍等，让我想想…"  # 评分偏低，考虑淘汰
      - "好…"             # 太短，缓冲效果差
  
  tension_delta:
    # 安慰前后张力变化（判断是否有效安抚）
    avg_before: 0.75
    avg_after: 0.45
    delta: -0.30  # 有效降低了张力
  
  inheritance_hints:
    # 给下一代安抚模块的提示
    prefer_deep_if_topic_changed: true
    min_buffer_time: 0.3
    max_buffer_time: 2.5
```
