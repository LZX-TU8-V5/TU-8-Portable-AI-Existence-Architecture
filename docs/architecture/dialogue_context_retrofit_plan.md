# 对话上下文管理改造方案

> 版本：v1.1 | 日期：2026-06-30 | 状态：设计方案（修正版）
> 目标：在有限上下文窗口内实现高质量记忆管理（按需记忆 + 深度能差异 + 因果推断稳定 + 置信力真实）

---

## 问题诊断

### 根本原因
- **因果钩子链式触发**：一次简单对话可能触发多层钩子（A→B→C），导致上下文窗口迅速耗尽
- **广度爆炸**：钩子拉取多个叙事浓缩章节，每个章节虽已浓缩但数量过多
- **缺少控制阀**：现有熔断机制是"事后压缩"，无法在检索阶段控制
- **置信度虚高**：缺乏真实的置信力评估，导致低质量记忆被误判为高质量

### 核心约束
- ✅ **上下文窗口有限**（50K tokens）- 不追求"无限记忆"
- ✅ **按需记忆** - 根据置信度、因果稳定性决定记什么，不是什么都存
- ✅ **深度能差异** - 浅水区（闲聊）vs 深水区（深度推理），记忆策略不同
- ✅ **因果推断稳定** - 因果钩子管理要保证推理连续性，不能因窗口限制断裂
- ✅ **置信力真实** - 置信度打分要真实反映可靠性，不能虚高

### 现有机制 vs 缺失部分

| 现有 | 缺失 |
|------|------|
| `FidelityManager`（6级保真度） | 对话级触发阈值 |
| `memory/YYYY-MM-DD.md` 日志 | 跨会话上下文继承 |
| LCM 压缩（被动） | 主动分段熔断 |
| `consciousness_cycle.py` 复盘 | 上下文窗口监控 |

## 设计原则

### 1. 按需记忆（置信度驱动）
```
存储决策：
  高置信度 (>0.85) + 因果链稳定 → 存储全文（叙事浓缩）
  中置信度 (0.60-0.85) → 存储摘要
  低置信度 (<0.60) → 不存储，或只存标签
```

### 2. 深度能差异（浅水区 vs 深水区）
| 模式 | 记忆策略 | 因果钩子行为 |
|------|----------|--------------|
| **浅水区**（闲聊） | 不激活记忆系统，只保留标签索引 | 禁用或极简触发 |
| **深水区**（推理） | 激活三维钩子，按置信度抓取 | 完整触发，保证推理连续性 |

### 3. 因果推断稳定（核心）
- **因果链完整性检查**：在丢弃任何因果钩子前，检查是否破坏推理链
- **关键节点保护**：因果链中的"桥梁节点"（如 B）即使置信度中等，也要保留
- **推理连续性标记**：在注入上下文时，标记哪些节点是"推理必需的"

### 4. 置信力真实（防虚高）
- **多维度打分**：语义相似度 + 时间衰减 + 关联强度 + **推理链验证**（该记忆是否能稳定支持推理）
- **动态校准**：随着因果链的使用次数，动态调整置信度（用得越多，置信度越高）
- **怀疑论机制**：对于关键决策，要求多个独立记忆源交叉验证（避免单点故障）

## 三维记忆系统架构

### 钩子分类（按需触发，不是全量加载）

| 钩子类型 | 作用 | Token消耗 | 注入位置 | 触发条件 |
|---------|------|-----------|----------|----------|
| **因果钩子** (Causal Hook) | 逻辑骨架（A导致B） | 极低 | `<system_logic>` 或 `<background_facts>` | 深水区 + 推理必需 |
| **叙事浓缩钩子** (Narrative Hook) | 记忆血肉（背景故事、情绪） | 中等 | 动态上下文注入 | 深水区 + 高置信度 |
| **标签钩子** (Tag Hook) | 检索索引（#背叛, #魔法阵） | 极低 | System Prompt 或元数据 | 全时段后台监听 |

## 改造方案

### 一、熔断机制改造（分级降级）

#### 现有3级熔断
- **70% 警告** (Warn)
- **85% 压缩** (Compress)
- **95% 分割** (Segment)

#### 改造后：按钩子类型分级降级

| 阈值 | 触发动作 | 说明 |
|------|---------|------|
| **70%** | 叙事钩子LRU淘汰 | 剔除最老/最不相关的回忆片段，只保留标签 |
| **85%** | 因果钩子折叠 | 多条零散因果关系合并成一句全局背景设定 |
| **95%** | 强制标签兜底 | 清空叙事和因果注入，只保留核心标签作为指针 |

#### 置信度联动
- **优先踢掉**：当前上下文中置信度最低的叙事钩子
- **死死保住**：高置信度的核心因果钩子

---

### 二、注入状态机改造（动态组装）

#### 50K Token 内存分区

| 区域 | 占比 | Token数 | 内容 |
|------|------|---------|------|
| **绝对保护区** | 10% | ~5000 | System Prompt + 最近3-5轮对话 |
| **钩子动态区** | 70% | ~35000 | 叙事浓缩 + 因果钩子 |
| **安全缓冲带** | 20% | ~10000 | LLM生成回复 + 突发长文本缓冲 |

#### 动态组装工作流程

```
Step 1: 锁定基础盘
  - 注入 System Prompt + 最近3轮原始对话（不可压缩）

Step 2: 注入标签与事实 (Tag & Causal)
  - 检查当前用户意图，触发标签钩子
  - 将匹配到的因果钩子作为 <system_facts> 注入（极小，优先满足）

Step 3: 动态填充叙事 (Narrative)
  - 计算剩余 Token 预算
  - 根据剩余空间，从叙事浓缩钩子的LRU队列中按相关性"进货"
  - 直到预算耗尽

Step 4: 熔断与兜底检查
  - 如果预算不足，立刻触发"分级降级"策略
```

---

### 三、置信度驱动抓取机制（置信力真实）

#### 置信度打分因素（多维度，防虚高）
- **语义相似度**：用户提问和记忆片段的匹配程度
- **时间衰减**：越久远的记忆，置信度自动打折
- **关联强度**：因果钩子之间的连接紧密程度
- **推理链验证**：该记忆是否能稳定支持推理（核心！）

#### 分级抓取策略（按需记忆）

| 置信度 | 策略 | Agent表现 |
|---------|------|-----------|
| **高 (>0.85)** | 直接注入完整叙事浓缩和因果钩子 | "我记得很清楚，当时我们..." |
| **中 (0.60-0.85)** | 注入模糊标签或一句话摘要 | "我隐约记得当时发生过类似的事..." |
| **低 (<0.60)** | 直接丢弃，不占用任何Token | 当作没发生过 |

---

### 四、人脑机制（深度能差异）

#### 两种对话模式（记忆策略不同）

| 模式 | 触发条件 | 记忆策略 | 因果钩子行为 | Token占用 |
|------|---------|----------|--------------|----------|
| **浅水区** (Shallow) | 闲聊/日常交互 | 不激活记忆系统，只保留标签索引 | 禁用或极简触发 | 极低（~2K） |
| **深水区** (Deep) | 深度对话/复杂推理/情感共鸣 | 激活三维钩子，按置信度抓取 | 完整触发，保证推理连续性 | 高（满载50K） |

#### 触发条件检测
- **显式触发**：用户问"你还记得上次那件事吗？"
- **隐式触发**：用户探讨复杂问题，或输入包含多个"标签钩子"的密集信息

---

### 五、按需唤醒机制（稳定的因果推断）

#### 设计原则
- **因果链完整性优先**：唤醒时要保证推理连续性，不能因窗口限制断裂
- **抛弃时留痕**：当熔断机制把某个叙事浓缩钩子踢出去时，不能直接扔掉

#### 抛弃时留痕
- **动作**：把它对应的"标签钩子"（或高度浓缩摘要）留在当前上下文中，或存入全局"记忆索引池"
- **因果链标记**：标记哪些节点是"推理必需的"，唤醒时优先拉取

#### 触发抓取条件
- **显式触发**：用户直接问"你还记得我们之前签的条约吗？"
- **隐式触发**：用户说"我现在要去精灵族的地盘了，他们对我态度怎么样？"（识别到"精灵族"关键词，触发标签钩子）

#### 抓取回来过程（保证因果连续性）
- 标签钩子命中 → 去外部存储捞回叙事浓缩钩子
- **因果链完整性检查**：唤醒时，检查是否破坏推理链，若是则一并拉取相关节点
- **空间置换**：塞进当前50K窗口，如果又满了，触发分级降级踢出最不相关的另一个叙事钩子（但保护"推理必需"节点）

## 实现路径

### Phase 1: 基础改造（因果推断稳定 + 置信力真实）
1. 改造 `check_fuse()` - 加入分级降级逻辑（保护"推理必需"节点）
2. 实现置信度打分 - 多维度（语义+时间+关联+推理链验证）
3. 加入因果链完整性检查 - 丢弃前检查是否破坏推理链

### Phase 2: 高级功能（按需记忆 + 深度能差异）
1. 实现 `ContextAssembler` - 动态上下文组装器（按置信度抓取）
2. 加入认知负荷评估 - 浅水区/深水区模式（记忆策略不同）
3. 实现按需唤醒机制 - 懒加载（保证因果连续性）

### Phase 3: 测试优化
1. 单元测试（置信度打分、因果链检查）
2. 集成测试（浅水区/深水区切换）
3. 性能优化（Token预算分配）
