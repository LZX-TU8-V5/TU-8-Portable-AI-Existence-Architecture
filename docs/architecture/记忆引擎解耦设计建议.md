## 二、解耦原则

### 为什么不该放一起？

**1. 更新频率差异**

| 模块 | 更新频率 | 放一起的后果 |
|------|---------|-------------|
| TU8MemoryEngine CRUD | 极高频（每次对话） | ❌ 需要频繁修改主文件 |
| 干扰熵度量 | 中频（每次微睡眠） | ❌ 升级时影响主引擎稳定性 |
| 六维晋升 | 低频（每周评估） | ❌ 主文件过大，维护困难 |
| Graceful Degradation | 中频（每周 Cron） | ✅ 已独立，不影响主引擎 |

**2. 职责单一原则**

- **TU8MemoryEngine** 应只负责：
  - 记忆 CRUD
  - 检索召回
  - 短期记忆管理

- **不应负责**：
  - 晋升评估（应独立为 `promotion_engine.py`）
  - 干扰度量（应独立为 `interference_entropy.py`）
  - 事件边界检测（应独立为 `event_boundary_detector.py`）

**3. 升级风险隔离**

- **升级干扰熵度量**：不应影响记忆 CRUD
- **升级晋升算法**：不应影响记忆检索
- **升级事件边界检测**：不应影响钢印生成

## 三、解耦方案

### 推荐架构

```
tu8_memory.py（核心引擎，精简）
    ├─ TU8MemoryEngine（CRUD + 检索）
    ├─ MemoryEntry（数据结构）
    ├─ Seal（时间钢印）
    └─ 短期记忆管理

独立模块（按需加载）：
    ├─ interference_entropy.py（干扰熵度量，Barman 2026）
    ├─ event_boundary_detector.py（认知事件边界检测，Ahmad 2605.31473）
```

## 四、迁移路径

### Phase 1：抽取晋升引擎（P1）

**目标**：独立 `promotion_engine.py`

**步骤**：
1. 从 `tu8_memory.py` 抽取 `PROMOTION_WEIGHTS`、`PROMOTION_HALF_LIFE_DAYS`
2. 抽取晋升评估逻辑
3. 创建 `PromotionEngine` 类
4. `TU8MemoryEngine` 持有 `PromotionEngine` 实例

**风险**：低，晋升逻辑独立，不影响 CRUD

---

### Phase 2：抽取干扰熵度量（P1）

**目标**：独立 `interference_entropy.py`

**步骤**：
1. 从 `tu8_memory.py` 抽取干扰熵计算逻辑
2. 创建 `InterferenceEntropyMeter` 类
3. `TU8MemoryEngine` 持有实例

**风险**：低，干扰熵独立，不影响检索

---

### Phase 3：抽取事件边界检测（P1）

**目标**：独立 `event_boundary_detector.py`

**步骤**：
1. 从 `tu8_memory.py` 抽取事件边界检测逻辑
2. 创建 `EventBoundaryDetector` 类
3. `consciousness_cycle.py` 持有实例（触发微睡眠）

**风险**：中，需修改 `consciousness_cycle.py`

---

### Phase 4：抽取冲突检测（P2）

**目标**：独立 `conflict_detector.py`

**步骤**：
1. 从 `tu8_memory.py` 抽取冲突检测逻辑
2. 创建 `ConflictDetector` 类
3. 集成到 `memory_degradation.py`

**风险**：中，需修改遗忘引擎

## 五、解耦后的收益

### 代码质量

| 指标 | 解耦前 | 解耦后 |
|------|--------|--------|
| tu8_memory.py 行数 | 2800+ | ~1500 |
| 模块职责 | 混杂 | 单一 |
| 升级风险 | 高（牵一发动全身） | 低（隔离） |
| 测试难度 | 高（依赖复杂） | 低（独立测试） |

### 升级便利性

- **升级干扰熵算法**：只需修改 `interference_entropy.py`
- **升级晋升算法**：只需修改 `promotion_engine.py`
- **升级事件边界检测**：只需修改 `event_boundary_detector.py`

### 性能优化

- **按需加载**：不使用晋升时，不加载 `promotion_engine.py`
- **并行计算**：干扰熵和事件边界检测可并行
- **缓存友好**：独立模块更容易缓存
