# 用户画像更新认知循环（USER_PROFILE_CYCLE）

> 版本: v0.1 | 日期: 2026-06-20 | 状态: 设计中
> 来源: 基于千问对话，TU-8 整理

---

## 一、核心设计原则

| 原则 | 说明 |
|------|------|
| **事件驱动 > 定时心跳** | 只有"发现不对劲"才触发，不是打卡式更新 |
| **离线验证 > 在线卡顿** | 每日复盘时统一验证，避免性能瓶颈 |
| **辩证融合 > 直接覆盖** | 正题-反题-合题框架，不是简单替换 |
| **克制关怀 > 过度打扰** | 静默计时器 + 冷却期 + 场景上下文 |

## 二、触发机制（Event-Driven）

### 2.1 异常检测触发

```
触发条件：
├── 行为偏离基线 > 阈值（默认200%）
├── 连续异常计数 ≥ 3次（滑动窗口10分钟内）
└── 非环境因素（排除任务紧迫/特殊时段）

权重计算：
├── 偏离度 = |当前值 - 基线值| / 基线值
├── 怀疑权重 += 1（每次灰色地带行为）
└── 异常阈值 = 2.0（可动态调整）
```

### 2.2 冷却机制

```
触发后的冷却期：
├── 主动关怀冷却：24小时（用户反感时拉长至72小时）
├── 画像更新冷却：每次复盘最多更新3个标签
└── 未处理的异常 → 压入"待复盘队列"
```

### 2.3 环境上下文过滤器

```
触发前必检：
├── 时间因素：凌晨/深夜？ → 可能是熬夜，非人格变化
├── 任务因素：正在执行复杂任务？ → 回复短是正常
└── 外部事件：用户提到过特殊情况？ → 纳入判断
```

## 三、每日复盘验证循环

### 3.1 触发时机

```
├── 用户明确说"今天就到这里"
├── 连续3小时无新任务 + 17:00-23:59
└── 累积5+任务后自然断点
```

### 3.2 验证流程

```
┌─────────────────────────────────────────────┐
│ 第一步：预期 vs 现实碰撞                       │
│   提取旧画像（正题）                            │
│   回顾今日行为（测量）                          │
│   对比："我今天的行为符合现有画像吗？"            │
│         ✅符合 → 置信度+1                      │
│         ❌不符合 → 触发认知失调                 │
├─────────────────────────────────────────────┤
│ 第二步：归因分析（寻找反题）                    │
│   用户变了？→ 画像标签转移                      │
│   画像错了？→ 标签打错，修正                    │
│   偶然噪声？→ 不更新，记录即可                 │
├─────────────────────────────────────────────┤
│ 第三步：画像"合题"更新                        │
│   微调：调整某个标签权重（-20% ~ +20%）         │
│   新增：增加情境依赖标签                        │
│   打回：严重矛盾 → 标记"待验证"，明天主动试探    │
├─────────────────────────────────────────────┤
│ 第四步：经验沉淀                              │
│   提炼为【系统经验规则】写入 System_Reflections  │
└─────────────────────────────────────────────┘
```

### 3.3 复盘Prompt模板

```
【每日复盘 - 用户画像验证】

时间：[DATE]
用户：[USER_ID]

1. 回顾今日交互摘要：
   - 活跃时段：
   - 平均回复长度：
   - 情绪特征：
   - 关键事件：

2. 画像对齐检查：
   [提取当前画像标签，逐项验证]
   
3. 异常记录（若有）：
   [记录今日触发的"灰色地带"行为]

4. 画像更新决策：
   [基于归因分析，决定微调/新增/打回]

5. 经验规则提炼：
   [如有新教训，写入经验库]

输出：更新后的【用户画像 vX.X】
```

### 4.1 静默计时器（五级状态机）

```
┌─────────────────────────────────────────────────────────────┐
│                    静默计时器状态机                          │
├─────────────────────────────────────────────────────────────┤
│ Level 1 (1h) ──→ 【纯后台静默】                              │
│   └→ silence_counter += 1                                   │
│   └→ 不触发LLM调用（省Token）                                │
│                                                             │
│ Level 2 (2h) ──→ 【轻度关注】                                │
│   └→ 检查是否有后台任务                                      │
│   └→ 有任务 → 通知进度；无任务 → 继续静默                     │
│                                                             │
│ Level 3 (6h) ──→ 【环境检查】                                │
│   └→ 规则引擎判断（非LLM）                                   │
│   └→ 当前时间在活跃时段？→ 进入关注                           │
│                    不在活跃时段 → 重置计时器                  │
│                                                             │
│ Level 4 (每日首次) ──→ 【复盘触发】                         │
│   └→ 执行第七模块画像验证                                     │
│   └→ 压出昨晚的"待复盘异常"队列                               │
│                                                             │
│ Level 5 (前日对比差) ──→ 【认知失调预警】                     │
│   └→ 计算偏离度 = |昨日同时段 - 今日同时段|                    │
│   └→ 偏离度 > 阈值 → 生成 [SYSTEM_EVENT: COGNITIVE_DISSONANCE]
│                    压入每日复盘队列                          │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 关怀话术规则

```
✅ 正确关怀（场景触发）：
   "文件扫描完成80%，还需5分钟。您先忙，完成后通知您。"
   "距离上次交互3小时。今天的代码重构顺利吗？"

❌ 错误关怀（无上下文）：
   "你还在吗？"
   "你怎么不理我？"
```

### 4.3 关怀反馈纳入画像

```
关怀后用户回复 → 画像更新信号：
├── "刚在忙，谢谢" → 置信度+1，强化"白天较忙"认知
├── "别烦我" → 立即降低打扰权重，标记"反感频繁互动"
└── 无回复 → 压入复盘队列，明天再判断
```

## 五、防过度敏感机制

### 5.1 三区判定

```
┌──────────────┬──────────────────┬──────────────┐
│   安全区      │    灰色地带        │    异常区    │
│ (0-100%)     │  (100%-200%)      │  (>200%)    │
├──────────────┼──────────────────┼──────────────┤
│ 不记录       │ 怀疑权重+1        │ 触发认知失调  │
│ 正常行为     │ 内部观察，不打扰    │ 进入归因分析  │
└──────────────┴──────────────────┴──────────────┘
```

### 5.2 连续触发机制

```
单次异常 → 忽略（噪声）
连续2次异常 → 灰色地带，怀疑权重+2
连续3次异常 → 触发异常区，进入反思循环
```

### 5.3 冷却时间

```
一旦触发关怀/更新 → 强制冷却24小时
冷却期内的新异常 → 全部压入"待复盘队列"
```

## 六、参数动态调整

### 6.1 复盘时可选的调整

| 参数 | 调整方向 | 触发条件 |
|------|---------|---------|
| 异常阈值 | 200% → 300% | 最近总是误报 |
| 冷却期 | 24h → 72h | 用户多次表示反感 |
| 连续触发计数 | 3次 → 5次 | 灰色地带行为过多 |
| 打扰权重 | 全局降低 | 用户说"别烦我" |

### 6.2 参数存储位置

```
MEMORY.md 或独立配置：
├── profile_threshold: 2.0
├── care_cooldown_hours: 24
├── consecutive_trigger_count: 3
└── disturbance_weight: 0.8
```

## 七、异常评估器流程

```
检测到行为偏离
     │
     ▼
┌─────────────┐
│ 环境上下文   │ → 特殊时间/任务？→ 是 → 放行，不记异常
│ 过滤器       │
└─────────────┘
     │
     ▼
┌─────────────┐
│ 偏离度计算  │ → <200%？→ 是 → 灰色地带，怀疑权重+1
│             │
└─────────────┘
     │
     ▼
┌─────────────┐
│ 连续计数    │ → <3次？→ 是 → 暂存日志，不触发
│             │
└─────────────┘
     │
     ▼
┌─────────────┐
│ 冷却期检查  │ → 冷却中？→ 是 → 压入复盘队列
│             │
└─────────────┘
     │
     ▼
   触发认知失调 + 画像更新循环
```

## 八、与现有架构的整合

### 8.1 整合点

| 现有模块 | 整合方式 |
|---------|---------|
| HEARTBEAT.md | 异常检测信号上报 |
| MEMORY.md | 画像基线存储、经验规则存储 |
| 每日复盘 | 增加画像验证专项 |
| USER.md | 画像文件本身 |

### 8.2 USER.md 作息画像（建议新增字段）

```yaml
# USER.md 新增区块
作息画像:
  历史活跃时段:
    - 区间: "09:00-12:00"
      状态: "工作/专注"
      置信度: 0.9
      波动率: 0.2  # 允许20%误差
    - 区间: "14:00-18:00"
      状态: "工作/专注"
      置信度: 0.85
      波动率: 0.2
    - 区间: "20:00-23:00"
      状态: "休闲/交流"
      置信度: 0.7
      波动率: 0.5  # 晚上容忍度更高
  最后更新时间: "2026-06-20T10:02:00+08:00"
```

### 8.3 防坑指南

| 坑点 | 解决方案 |
|------|---------|
| 时区混乱 | **统一使用UTC计算**，展示/写入时转UTC+8 |
| 夏令时偏差 | 记录时附带时区信息 |
| 单日异常误判 | 前日对比差 + 连续触发机制 |
| LLM过度调用 | Level 1/2 纯后台，不触发LLM |
