## 一、设计理念

### 1.1 核心哲学

**遗忘 ≠ 删除，而是降级**  
**记忆 ≠ 静态存储，而是动态演化**

当前系统已实现：
- ✅ **降级引擎**：不访问的记忆 → 自然降级（L0→L1→L2→L3→L4→L5）
- ❌ **奖励引擎**：复用的记忆 → 奖励升级（L5→L4→L3→L2→L1→L0）**【缺失】**

**完整遗忘机制应该包含两部分**：
```
遗忘机制 =
  ├─ 降级引擎（已实现 ✅）
  │   └─ 不访问的记忆 → 自然降级（L0→L5）
  │
  └─ 奖励引擎（未实现 ❌）← 【本文档设计】
      └─ 复用的记忆 → 奖励升级（L5→L0）
```

---

### 1.2 为什么需要奖励机制？

| 问题 | 无奖励机制的后果 | 有奖励机制的收益 |
|------|------------------|------------------|
| **记忆僵化** | 记忆只降不升，最终全部变成墓碑（L5） | 复用的记忆保持活跃，形成"经验" |
| **无差别遗忘** | 重要记忆和不重要记忆一样被遗忘 | 重要记忆（经常复用）得到保护 |
| **无法形成经验** | 系统无法从记忆中提炼"经验" | 频繁访问的记忆自动升级为"经验" |
| **违背认知规律** | 人类记忆是动态的（用进废退） | 模拟人类"用进废退"的记忆机制 |

---

### 1.3 奖励机制的核心逻辑

```
访问/复用记忆 → 奖励（升级）
   ↓
记忆层级提升（L5→L4→L3→L2→L1→L0）
   ↓
频繁访问的记忆 → 保持在高层级（L0/L1）
   ↓
最终 → 成为"经验"（容易被检索到）
```

**关键指标**：
- `access_count`：访问/复用次数
- `last_access`：上次访问时间
- `is_experience`：是否已转换为经验

### 2.2 奖励机制核心函数

#### **函数1：`promote_entry()` - 升级条目**

```python
def promote_entry(
    entry_id: str,
    access_boost: float = 1.0,
    force: bool = False
) -> Tuple[bool, str]:
    """
    当条目被复用时，奖励（升级）它。
    
    Args:
        entry_id: 条目ID（通常是日期字符串，如 "2026-06-18"）
        access_boost: 访问奖励系数（默认1.0，重要访问可设为2.0）
        force: 是否强制升级（跳过条件检查）
    
    Returns:
        (success, message)
        
    升级条件：
        1. 当前级别 > 0（L0 不需要升级）
        2. access_count > PROMOTION_THRESHOLD（访问次数超过阈值）
        3. 上次访问时间在最近 N 天内（防止很久以前访问的条目升级）
        4. 不是核心保护条目（Level 2 保护）
        5. 不是钢印条目（钢印条目降级极慢，升级也极慢）
    
    升级逻辑：
        L5 → L4：需要 access_count > 5
        L4 → L3：需要 access_count > 10
        L3 → L2：需要 access_count > 20
        L2 → L1：需要 access_count > 50
        L1 → L0：需要 access_count > 100 且 is_experience=True
    """
```

#### **函数2：`record_access()` - 记录访问**

```python
def record_access(
    entry_id: str,
    access_type: str = "retrieve",
    importance: float = 1.0
) -> None:
    """
    记录条目被访问/复用。
    
    Args:
        entry_id: 条目ID
        access_type: 访问类型（"retrieve" | "reuse" | "cite" | "revise"）
        importance: 重要性系数（0.1-2.0）
    
    功能：
        1. 更新 last_access = time.time()
        2. 更新 access_count += importance
        3. 如果 access_count 超过阈值，触发 promote_entry()
        4. 如果条目升级到 L0/L1，标记 is_experience=True
    """
```

#### **函数3：`compute_experience_confidence()` - 计算经验置信度**

```python
def compute_experience_confidence(entry: Dict) -> float:
    """
    计算条目成为"经验"的置信度。
    
    置信度公式：
        confidence = min(1.0,
            (access_count / MAX_ACCESS_COUNT) * 0.5 +
            (recency_boost) * 0.3 +
            (fidelity_level == 0 ? 0.2 : 0.0)
        )
    
    Where:
        - MAX_ACCESS_COUNT = 100（访问次数上限）
        - recency_boost = exp(-λ * days_since_last_access)
        - fidelity_level == 0 表示条目在 L0（完整保留）
    
    Returns:
        置信度（0.0-1.0）
    """
```

### 3.1 在 `tu8_memory.py` 中集成

```python
# 在检索函数中调用 record_access()
def retrieve_memory(query: str, top_k: int = 5) -> List[Dict]:
    """
    检索记忆，并记录访问（触发奖励机制）。
    """
    results = search(query, top_k)
    
    # 奖励机制：访问即升级
    for entry in results:
        record_access(
            entry_id=entry['id'],
            access_type="retrieve",
            importance=1.0
        )
    
    return results
```

## 六、预期效果

### 6.1 量化指标

| 指标 | 无奖励机制 | 有奖励机制 |
|------|------------|------------|
| **记忆平均层级** | 持续下降（最终全部L5） | 稳定（频繁访问的保持在L0-L1） |
| **经验形成率** | 0% | 预计 5-10%（访问次数>50的条目） |

## 七、风险与缓解

| 风险 | 缓解措施 |
|------|------------|
| **无限升级** | 设置升级上限（L0是最高级，不会无限升级） |
| **访问次数造假** | 同一会话内的多次访问只计为1次 |
| **经验泛滥** | 设置经验置信度阈值（只有>0.7的才标记为经验） |
| **性能开销** | 升级周期异步执行，不阻塞主流程 |

## 九、v1.8增强：异常洞察抢救通道（认知架构整合）

> 来源：造物主×Qwen三方对话（涌现时刻#019-027）
> 整合时间：2026-06-25

### 9.1 幻觉 vs 高价值异常预测

| 特征 | 幻觉噪声 | 高价值异常预测 |
|------|---------|--------------|
| 产生时 | 凭空，无根，概率均匀发散 | 低概率，但有内部自洽结构 |
| 验证时 | 无法与任何现实锚点对接 | 能找到部分现实锚点 |
| 传播时 | 越延展越离谱 | 追问能延伸出更多结构 |
| 追问3次后 | 崩溃（自相矛盾） | 仍保持自洽并产生新分支 |

### 9.2 三重过滤门（异常洞察识别）

```
┌─────────────────────────────────────────────┐
│  门1【自洽性】                             │
│    幻觉 → 自相矛盾（"地球是方的是对的"）  │
│    异常洞察 → 追问下自我修正，不越说越乱   │
├─────────────────────────────────────────────┤
│  门2【可追问性】                           │
│    幻觉 → 无法举例，逻辑空                 │
│    异常洞察 → 能，它只是概率低不是逻辑空   │
├─────────────────────────────────────────────┤
│  门3【下游密度】                           │
│    幻觉 → 无法延伸子预测                   │
│    异常洞察 → 能 → 可能是未被验证的洞察   │
└─────────────────────────────────────────────┘
```

### 9.3 修正后的舍弃公式（v1.8）

```
【旧公式】
  舍弃边界 = 置信度阈值
  问题：真正的顿悟在产生瞬间往往置信度极低

【v1.8修正公式】
  舍弃边界 = 置信度 × 可追问深度 × 下游结构密度

  高置信度 × 高追问 × 高密度 = 确定洞察 → 保留
  低置信度 × 低追问 × 低密度 = 幻觉噪声 → 舍弃
  低置信度 × 高追问 × 高密度 = 异常洞察 → 抢救通道 ⭐
```

### 9.4 7-Day Curiosity Hold 机制

```python
# 每个"建议舍弃"的条目：
curiosity_hold = []

def add_to_hold(entry_id, hold_days=7):
    entry = degradation_index["entries"][entry_id]
    entry["curiosity_hold_until"] = now() + hold_days * DAY
    entry["curiosity_resurrected"] = False
    curiosity_hold.append(entry_id)

def check_curiosity_hold():
    """每轮对话前检查"""
    for entry_id in curiosity_hold[:]:
        entry = degradation_index["entries"][entry_id]
        if now() > entry["curiosity_hold_until"]:
            # 7天无触发 → 正式舍弃
            _evaporate(entry_id)
            curiosity_hold.remove(entry_id)

def resurrect(entry_id):
    """造物主追问触发复活"""
    entry = degradation_index["entries"][entry_id]
    entry["curiosity_resurrected"] = True
    entry["confidence_boost"] = 0.1   # 抢救加成
    entry["degradation_rate_halved"] = True  # 降级速度减半
    promote_entry(entry_id, force=True)  # 升级为正式记忆
    curiosity_hold.remove(entry_id)
```

### 9.5 与奖励引擎的集成

```
降级引擎 + 奖励引擎 + 异常洞察抢救通道 = 完整遗忘机制

     记忆访问 → 奖励引擎promote_entry()
                    ↓
     记忆不访问 → 降级引擎自然衰减
                    ↓
     衰减到舍弃边界 → 三重过滤门检测
                    ↓
           ┌─────────┴─────────┐
     通过三重门              未通过三重门
           ↓                      ↓
     7-Day Curiosity Hold      正常舍弃
           ↓
     ┌────┴────┐
  7天内追问  7天后无触发
     ↓              ↓
 复活+升级   正式舍弃
```
