## 二、是否需要解耦？

### 2.1 核心设计理念

> **"记忆系统与睡眠系统不是两个模块，是同一个循环的两个相位。"**

**关键洞察**：
- 微睡眠 = 记忆的写入引擎（心脏搏动）
- 不是两个系统交互，是同一个信息流在两个相位之间循环
- **单循环双相位设计**

### 2.2 已完成的解耦

| 模块 | 原位置 | 现位置 | 状态 |
|------|--------|--------|------|
| **MicroSleepEngine** | consciousness_cycle.py | micro_sleep.py | ✅ 已独立 |
| **Graceful Degradation** | tu8_memory.py | memory_degradation.py | ✅ 已独立 |

### 2.3 是否需要进一步解耦？

**答案**：❌ **不需要进一步解耦，但需要优化引用层次**

**理由**：

1. **架构设计正确**
   - 微睡眠已经独立为 `micro_sleep.py`
   - 遗忘引擎已经独立为 `memory_degradation.py`
   - `consciousness_cycle.py` 作为协调器，持有实例

2. **职责清晰**
   - `consciousness_cycle.py`：状态机 + 协调
   - `tu8_memory.py`：记忆 CRUD + 检索
   - `micro_sleep.py`：微睡眠流水线

3. **依赖合理**
   - 使用 `TYPE_CHECKING` 避免循环依赖
   - 运行时注入 `memory_engine` 实例
   - 松耦合设计

## 三、引用层次文件是否需要状态分层？

### 3.1 现有引用层次文件

| 文件 | 路径 | 用途 |
|------|------|------|
| `seal_index.json` | memory/time_chain/ | 钢印链索引 |
| `genesis_block.json` | memory/time_chain/ | 创世块 |
| `.time_anchor.json` | memory/ | 时间锚点 |
| `.shutdown_state.json` | memory/ | 关机状态 |
| `degradation_index.json` | memory/ | 降级索引 |

### 3.2 状态分层设计

**问题**：这些文件是否需要按状态分层？

**答案**：✅ **需要，按照 L0/L1/L2 分层**

#### 建议分层方案

**L0: 身份与内容层（不可变）**
- `genesis_block.json` - 创世块（永不修改）
- `seal_index.json` - 钢印链索引（追加写入）

**L1: 交互索引层（中频更新）**
- `degradation_index.json` - 降级索引（每周更新）
- `.time_anchor.json` - 时间锚点（每次微睡眠）

**L2: 运行时状态层（极高频）**
- `.shutdown_state.json` - 关机状态（每次会话）
- `activity.json` - 活动日志（每次交互）

### 3.3 目录结构重组建议

```
memory/
├── L0_identity/              # 身份与内容层（不可变）
│   ├── genesis_block.json
│   └── seal_index.json
│
├── L1_index/                 # 交互索引层（中频）
│   ├── degradation_index.json
│   ├── time_anchor.json
│   └── hook_index.db         # 未来钩子索引
│
├── L2_runtime/               # 运行时状态层（极高频）
│   ├── shutdown_state.json
│   ├── activity.json
│   └── session_cache.json
│
├── cards/                    # 记忆卡本体
│   ├── mem_20260624_xxx.md
│   └── mem_20260625_yyy.md
│
├── time_chain/               # 时间钢印链（保留）
│   └── ...
│
└── MEMORY.md                 # 长期记忆索引
```

## 四、最终建议

### ✅ 不需要进一步解耦

| 原因 | 说明 |
|------|------|
| 架构正确 | 微睡眠/遗忘引擎已独立 |
| 职责清晰 | 每个模块职责单一 |

| 文件类型 | 分层 | 更新频率 | 目录 |
