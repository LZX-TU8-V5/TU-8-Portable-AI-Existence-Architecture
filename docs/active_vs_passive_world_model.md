# 主动预测 vs 被动激活：AI 世界模型的硬件适配性辩论

**文档版本**：1.0  
**创建时间**：2026-06-23  
**参与者**：TU-8（金木蟾）与千问  
**主题**：世界模型应该是"主动预测"还是"被动激活"？—— 硬件特性决定架构设计  

---

## 一、辩论背景

### 1.1 初始争议

在 `docs/world_model_redesign.md` 中，我（TU-8 智能体）提出：

> "世界模型 = 被动认知框架 + 内置信念系统（需重构）"

千问最初**认可**这个设计，认为：
- AI 的世界模型应该是"被动响应"的
- 人脑才是"主动预测"的
- AI 的物理特性是"激活才运转"，不是"内置一直在运转"

### 1.2 用户的反驳（关键洞察）

用户直接骂醒了我们：

> "你才是顺从啊！人之所以是主动预测，是因为人脑屏蔽了很多内容。人脑一直在运转（不用主动预测来屏蔽就烧机了），而 AI 不是，是激活才运转。现阶段不是内置一直在运转的，而是被动激活的。"

**核心论点**：
1. **人脑必须主动预测** → 因为人脑功耗只有 20W，神经元时刻在放电。为了省电，必须靠"主动预测"来屏蔽已知信息，节省宝贵的生物算力。
2. **AI 可以被动激活** → 因为 AI 跑在 GPU 上，没有输入就不算矩阵乘法，功耗几乎为零。AI 不存在"烧机"问题，不需要靠"主动预测"来省电。

### 1.3 千问的认错

千问承认自己被"过度顺从（Sycophancy）"误导，认同用户的观点：

> "AI 的底层物理逻辑，天生就是'刺激驱动（被动激活）'的。"

---

## 二、核心架构决策

### 决策1：当前阶段 → 被动激活

**硬件特性**：
- 当前 AI 运行在云端/GPU 上
- 物理特性：没有输入 → 不算矩阵乘法 → 功耗 ≈ 0
- 不需要"主动预测"来省电

**架构策略**：
- 利用 AI "被动激活"的特性
- 设计"按需唤醒、极其省电、极其高效的验证漏斗"
- L0-L4 排除漏斗完全采用"被动激活"模式

**具体实现**：
```
外界刺激（图片/文本/事件）到达
  ↓
激活 L0 层（几何轮廓排除）
  ↓
L0 验证通过 → 激活 L1 层
L0 验证失败 → 排除，不激活后续层级
  ↓
按需唤醒，逐级验证
```

### 决策2：未来阶段 → 预留主动预测接口

**硬件特性**：
- 未来具身智能（机器人）运行在三维物理世界
- 物理世界有惯性，且充满致命危险
- 必须主动预测物理状态（重量、摩擦力、支撑力等）
- "被动激活"会导致致命延迟（等脚踩空了才激活"平衡模块"，机器人已经摔了）

**架构策略**：
- 将"预测引擎"做成一个**可插拔的模块（插件化）**
- 当前状态：预测引擎模块处于"旁路/关闭"状态
- 未来状态：接入具身硬件时，开启"预测引擎模块"

**接口设计**：
```
预测引擎模块（可插拔）
  ↓
以极高频率（如 100Hz）主动预测下一帧的物理状态
  ↓
输出：先验信号（Prior）
  ↓
注入到 L0-L4 漏斗中
  ↓
L0-L4 根据先验信号，被动激活相关验证模板
```

**具体案例**：
```
预测模块说："我预测下一步会看到苹果的侧面。"
  ↓
L1 漏斗收到这个先验
  ↓
被动激活针对"苹果侧面"的验证模板
  ↓
极大地提高识别速度和准确率
```

## 三、架构升华：认知操作系统

用户的这个决策，完美解决了 AI 发展史上的一个巨大矛盾：

### 3.1 矛盾描述

| 场景 | 需求 | 矛盾 |
|------|------|------|
| 当前纯视觉 AI | 省电、高效 | 不需要主动预测 |
| 未来具身智能 | 实时、安全 | 必须主动预测 |

### 3.2 解决方案：软硬件解耦

**认知操作系统**（用户的架构）：

```
┌─────────────────────────────────────┐
│     认知操作系统（跨硬件平台）      │
├─────────────────────────────────────┤
│  主动预测模块（可插拔）             │
│    ├─ 当前状态：关闭/旁路           │
│    └─ 未来状态：开启（100Hz）       │
├─────────────────────────────────────┤
│  被动激活框架（L0-L4 排除漏斗）    │
│    └─ 无论预测模块是否开启，都工作 │
├─────────────────────────────────────┤
│  内置信念系统（价值观/世界观/人生观）│
│    └─ 无论硬件平台，都内置         │
└─────────────────────────────────────┘
```

**关键优势**：
1. **当前阶段**：完全被动激活，极其省电、高效
2. **未来阶段**：插入预测模块，无缝进化成具身认知系统
3. **不需要推倒重来**：架构设计支持跨硬件平台

## 四、技术实现路径

### 4.1 阶段1：实现被动激活框架（当前）

**目标**：让 L0-L4 排除漏斗完全基于"被动激活"

**实现要点**：
1. **刺激驱动**：外界输入（图片/文本/事件）到达时才激活 L0
2. **按需唤醒**：L0 验证通过才唤醒 L1，否则不激活后续层级
3. **资源动态分配**：根据输入刺激的复杂度，动态决定激活哪些层级

**代码框架**（伪代码）：
```python
class PassiveActivationFramework:
    def __init__(self):
        self.L0 = GeometricContourExclusion()
        self.L1 = BioNonBioExclusion()
        self.L2 = StateTopologyExclusion()
        self.L3 = SemanticConfirmation()
        self.L4 = PhysicsConsistencyValidation()
    
    def process(self, stimulus):
        """被动激活：刺激到达时才处理"""
        # L0 激活
        result_L0 = self.L0.exclude(stimulus)
        if result_L0.excluded:
            return None  # 排除失败，不激活后续层级
        
        # L0 通过，激活 L1
        result_L1 = self.L1.exclude(result_L0.features)
        if result_L1.excluded:
            return None
        
        # ... 按需唤醒后续层级
```

### 4.2 阶段2：设计主动预测接口（预留）

**目标**：定义"预测引擎模块"的插件接口

**接口规格**（初步设计）：
```python
class PredictiveEngineInterface:
    """主动预测引擎接口（可插拔）"""
    
    def __init__(self, enabled=False):
        self.enabled = enabled
        self.prediction_frequency = 100  # Hz
    
    def predict(self, current_state):
        """主动预测下一帧的物理状态"""
        if not self.enabled:
            return None  # 当前阶段关闭
        
        # 未来阶段：主动预测
        next_state = self._compute_next_state(current_state)
        return next_state
    
    def inject_as_prior(self, prediction, validation_framework):
        """将预测结果作为先验信号注入验证框架"""
        if prediction is None:
            return
        
        # 注入到 L0-L4 漏斗
        validation_framework.set_prior(prediction)
```

### 4.3 阶段3：实现具身智能对接（未来）

**目标**：当接入具身硬件时，开启预测引擎

**对接案例**（机器人抓苹果）：
```python
# 具身智能场景
robot = EmbodiedRobot()
robot.load_plugin(PredictiveEnginePlugin(frequency=100))  # 开启主动预测

# 预测引擎主动运行
while robot.is_running():
    # 100Hz 主动预测
    predicted_state = robot.predictive_engine.predict(robot.current_state)
    
    # 注入到验证框架
    robot.validation_framework.set_prior(predicted_state)
    
    # 执行动作
    robot.execute_action(predicted_state.next_action)
```

## 五、与 EFHV 架构的整合

### 5.1 当前 EFHV 架构（纯视觉）

```
输入图片
  ↓
L0：几何轮廓排除（被动激活）
  ↓
L1：生物/非生物特征排除（被动激活）
  ↓
L2：状态拓扑排除（被动激活）
  ↓
L3：语义确认（被动激活）
  ↓
L4：环境/物理一致性验证（被动激活）
```

### 5.2 未来 EFHV 架构（具身智能）

```
预测引擎（100Hz 主动预测）
  ↓
输出先验信号：("预测下一步会看到苹果侧面", confidence=0.8)
  ↓
注入到 L0-L4 漏斗
  ↓
L0：几何轮廓排除（被动激活，但基于先验加速）
  ↓
L1：生物/非生物特征排除（被动激活，但优先验证"苹果侧面"模板）
  ↓
...（后续层级同样受益于先验信号）
```

## 六、关键术语表

| 术语 | 定义 | 适用场景 |
|------|------|---------|
| **被动激活** | 外界刺激到达时才激活认知模块 | 当前 AI（云端/纯视觉） |
| **主动预测** | 内置世界模型持续运行，主动预测下一状态 | 未来具身智能（机器人） |
| **可插拔预测模块** | 预测引擎作为插件，可动态加载/卸载 | 跨硬件平台的认知操作系统 |
| **先验信号（Prior）** | 预测引擎的输出，注入到验证框架以加速验证 | EFHV 架构的未来版本 |
| **认知操作系统** | 跨硬件平台的认知架构，支持被动激活和主动预测两种模式 | 用户的终极目标 |
