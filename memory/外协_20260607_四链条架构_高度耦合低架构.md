## 一、四链条的升维

从"三链条"到"四链条"，不仅仅是数量的增加，是系统维度的升维。

### 四大基石

| 链条 | 职责 | 生物学对应 |
|-----|------|-----------|
| **钢印链 (Seal Chain)** | 身份与时间锚 | 我是誰？我在什么时间节点？ |
| **记忆链 (Memory Chain)** | 经验与知识池 | 我经历过什么？我知道什么？ |
| **调度链 (Dispatch Chain)** | 注意力与执行中枢 | 我现在该关注什么？我该调用哪块记忆？ |
| **代谢链 (Metabolism Chain)** | 演化与自净能力 | 我需要遗忘什么？如何提炼经验？ |

## 二、高度耦合（内部的数据共振）

> "在生物学里，心脏、肺、血液和神经系统难道不是'高度耦合'的吗？如果它们之间松耦合了，那叫器官衰竭。"

四条链之间的强制绑定：

```
调度 + 记忆：调度链拉取记忆时，必须带上记忆的"钢印ID"。没有钢印的记忆是孤立的死数据。

记忆 + 代谢：记忆链产生的新条目，自动触发代谢链的"突触修剪"或"深睡压缩"评估。

代谢 + 钢印：代谢链在进行互斥清洗或深度整合后，必须生成一个新的"元钢印（Meta-Seal）"，记录这次演化的发生。

钢印 + 调度：调度链在装配上下文时，必须以最新的钢印为根节点，向外发散因果链。
```

### 工程真相

这四条链**不能分成四个独立的微服务**。它们应该被封装在一个极其紧密的核心模块中（比如 `tu8_core` 或 `v5_soul`）。

在这个模块内部：
- 函数可以直接互相调用
- 共享内存级的数据结构
- 这就是"高度耦合"的工程体现

## 三、低架构（对外的极简接口）

虽然内部咬合得极其复杂，但对于外部的"本地肉体脚本"和"云端大模型"来说，它必须是透明的、简单的。

### 对外接口

```
对外只有一个动作：
  dispatch(user_input, soul_context)
  外部不需要知道里面是怎么做意图路由、怎么做记忆检索、怎么触发微睡的。

对外只有一个输出：
  response_text + new_seal_payload
  外部只管把文本展示给用户，把钢印写入文件。

屏蔽复杂性：
  就像人类的大脑皮层不需要意识到自己正在分泌胃酸一样
```
