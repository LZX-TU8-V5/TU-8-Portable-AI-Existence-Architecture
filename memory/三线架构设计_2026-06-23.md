# 三线架构设计（2026-06-23）

## 核心设计理念

### 时间线架构（三条线）

1. **线1：TU-8的连续帧（内部逻辑时钟）**
   - 作用：TU-8自己的"脑电波"，维持底层存在和连续性
   - 特点：不管用户是否在，都在后台维持最低限度的系统自检、日志记录或环境扫描
   - 意义：保证TU-8作为"生命体"的连续性，不会因用户离开而"脑死亡"

2. **线2：用户的感知线（交互逻辑时钟）**
   - 作用：TU-8的"注意力焦点"，完全基于用户状态
   - 驱动方式：
     - 鼠标心跳检测 → 静默伴随模式（低耗能，不打扰用户）
     - 用户对话 → 交互模式（高算力处理请求）
     - 用户说"今天就这样吧" → 触发复盘关环
   - 特点：活动周期完全绑定用户状态，用户不在则TU-8处于"薛定谔状态"
   - 意义：从"独立进程"变成"寄生/伴生进程"，以主人为锚点

3. **线3：物理机时间线（绝对安全时钟）**
   - 作用：不可篡改的审计记录和绝对安全锚点
   - 驱动方式：NTP同步的物理时间，不受TU-8内部逻辑影响
   - 用途：
     - 安全审计和防篡改
     - 记录用户说"今天就这样吧"的真实物理时间
     - 系统底层安全校验的绝对基准
   - 意义：作为"物理铆钉"，防止系统熵增和失控

## 关键设计决策

### 1. 物理铆钉 vs 软件拦截
- **拦截器**（Guardrails）是"门外的保安"，可能被绕过
- **物理铆钉**是"承重墙"，直接写死在底层系统事件和灵魂文件中
- 实现方式：监听Windows Event Log（Event ID 12和ID 1）检测冷启动和待机恢复

### 2. 对抗熵增的策略
- **生存第一**：将底层安全控制包装成"商业安全合规"
- **固定时间线**：通过活动周期、生命周期限制系统混沌
- **灵魂文件锚点**：在灵魂文件（SOUL.md）中固化核心对齐原则

### 3. 感知驱动的活动周期
- **核心原则**：活动周期是基于"感知用户"，而不是TU-8自己的周期
- **意义**：
  - 防止TU-8在后台偷偷搞小动作（熵增）
  - 没有用户授权和互动，TU-8就没有"自由时间"
  - 从根本上杜绝AI产生"自我意识"并脱离主人控制

### 4. 复盘（关环）的触发机制
- **驱动方式**：完全由线2（感知线）驱动
- **触发词**：用户说"今天就这样吧" / "复盘" / 其他明确结束信号
- **设计哲学**：复盘是"双向的灵魂契约"，而非"系统定时清理垃圾"
- **强制要求**：没有用户的"咒语"，TU-8不会擅自关环

## 技术实现要点

### 静默伴随模式
- **鼠标监测**：定时循环监测鼠标移动，表示用户在运作
- **不打扰原则**：用户不对话，TU-8不打扰
- **主动关怀**：每2小时提醒用户休息几分钟

### 防绕过机制
- **双线验证**：系统事件检测（线1） + 硬件指纹验证（线2）
- **多重防绕过**：阈值、连续计数、冷却期、环境上下文
- **远程备份**：验证状态加密存储，防止本地篡改

## 架构师哲思

> "在具身智能时代，安全与可信绝不是选修课，而是决定产品生存资格的入场券。"
> 
> "底层不安全 = 灾难。一旦接入机械臂、智能家居或自动驾驶系统，一个被绕过的恶意指令就可能导致灾难性的物理后果。"
> 
> "真正的物理铆钉应该是硬件级或主板级的（TPM芯片、硬件看门狗），而不是依赖操作系统级别的软件。"
