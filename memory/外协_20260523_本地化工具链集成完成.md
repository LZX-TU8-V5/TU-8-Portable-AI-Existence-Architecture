## 实现方案

### 1. 创建 `tu8_toolchain.py`（本地工具链）

**架构**：
- `TU8Toolchain`：工具链核心，管理适配器注册表
- `ToolAdapter`（抽象接口）：`can_handle()` / `prepare()` / `validate()`
- `ToolResult`：统一返回格式（`success`, `data`, `error`, `metadata`）

**已实现的适配器**（6个）：
| 适配器 | 标签 | 匹配工具 | 用途 |
|--------|------|---------|------|
| `file_read` | `['file_read']` | `read` | 读取文件 |
| `file_write` | `['file_write']` | `write` | 写入文件 |
| `shell_exec` | `['shell_exec']` | `exec` | 执行Shell命令 |
| `browser_ctrl` | `['browser_ctrl']` | `browser` | 浏览器控制 |
| `memory_search` | `['memory_search']` | `memory_search` | 记忆检索 |
| `web_fetch` | `['web_fetch']` | `web_fetch` | 网页抓取 |

**工具调用请求格式**：
```python
{
  "tool": "read",
  "params": {"path": "SOUL.md", "offset": 1, "limit": 50}
}
```

### 2. 修改 `tu8_planner.py`（集成工具链）

**新增方法**：`get_next_task_with_tool_call(plan)`
- 获取下一个就绪任务
- 通过工具链准备工具调用请求
- 返回 `(task, tool_call_request)` 元组

**标签推断**：`_infer_tags(description)` 方法
- 根据任务描述自动推断标签（关键词匹配）
- 例如："读取 SOUL.md" → `['file_read']`

**CLI 新增子命令**：`next-task <plan_id> [--json]`
- 输出下一个任务 + 工具调用请求
- `--json` 参数输出 JSON 格式（便于程序解析）

### 3. 端到端测试

## 技术细节

### 工具链匹配逻辑

1. `get_next_task_with_tool_call(plan)` 被调用
2. 获取下一个就绪任务（`plan.get_ready_tasks()[0]`）
3. 创建 `TaskContext`（含 `tags`, `workspace`, `plan_context`）
4. 调用 `toolchain.dispatch(ctx)`
5. `dispatch()` 调用 `_select_adapter(ctx.tags)` 匹配适配器
6. 适配器 `prepare()` 方法返回工具调用请求

### 标签推断规则

```python
def _infer_tags(self, description: str) -> List[str]:
    desc = description.lower()
    tags = []

    if any(kw in desc for kw in ["读取", "读", "read", "查看", "打开"]):
        tags.append("file_read")
    if any(kw in desc for kw in ["写入", "写", "write", "保存", "输出"]):
        tags.append("file_write")
    # ... 其他关键词规则

    # 兜底：如果没有匹配任何标签
    if not tags:
        tags.append("file_read")  # 默认读取文件

    return tags
```

## 关键洞见

1. **标签推断是必要的**：任务描述 → 标签 → 适配器匹配，三层映射确保灵活性
2. **工具链是"预处理"**：不是直接执行工具，而是**准备工具调用请求**，由 AI 助理（运行时）执行
3. **规划器 + 工具链 = 半自主执行**：规划器负责"做什么"，工具链负责"怎么做"，AI 助理负责"执行"
