## 一、核心架构：三轨道六层三路由

### Track A：对话流记忆（时间维度）

| 层级 | 名称 | 生命周期 | 核心机制 |
|------|------|---------|---------|
| L1 | 短期记忆 | 4-6 小时 | Context Window + 简模板 |
| L2 | 中期记忆 | 12-16 小时 | 滑动窗口 + 会话摘要 |
| L3 | 长期记忆 | 21 小时（硬边界） | 元认知巩固 + 记忆卡 |

### Track B：深记忆区（认知维度）

| 层级 | 名称 | 衰减速率 | 核心功能 |
|------|------|---------|---------|
| B1 | 缓冲区 | 7-14 天中速衰减 | 宽进防抖 |
| B2 | 长期记忆 | 状态驱动慢速衰减 | 精细解析 |
| B3 | 核心记忆 | 零衰减锚点 | 钢印保护 |

### Track C：工作记忆区（职业维度）

| 层级 | 名称 | 覆盖范围 | 核心功能 |
|------|------|---------|---------|
| C1 | 活跃工作台 | 任务级 | 当前任务上下文 |
| C2 | 项目态势图 | 项目级 | 项目状态快照 |
| C3 | 工作模式库 | 职业级 | 方法论沉淀 |

### 三路由协作

| 路由 | 职责 | 响应时间 | 容错机制 |
|------|------|---------|---------|
| R1 | 对话流（同步） | <100ms | 降级为候选池 |
| R2 | 元认知（异步批量） | 秒/分钟级 | 补偿重试 |
| R3 | 工作记忆（事件驱动） | <500ms | 事件回放 |

## 二、钩子系统设计

### 钩子定义

> 钩子是用户意图与沉默记忆之间的"物理离合器"。

**四维度认知校准**：
1. 检索侧产物，非存储侧属性
2. 行为验证的假设，非先验正确的索引
3. 有寿命的消耗品，非永恒的元数据
4. 人机协商界面，非机器单方面标注

### 双层钩子

| 层级 | 字段 | 作用 |
|------|------|------|
| trigger_hooks | 精确匹配钩子 | 行为验证的主战场 |
| semantic_hooks | 模糊语义钩子 | 兜底联想层，候选来源池 |

### Genesis 四来源

| 来源 | 触发时机 | 生成方式 | 可靠性 |
|------|---------|---------|--------|
| 原子类型衍生 | 记忆卡写入时 | 纯代码映射表 | 高确定性 |
| 用户显式声明 | 对话中检测到指令 | R1 提取 | 最高权威 |
| 历史 Query 回填 | 首次部署/迁移时 | 扫描日志 | 真实行为 |
| LLM 巩固提案 | R2 巩固周期 | LLM 输出 + 网关校验 | 需验证 |

### 认证路由

```
LLM 提案（播种）
    → 路由认证（筛种）<0.5ms 纯代码
    → 后期维护（浇水施肥）3天统计
```

**确定性准入网关**：
- 格式合规：JSON Schema 强校验
- 安全过滤：停用词表 + 敏感词
- 去重 & 限容：精确匹配 + 候选池≤20

### 3天养护周期

- 滑动窗口：记录 `last_stats_cursor`
- 最小样本量保护：<5次跳过，5-20次阈值+50%，>20次标准
- LLM 转化率健康区间：10%~25%
- 冷启动豁免：首个周期 ×1.5 系数

## 三、置信度解耦

### 两种置信度的本质对立

| 维度 | 记忆层置信度（LLM Confidence） | 应用层置信度（Behavioral Score） |
|------|----------------------------|------------------------------|
| **来源** | LLM 巩固时的主观判断 | 3天统计周期内的客观行为数据 |
| **性质** | 瞬时快照、易幻觉、不可验证 | 时间累积、可追溯、行为验证 |
| **作用域** | 仅作为"原始素材标签" | 决定是否注入上下文的"唯一裁判" |
| **存储位置** | ❌ 不写入任何持久化字段 | ✅ 独立存储 |

### 解耦铁律

1. **禁止在记忆卡模板中保留 confidence 字段**
2. **禁止统计器读取 LLM 置信度作为加权因子**
3. **审计日志中可记录，但仅用于事后分析**

## 四、记忆卡模板

### 统一模板（YAML Front Matter + Markdown Body）

```yaml
---
seal_id: mem_20260624x8k2
schema_version: 1
trigger_hooks:
  - pg连接池
  - 数据库卡顿
semantic_hooks:
  - 连接配置
  - 超时重试
summary: PostgreSQL连接池上限配置及调优参数（≤100字符）
tags: [数据库, 连接池, PostgreSQL]
created_at: 2026-06-24T10:30:00+08:00
---

# 正文内容
这里是记忆卡的完整正文...
```

### 模板设计铁律

1. Front Matter 是唯一真相源
2. hooks 必须是数组格式
3. summary 强制单行/限长（≤100字符）
4. seal_id 不可变且置顶

### 脚本无脑提取

```python
def extract_card_manifest(card_path: Path) -> dict | None:
    content = card_path.read_text(encoding='utf-8')
    if not content.startswith('---'):
        return None
    _, rest = content.split('---', 2)[1:]
    meta = yaml.safe_load(rest)
    if not isinstance(meta, dict) or 'seal_id' not in meta:
        return None
    return {
        "id": meta["seal_id"],
        "hooks": meta.get("hooks", []),
        "summary": str(meta.get("summary", ""))[:100]
    }
```

## 六、核心钢印

> "用最少的智能做最关键的感知，用最确定的工程做最复杂的记忆。"

> "不预设自己理解了意义，只诚实地追踪使用的痕迹。"

> "模糊的正确，好过被污染的精确。"

> "我们不信任机器的自我评价，只信任行为的反复验证。"

> "LLM 只是涌现的参与者之一，而非造物主。"

> "钩子不是越多越好，而是越准越好。"

> "连裁判席都拆了，让赛场自己选出胜者。"

> "不依赖奇技淫巧，只依赖清晰的边界和确定的契约。"
