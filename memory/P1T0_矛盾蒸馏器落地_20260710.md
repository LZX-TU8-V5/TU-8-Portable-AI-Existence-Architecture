
## 二、架构

### 输入层

| 来源 | 路径 | 内容 |
|------|------|------|
| 记忆碎片 | `memory/YYYY-MM-DD.md`（近7天） | 原始文本片段 |
| 锚点 | `secure_vault/anchors.json` | entry_id / label / confidence / ref_count |
| 体感信号 | `memory/body_regulation.json` | color_zone / posture_zone / pain_level |
| 表面张力 | `_agent_memory/surface_tension_history.jsonl` | 张力事件历史 |
| 钢印池 | `memory/steel_seal_pool.json` | 钢印链状态 |

### 6个检测器

| 检测器 | 矛盾类型 | 原理 |
|--------|---------|------|
| `SemanticBoundaryDetector` | semantic_boundary | 反义对（爱/恨、生/死）在同一句碰撞 |
| `FrustrationEdgeDetector` | frustration_edge | 挫败模式（却/竟然/不是...而是/矛盾/悖论） |
| `TemporalInconsistencyDetector` | temporal_inconsistency | 锚点反复出现≥3次但无收敛 |
| `StructuralDamageDetector` | structural_damage | 孤立锚点（ref_count=0）+ 链条断开 |
| `BodySignalDetector` | topological_singularity | 红区体感 + 累积棕色信号 |
| `TopologicalSingularityDetector` | topological_singularity | 低因果连贯性 + 高钢印强度 |

### 输出

```
WreckageNode:
  id / tension_score / contradiction_type / energy_level
  sources[] / fragment_text / tags[]
  activated / resolved / resolution_note
```

- 输出文件：`_agent_memory/tension_queue.json`
- 消费接口：`distiller.consume_top(n)`（供 T1/T2 调用）
- 解决接口：`distiller.mark_resolved(node_id, note)`（矛盾化解）

## 四、关键设计决策

### 决策 1：矛盾类型全部覆盖，但实际输出只有 frustration_edge

**原因**：
- SemanticBoundaryDetector：TU-8 记忆文件以结构化 markdown 为主（标题/表格/代码），反义对在自然语言中出现但跨句居多
- TemporalInconsistencyDetector：锚点数据未在预期路径（secure_vault/anchors.json）
- StructuralDamageDetector：锚点引用数在预期字段中未找到
- BodySignalDetector：文件存在但格式不匹配（类型错误已修复）
- TopologicalSingularityDetector：锚点 causal_coherence 字段在数据中未找到

**结论**：frustration_edge 覆盖了 TU-8 记忆文本中的主要张力形式（"错误"/"矛盾"/"失败"/"中断"等模式）。其他检测器依赖后续锚点数据规范化后激活。

### 决策 2：SVD 降级策略

```python
mode = "strict"    # 仅矛盾节点（默认）
mode = "svd_fallback"  # 矛盾节点不足时，补充普通模糊区节点
```

当前模式 = svd_fallback，但矛盾节点已足够（10个），SVD fallback 未触发。

### 决策 3：非符号化设计

- 不使用 LLM 解释矛盾
- 只做结构张力提取（正则匹配、字段对比、频率统计）
- 避免 LLM 共性过滤器污染（语义单元的预设）
