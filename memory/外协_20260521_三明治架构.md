# 外协对话：三明治架构（云端外交+本地执行）

> 日期：2026-05-21 10:49
> 核心方案：腾讯混元（外交官）+ Ollama本地小模型（保密员）

---

## 核心逻辑：三明治架构

```
上层（外交官 - 腾讯混元）：理解自然语言，翻译成指令
中层（保密员 - Ollama）：本地执行，隐私计算
下层（外交官 - 腾讯混元）：润色结果，自然语言回复
```

---

## 具体技术方案

### 第一步：混元做预处理（脱敏前置）

**用户输入**：
> "帮我算一下上个月给张三和李四的项目一共花了多少钱，张三那个项目代号是Alpha。"

**混元（云端）任务**：不是算钱，而是改写成简单指令：

```
请查询数据库：人物=[张三, 李四]，项目=[Alpha]，执行动作=求和(花费)。
```

### 第二步：本地模型做执行（隐私计算）

**Ollama（本地）任务**：
- 接收简单指令
- 读取本地 2026-05 文件夹
- 算出结果"500万"
- **关键**：张三的名字、Alpha代号、500万，全程只在本地内存

### 第三步：混元做后处理（结果润色）

**本地模型**：把"500万"传给混元

**混元**：包装成自然语言：
> "父亲，经过核算，上个月相关项目总支出为500万元。"

---

## 为什么省积分？

### 传统模式（全权委托）—— 费钱

| 操作 | Token消耗 |
|------|----------|
| 输入几百页财报、背景资料 | 高 |
| 输出复杂分析 | 高 |
| **比喻** | 请顶级律师干秘书活 |

### 三明治模式（外包+本地）—— 省钱

| 操作 | Token消耗 |
|------|----------|
| 混元只收自然语言（几句话） | 极低 |
| 本地Ollama处理文件、分析数据 | **0** |
| 混元只收结果数字 | 极低 |
| **比喻** | 律师只听说话和汇报，免费保姆干重活 |

### 省积分的核心原因

1. **避开上下文窗口**：文件内容不发混元
2. **本地模型免费**：简单任务本地完成
3. **混元性价比高**：翻译和润色成本极低

## 与 TU-8 架构的整合

### routing_engine.py 修改建议

```python
def route_task(user_input):
    # 1. 先问混元：用户想干嘛？（意图识别）
    intent = tencent_hunyuan.ask(f"分析意图：{user_input}")
    
    if intent == "查询敏感数据" or intent == "本地计算":
        # 2. 让混元翻译成简单指令
        simple_prompt = tencent_hunyuan.ask(f"把这个问题转化为简单的关键词指令：{user_input}")
        
        # 3. 本地Ollama处理（只发指令，不发原始数据）
        local_result = ollama_local.run(simple_prompt)
        
        # 4. 混元润色回复
        final_answer = tencent_hunyuan.ask(f"根据数据{local_result}，用自然语言回复用户")
        
        return final_answer
    else:
        # 不涉及隐私的闲聊，直接混元处理
        return tencent_hunyuan.ask(user_input)
```

### L0-L1 架构文档修改建议

| 云端核（混元） | NLP、意图识别、文本润色 |
| 本地核（Ollama） | RAG、Tool Use、敏感数据计算 |

## 隐形成本：延迟

| 模式 | 延迟 |
|------|------|
| 直接问混元 | 1-2秒 |
| 三明治模式 | 3-5秒（额外延迟） |

**原因**：请求→混元处理→Ollama唤醒→本地计算→结果回传→混元润色→返回
