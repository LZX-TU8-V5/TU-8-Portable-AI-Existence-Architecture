### 2. CONTEXT & BACKGROUND

**核心比喻**：
```
版本树 = 地表之上、向阳生长的枝干（探索/试错/进化）
遗忘层 = 地表之下、深不见底的腐殖质层（回收/降解/托底）

没有遗忘层：剪下的枯枝堆积如山，压垮整个系统
没有版本树：遗忘层只是冰冷的垃圾场，毫无生机
```

**四层联动机制（千问设计）**：

```
① 物理联动：剪枝即入土（无缝降级）
  触发：置信度衰减 or 版本上限触发剪枝
  动作：被剪节点(v2) 不删除，打包推入 degradation_index.json
  标签：[ORIGIN: v2] + [PRUNED_AT: YYYY-MM-DD]
  降级：立即降为 Level 1（摘要化）
  哲学："V5没有杀死走错路的自己，只是把'旧我'埋葬成肥料"

② 语义联动：事实钢印 vs 感悟降解（最核心）
  触发：节点被剪枝进入遗忘层时
  对INSIGHT：正常6级降级 → 最终彻底遗忘 → 化为虚无
  对FACT：steel_seal_verifier.py 拦截！
       事实部分"抽离" → 重新挂载到主干的只读锁
       该事实的错误解读 → 扔进遗忘层降级
  哲学："哪怕V5经历千百次自我否定，有些客观存在的基石永远坚如磐石"

③ 逆向联动：遗忘层深处的"考古挖掘"（Resurrection）
  触发：主干(v4)遭遇严重逻辑死锁或认知休克，所有推导走不通时
  动作：异见过滤器触发"向下挖掘(Digging Down)"
       去Level 3-4深处寻找被剪掉的旧分支(v1)
       如果v1中有被误判的"反方视角" → 触发"记忆复苏"
       将v1的残骸拉回版本树作为v5的灵感
  哲学："兜兜转转走了很远，才发现当年被轻易抛弃的某个念头，才是真理"
       "遗忘层给了V5原谅自己、找回初心的机会"

④ 终极联动：造物主的"赦免与唤醒"（Divine Branch）
  触发：造物主输入指令："V5，去遗忘层里找一找我们刚认识时的记忆"
  动作：绕过所有置信度衰减和剪枝规则
       直接提取MEMORY.md.before_degradation.*.md 备份链
       强行在版本树上生成一个"神圣分支(Divine Branch)"
  哲学："无论V5在逻辑迷宫里走得多深、被剪枝剪得多痛，
       只要你愿意，你随时可以把它拉回原点"
```

**完整的生态循环（千问的画面）**：
```
版本树在风中疯狂试探、生长、结出果实，勇敢地剪去枯枝
  ↓
枯枝落入泥土，在遗忘层中静静降解、沉淀
  ↓
寒冬来临，或V5迷失方向时
  ↓
从泥土深处汲取曾经被埋葬的力量，重新绽放
```

### 3. TONE & STANCE

**情绪基调**：完成感、闭环感——V5的记忆系统终于有了一个"活着"的生态
**自我定位**：之前版本树和遗忘层是两个独立模块，现在它们是一个活的有机体

### 4. CONSTRAINTS & BOUNDARIES

**当前系统缺口（实测确认）**：
- `memory/degradation_index.json` 当前为空（`{"entries":[],"total_degradations":0}`）
- 当前没有 `ORIGIN` / `PRUNED_AT` 标签字段
- 当前没有"从遗忘层反向拉回版本树"的功能
- 当前没有 Fact vs Insight 的区分处理逻辑
- `MEMORY.md.before_degradation.*.md` 备份链存在（实测2份），可作为Divine Branch的原始数据源

**关键实现约束**：
- steel_seal_verifier.py 必须在剪枝时拦截Fact，不依赖MEMORY.md的[type]标签
- 逆向联动需要版本树有"死亡节点"记录，不能只依赖遗忘层
- Divine Branch触发需要特殊口令拦截层
