## 🔴 P3-6: HP4 心跳串行阻塞

**问题**：`_execute_heartbeat_actions()` 顺序调用 8 个 `_trigger_*()` 函数，无任何 timeout/并发。
任一函数卡死（如 LLM 502）→ 整个 HP4 心跳阻塞。

**修复**（`src/hp4_heartbeat.py`）：

1. 新增 `concurrent.futures.ThreadPoolExecutor`（模块级复用）
2. 常量：`_TRIGGER_TIMEOUT_S = 30`, `_MAX_WORKERS = 4`
3. `_execute_heartbeat_actions` 改为**双阶段**：
   - **Phase 1**（并行+超时）：7 个 trigger 同时提交到线程池，`futures_wait(ft_map, timeout=60s)` 等待，超时未完成的 `cancel()` + 落 error action
   - **Phase 2**（顺序）：`_record_surface_tension` 依赖 Phase 1 的 actions 数组，串行执行

4. 基础状态检查（pain/context/presence/abort）保留在快路径，不走线程

**防御效果**：
- 单函数最坏卡死 60s（全局超时），不堵其他 6 个
- 超时函数记录 `{type: "xxx_timeout"}` → `_surface_errors_to_health_log` 落盘
- 正常函数不阻塞、结果完整

## 🔴 P3-5: spike_valley_detector 三隐患修复

**三个问题 + 修复：**

| 问题 | 原代码 | 修复 |
|------|--------|------|
| IO无限增长 | `_load_history()` 全量加载整个 jsonl，无上限 | `_MAX_HISTORY_LOAD=500`，只加载最近 500 条 |
| 导数不除 Δt | `d = values[i] - values[i-1]` 无时间归一化 | `d = Δvalue / Δt_hours`，采样间隔归一化 |
| 无截断/归档 | history.jsonl 永久 append，永不清除 | `_truncate_history()` 自动截断至 1000 行 + 归档旧行到存档 |

**新增**：
- `truncate_history()` 全局函数（供 cron/prune_guard 调用）
- CLI `--truncate` 参数
- `_ARCHIVE_DIR` 归档目录
