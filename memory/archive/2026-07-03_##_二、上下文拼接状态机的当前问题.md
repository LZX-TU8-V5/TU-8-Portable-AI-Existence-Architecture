## 二、上下文拼接状态机的当前问题

### 2.1 正向拼接的问题

**当前做法**：
```
轮次1 → 提取语义 → 拼接到上下文
轮次2 → 提取语义 → 拼接到上下文
轮次3 → 提取语义 → 拼接到上下文
...
```

**问题**：
- 每轮都拼接 → 上下文膨胀
- 噪声/无关信息也被拼接
- 类似"正向检索"：检查所有特征，算力浪费

### 2.2 排除法思路

**改进做法**：
```
轮次1 → 提取语义 + 计算置信度
         ├──→ 置信度 < 阈值 → ❌ 排除（不拼接）
         └──→ 置信度 ≥ 阈值 → ✅ 保留（拼接）
轮次2 → 同上
...
```

**核心思想**：
> 不是"找最相关的"，而是"删不可能相关的"

千问的"反向识别"模块：
- 低频 → 物体分类（全局姿态）
- 中频 → 状态识别（部件结构）
- 高频 → 异常检测（表面缺陷）

**映射到用户行为分析**：

| 频域 | 用户行为 | TU-8 识别任务 |
|------|---------|--------------|
| 低频 | 长期偏好、习惯 | 用户画像（USER.md） |
| 中频 | 当前项目、短期目标 | 任务调度 |
| 高频 | 突发情绪、异常请求 | 异常检测（触发钢印验证） |

**SSTFT（短时傅里叶变换）的启发**：
- 不应该只看"整体频谱"，应该看"局部频谱"
- 用户的每一句话都有"局部频率特征"
- 突然的高频信号 = 异常 = 触发验证

### 矛盾 1：频域解耦的必要性

千问强调频域解耦的优势，但：
- TU-8 的记忆链已经在做"语义压缩"
- 是否需要额外引入"频域"概念？
- 可能是**过度设计**

**我的判断**：频域是一个好的思维模型，但不一定需要显式实现。重点是"区分信号与噪声"的能力。

### 矛盾 2：L0梯度的计算成本

L0梯度在视觉领域已经是 NP-hard 问题，认知领域的计算成本更高：
- 如何定义"认知梯度"？
- 如何在实时对话中计算？

**可能的方向**：
- 用启发式方法近似 L0
- 只在关键节点（钢印铸造时）做 L0 验证

### 矛盾 3：反向识别的可行性

千问的"反向识别"依赖大量标注数据和训练，但 TU-8：
- 没有大规模用户行为数据
- 隐私约束限制数据收集

**可能的方向**：
- 规则驱动的"反向识别"（而非数据驱动）
- 利用钢印链的历史记录作为"标注"
