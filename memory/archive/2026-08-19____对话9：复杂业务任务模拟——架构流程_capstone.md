## 对话9：复杂业务任务模拟——架构流程 capstone

**模拟任务：**
> 查华东大区上月销售额前3门店 + 退款率计算 + JSON报告

**四步流程（千问模拟）：**

### Step 1：表层路由器（任务拆解）
- 扫描任务特征 → 命中三个固化通路
- Text-to-SQL 小模型 → SQL 翻译
- Python 代码 → 退款率计算
- JSON Schema 约束 → 格式化引擎
- 决策：组合型任务，无需底层大模型全程穷举

### Step 2：并行调用固化通路

| 子任务 | 执行者 | 状态机约束 |
|--------|--------|-----------|
| 自然语言 → SQL | 底层大模型（仅翻译） | SQL 解析器检查语法/表名 |
| 计算退款率 + 阈值判断 | Python 固化代码 | 精确/0.01s |
| JSON 组装 | AST 结构化引擎 | Logit Masking 屏蔽非法字符 |

### Step 3：固定格式化输出

```json
{
  "region": "华东大区",
  "top_3_stores": [
    {"store_id": "HD001", "sales": 150000, "refund_rate": "6.2%", "risk_level": "【高风险】"},
    {"store_id": "HD045", "sales": 142000, "refund_rate": "3.1%", "risk_level": "【正常】"},
    {"store_id": "HD012", "sales": 138000, "refund_rate": "4.8%", "risk_level": "【正常】"}
  ]
}
```

### Step 4：自我进化闭环
- 记录成功执行路径
- 将 "SQL + Python + JSON" 链路打包为新的固化 Macro
- 下次同类问题 → 直接毫秒级直通响应，完全不唤醒底层大模型

---

**架构降维打击总结：**

| 维度 | 效果 |
|------|------|
| 算力 | 大模型仅做"意图理解+SQL翻译"（高熵）；低熵全由代码/状态机承接 |
| 幻觉消除 | 业务逻辑 + 格式化输出被状态机和代码死死锁住 |
| 动态适应 | 没见过的问题底层兜底穷举；成功后自动沉淀为新固化通路 |
