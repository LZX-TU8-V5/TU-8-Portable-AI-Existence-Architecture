## 三、排除法在上下文拼接中的应用

### 3.1 多层级排除

```
输入：新轮次对话
       ↓
L1: 相关性排除
       ├──→ 与当前任务无关 → ❌ 不拼接
       └──→ 与当前任务相关 → ✅ 进入下一层
              ↓
L2: 时效性排除
       ├──→ 过期信息（已被后续轮次覆盖） → ❌ 不拼接
       └──→ 有效信息 → ✅ 进入下一层
              ↓
L3: 冗余性排除
       ├──→ 与已拼接内容重复 → ❌ 不拼接
       └──→ 新增信息 → ✅ 进入下一层
              ↓
L4: 置信度排除
       ├──→ 置信度 < 阈值 → ❌ 不拼接（或降级处理）
       └──→ 置信度 ≥ 阈值 → ✅ 拼接
```

### 3.2 短路机制

**排除法的核心优势**：
> 任意一层排除，立即终止，不再检查后续层级

**例子**：
- L1 判断"与当前任务无关" → 直接跳过，不计算时效性/冗余性/置信度
- 类似视觉领域的"无sinc峰 → 排除棱柱类"

### 5.1 状态编码

**视觉领域**：
- 200-bit 向量表示标签
- 位运算快速排除

**TU-8映射**：
- 对话状态编码为位掩码
- 每个bit代表一个状态维度

**状态维度示例**：
```
[任务相关, 时效性, 冗余性, 置信度, 情绪, 意图, ...]
[  1,      1,     0,      1,    0.8,  0.9,  ...]
```

### 5.2 批量排除

**应用场景**：
- 多轮对话同时到达（群聊场景）
- 批量处理时，用位运算同时排除多条

---


**LCM (Lossless Context Management)**：
- 当前 LCM 做的是"压缩"（类似L2平滑）
- 可以引入"排除法"做"剪枝"（类似L0梯度）

**改进方向**：
```
当前：LCM 压缩 → 保留摘要
改进：LCM 排除 → 先剪枝再压缩
```

**算力节省**：
- 先用排除法剪枝（位运算，快）
- 再对剩余内容压缩（浮点运算，慢）

---


千问建议：
> 不要仅用L0做后处理，应作为损失函数嵌入网络。

**TU-8 应用**：

当前流程：
```
对话发生 → 记忆写入 → [无验证] → 存储
```

改进流程：
```
对话发生 → 提取候选记忆 → L0梯度验证 → 通过则写入 / 不通过则标记冲突
```

**L0梯度在认知领域的定义**：
- 梯度 = 新信息与已有知识的差异
- L0 = 显著差异的数量
- 平滑 = 新知识与已有知识一致
- 边缘 = 新知识与已有知识冲突

**验证指标**：
- GSR（梯度稀疏比）过低 → 新信息全是噪声，忽略
- GSR 过高 → 新信息全是冲突，需人工确认
- GSR 适中 → 有价值的知识更新，写入
