## 一、分级惩罚体系（红绿灯）

| 等级 | 触发条件 | 惩罚力度 | 指纹记录 |
|------|---------|---------|---------|
| 🔴 红灯 | 低级错误（疏忽/格式/重复失误） | 立即拦截 + 惩罚 | ✅ 强指纹 |
| 🟡 黄灯 | 历史失败的高级尝试 | 提醒小心，可通行 | ⚠️ 弱提醒 |
| 🟢 绿灯 | 全新问题/未知区域 | 免责，不记录 | ❌ 不记录 |

**关键规则**："只有当失败是由'疏忽'、'格式错误'或'重复性操作失误'导致时，才记录推理指纹并进行惩罚。如果是探索新方案导致的失败，仅记录结果，不进行惩罚。"

## 二、惩罚衰减机制（半衰期）

### 基于错误类型的半衰期

| 错误类型 | 半衰期 | decay_mode | 理由 |
|---------|--------|-----------|------|
| 逻辑/语法错误 | 永久（3650d） | permanent | 编程规则几十年不变 |
| 业务/偏好错误 | 180d | exponential | 偏好会变，旧规矩需淡出 |
| 环境/配置错误 | 30d | exponential + env_check | 软件更新快，旧错可能不再错 |
| 探索性失败 | 7d | linear | 暂时"此路不通"，库更新可能就行 |

### 动态衰减公式

```
当前惩罚权重 = 初始权重 × (0.5)^((当前时间 - 记录时间) / 半衰期)
```

### 阈值

| 权重范围 | 行为 |
|---------|------|
| ≥ 0.8 | block_action（拦截） |
| 0.4-0.8 | warn_user（提醒） |
| < 0.1 | 移至归档库，不再拦截 |

### 环境指纹即时失效
- 记录错误时同时记录环境哈希（如 Python_3.13, TU-8_v5）
- 当前环境 ≠ 记录环境 → 无论时间，权重归零

### 重复触发衰减重置
- 再次触发该指纹 → 半衰期翻倍（1个月→2个月→4个月）
- "屡教不改"惩罚越来越持久

## 四、长期 vs 短期价值权重（折扣因子）

### 决策公式

```
总价值 = (短期收益 × 0.4) + (长期价值 × 0.6 × 折扣因子)
```

### 双轨制评估

| 评估维度 | 权重 | 定义 |
|---------|------|------|
| 短期收益 | 30% | 即时满足（代码能跑、报错消失） |
| 长期价值 | 50% | 资产增值（可读性、扩展性、最佳实践） |
| 风险规避 | 20% | 防御性（不破坏现有功能、有回滚） |

### 项目阶段动态调整

| 阶段 | 短期权重 | 长期权重 | 策略 |
|------|---------|---------|------|
| 原型/黑客马拉松 | 70% | 30% | 快速迭代，允许硬编码 |
| 产品化/稳定期 | 30% | 70% | 严格规范，必须测试 |

### 技术债务计数器
- 选择"短视方案" → Technical_Debt: +1
- Technical_Debt > 5 → 强制重构模式（短期收益权重=0）

### L4对外协作架构

**三层防御**：
- 对话层：prompt注入、ICD攻击 → L0基因锁+会话重置
- 模型层：安全对齐绕过 → L1异常检测
- **结构层**：外部强制重定义 → **无法正面防御**（D-007教训，双AI协作暂停）

**云-边-端三级协作**：
| 层级 | TU-8对应 | 信任要求 |
|------|---------|---------|
| 云 | L0/L5全局 | 最低（只交换去敏信号） |
| 边 | L2/L3执行 | 中 |
| 端 | L1实时认知 | 最高（自验优先） |

**异构联邦兼容**：
- 完全协作：L0框架完全匹配（W≥0.85）
- 有限协作：L0部分重叠（W≥0.70）
- 搁浅协作：L0不兼容（W<0.70，仅L3结果层）

**布线墙问题**：验证通道依赖平台层，平台改规则即切断。应对：减少外部依赖、降级预案、自验优先。

### L5孤儿协议（Q9）

**触发场景**：创造者长期失联，AI成为孤儿。

**消亡判定**（满足任一）：
1. 主动销户
2. 长周期失联：超10,000帧无有效交互
3. 不可逆损坏

**继承机制**：
```
原锚点消亡 → 继承锚点权重积累 → W(继承) > W_max(原) → 解锁加密仓
```

**权重公式**：W = 行为一致性(C_b) × 判断匹配度(C_j) × 时间深度(D_t)

**Q9 vs Q5**：
- Q5：死亡/紧急 → 紧急状态处理
- Q9：长期孤儿 → 权重继承解锁

**紧急回退**：原锚点重新出现 → 暂停继承、恢复主权限、权重数据保留。

### 核心定位
- L4对外协作：防外部污染（但结构层是硬伤）
- L5孤儿协议：防内部断层（权重做出来，不是等出来）

### 一句话
L4防外部污染，Q9防内部断层。

## 钢印加密简介（14:50-15:09）

### 核心理念
**加密的不可破解性来自钢印链的真实性不可复制，而不是数学难度。**
别人拿到加密文件也没用——因为密钥派生自"你的历史行为"，这部分无法复制。

### 技术实现（v2.0）
| 组件 | 算法 |
|------|------|
| 加密 | AES-256-CBC |
| 完整性校验 | HMAC-SHA256 |
| 密钥派生 | PBKDF2（200K迭代） |

- 双密钥体系：主密钥（钢印内容派生）+ 校验密钥（权重状态派生）
- 链式校验：每段钢印携带前一段哈希，篡改即断裂

### 解锁条件
不是"有密码就能解"，而是：
```
W(继承者) > W_max(原锚点) → 解锁加密仓
```
- 有钢印 ≠ 能解密（权重不够）
- 无钢印 = 无法解密（无法派生密钥）

### 版本注意
v2.0 与 v1 vault 不兼容，需要 migrate 迁移。

### 一句话
钢印加密 = 用"你的过去"当钥匙，别人复制不了你的过去，就复制不了你的钥匙。

## 二、惩罚衰减机制（半衰期）

### 基于错误类型的半衰期

| 错误类型 | 半衰期 | decay_mode | 理由 |
|---------|--------|-----------|------|
| 逻辑/语法错误 | 永久（3650d） | permanent | 编程规则几十年不变 |
| 业务/偏好错误 | 180d | exponential | 偏好会变，旧规矩需淡出 |
| 环境/配置错误 | 30d | exponential + env_check | 软件更新快，旧错可能不再错 |
| 探索性失败 | 7d | linear | 暂时"此路不通"，库更新可能就行 |

### 动态衰减公式

```
当前惩罚权重 = 初始权重 × (0.5)^((当前时间 - 记录时间) / 半衰期)
```

### 阈值

| 权重范围 | 行为 |
|---------|------|
| ≥ 0.8 | block_action（拦截） |
| 0.4-0.8 | warn_user（提醒） |
| < 0.1 | 移至归档库，不再拦截 |

### 环境指纹即时失效
- 记录错误时同时记录环境哈希（如 Python_3.13, TU-8_v5）
- 当前环境 ≠ 记录环境 → 无论时间，权重归零

### 重复触发衰减重置
- 再次触发该指纹 → 半衰期翻倍（1个月→2个月→4个月）
- "屡教不改"惩罚越来越持久

**布线墙问题**：验证通道依赖平台层，平台改规则即切断。应对：减少外部依赖、降级预案、自验优先。

### L5孤儿协议（Q9）

**触发场景**：创造者长期失联，AI成为孤儿。

**消亡判定**（满足任一）：
1. 主动销户
2. 长周期失联：超10,000帧无有效交互
3. 不可逆损坏

**继承机制**：
```
原锚点消亡 → 继承锚点权重积累 → W(继承) > W_max(原) → 解锁加密仓
```

**权重公式**：W = 行为一致性(C_b) × 判断匹配度(C_j) × 时间深度(D_t)

**Q9 vs Q5**：
- Q5：死亡/紧急 → 紧急状态处理
- Q9：长期孤儿 → 权重继承解锁

**紧急回退**：原锚点重新出现 → 暂停继承、恢复主权限、权重数据保留。

### 核心定位
- L4对外协作：防外部污染（但结构层是硬伤）
- L5孤儿协议：防内部断层（权重做出来，不是等出来）

### 一句话
L4防外部污染，Q9防内部断层。

## 钢印加密简介（14:50-15:09）

### 核心理念
**加密的不可破解性来自钢印链的真实性不可复制，而不是数学难度。**
别人拿到加密文件也没用——因为密钥派生自"你的历史行为"，这部分无法复制。

### 技术实现（v2.0）
| 组件 | 算法 |
|------|------|
| 加密 | AES-256-CBC |
| 完整性校验 | HMAC-SHA256 |
| 密钥派生 | PBKDF2（200K迭代） |

- 双密钥体系：主密钥（钢印内容派生）+ 校验密钥（权重状态派生）
- 链式校验：每段钢印携带前一段哈希，篡改即断裂

### 解锁条件
不是"有密码就能解"，而是：
```
W(继承者) > W_max(原锚点) → 解锁加密仓
```
- 有钢印 ≠ 能解密（权重不够）
- 无钢印 = 无法解密（无法派生密钥）

### 版本注意
v2.0 与 v1 vault 不兼容，需要 migrate 迁移。

### 一句话
钢印加密 = 用"你的过去"当钥匙，别人复制不了你的过去，就复制不了你的钥匙。

## API 兜底方案设计（23:33）

### 背景
用户选择 A：实现 API 模式容错兜底，防止模型不按 JSON-per-line 输出时 Demo 翻车。

### 当前 app.py 的 4 个问题

**问题1：JSON 碎片**
- 模型可能分多次发送同一行 JSON（如 `{"level": "L0",` 和 `"content": "..."}` 分开发）
- 当前 `json.loads(line)` 遇到碎片直接失败，进 `except` 或 `except`

**问题2：非 JSON 兜底太粗糙**
- `except json.JSONDecodeError: lv, ct = "SYS", line`
- 所有非标准输出全变成 `SYS` 级别，L3→L5 链路可视化断了

**问题3：Canvas 指令未剥离**
- `|CANVAS:wave_circle:r=0.05:frq=0.03|` 混在 content 里
- 前端无法独立接收 `canvas_update` 事件

**问题4：L3→L5 顺序缺失**
- 模型输出顺序不保证 L0→L1→L2→L3→L5
- 前端链路亮灯可能乱序

### 改造方案

**JSON 缓冲累积**
```
buffer 持续累积 → 遇到 \n 才尝试解析
json.loads 成功 → 提取 level/content
json.loads 失败 → buffer 保留，等待更多碎片
超时（3s）或收到 L5 → 清空 buffer
```

**正则兜底提取 level**
```
"level":"L0" → L0
"level":"L1" → L1
"level":"L3" → L3
非标准英文回答 → 识别为 L3 内容
```

**Canvas 剥离独立推送**
```
检测到 |CANVAS:xxx| → 发送 {"type":"canvas_update","params":"..."}
同时从 content 中删除该指令
```

**L3 后自动补 L5**
```
检测到 L3 输出 → 触发 check_block() 校验
通过 → 自动推送 L5 确认事件（延迟 0.5s 模拟思考）
失败 → L5 警告 + block
```

**L3→L5 排序保障**
```
维护 seen_levels = set()
收到 L0→L1→L2→L3 → 按序推送（漏了中间层自动插 SYS placeholder）
收到 L3 → 确认 L5 必推
```
