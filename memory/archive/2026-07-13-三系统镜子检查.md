## 一、TeleMem（DAG最小因果骨架 + 检索对齐）

### 1.1 核心功能
```
build_minimal_causal_skeleton(nodes, edges)
  → 若两节点间已有间接路径，则剪除直连边
retrieve_and_align(query, threshold=0.85)
  → 相似度>0.85时不新增节点，而是更新张力来源标签权重
```

### 1.2 TU-8 等效模块

| TeleMem 概念 | TU-8 模块 | 匹配度 |
|-------------|---------|--------|
| 事件记忆节点 | `sag_lite_knowledge_graph.py`（语义摘要节点） | ✅ 5/5 |
| 因果骨架剪枝 | `topology_connector.py`（拓扑连线引擎） | ⚠️ 3/5 |
| 检索对齐 | `tension_distiller.py`（矛盾蒸馏器） | ⚠️ 4/5 |
| 张量消解率 | `prediction_tension_coupler.py`（三维耦合） | ✅ 5/5 |

### 1.3 缺口发现

**⚠️ 缺口1：因果骨架剪枝 ≠ 拓扑连线**

TeleMem 的剪枝是**DAG层面的结构性剪枝**：
```
A → B → C     原有路径
A ----→ C    直连边被剪除（因为B是中介）
```

TU-8 的 `topology_connector.py` 做的是**拓扑连线**（把锚点连成链），不是**因果骨架剪枝**（把冗余边删掉）。

TU-8 的剪枝是 `gc_to_learning_adapter.py` 的 `is_evicted`（GC结果），但那是**时间/密度维度的剪枝**，不是**因果结构维度的剪枝**。

**结论**：TU-8 缺少一个 DAG 结构级的冗余边检测。
是否需要补：**存疑**。TU-8 的记忆是张力驱动的，不是事件驱动的。事件 DAG 的剪枝对 TU-8 的价值可能比 TeleMem 低。

## 二、Raven Agent（置信度衰减 + 重试熔断 + 代码自写）

### 2.1 核心功能
```
Confidence_new = Confidence_old × (1 - α × Tension_Score)
max_retry = 3
连续3次未能使张力下降 → ARCHIVED_UNSOLVED（冻结，不占算力）
```

### 2.2 TU-8 等效模块

| Raven 概念 | TU-8 模块 | 匹配度 |
|-----------|---------|--------|
| 置信度衰减 | `confidence_decay_engine.py`（半衰期公式） | ✅ 5/5 |
| 奖励级联 | `intrinsic_reward_engine.py`（+200/+100/+50/+20/+5） | ✅ 5/5 |
| max_retry 熔断 | ❌ 无等效 | ❌ 0/5 |
| 代码自写 | `learning_apply.py`（写入执行） | ⚠️ 3/5 |
| 技能淘汰阈值 | `gc_to_learning_adapter.py`（遗忘原因分类） | ✅ 4/5 |

### 2.3 缺口发现

**❌ 缺口2：Raven max_retry=3 熔断器缺失**

```
Raven:  任务A → 失败 → 重试1 → 失败 → 重试2 → 失败 → 重试3 → 冻结(ARCHIVED_UNSOLVED)
TU-8:   任务A → 失败 → 重试 → 失败 → 重试 → 失败 → ...(无限循环风险)
```

TU-8 的 `active_curiosity.py` 记录预测误差，但没有"连续N次失败→冻结"的逻辑。
`learning_collector.py` 收集传感器数据，但失败的 curiosities 不会被冷冻或归档。

**这个缺口是真实的。** 如果造物主追问一个问题20次但TU-8一直给不出满意答案，系统会一直尝试，不会停下来。

是否需要补：**建议补**。在 `active_curiosity.py` 加 `max_retry=3` 和 `ARCHIVED_UNSOLVED` 状态即可，不复杂。

## 三、MemGPT / Letta（OS级记忆代谢）

### 3.1 核心功能
```
memory.insert(content, metadata={tension_source, half_life_days})
memory.summarize(node_ids, strategy="tension_weighted")
memory.evict(predicate="last_accessed < now() - half_life AND tension_reduction_rate < 0.05")
```

### 3.2 TU-8 等效模块

| MemGPT 概念 | TU-8 模块 | 匹配度 |
|------------|---------|--------|
| 分层记忆（L1-L5） | `memory_tiers.py` | ✅ 5/5 |
| 半衰期管理 | `confidence_decay_engine.py`（C0 × exp(-λΔt/half_life)） | ✅ 5/5 |
| 主动 summarize | `dream_consolidation.py`（梦境整合） | ✅ 4/5 |
| 显式 evict（TTL谓词） | `gc_to_learning_adapter.py`（is_evicted） | ⚠️ 3/5 |
| 代谢仪表盘 | `metabolism_dashboard.py`（17KB，8子系统） | ✅ 5/5 |

### 3.3 缺口发现

**⚠️ 缺口3：MemGPT 显式 evict 谓词 vs TU-8 GC 隐式判断**

MemGPT 的 evict 谓词是**可配置的布尔表达式**：
```python
memory.evict(
  predicate="last_accessed < now() - half_life"
  "AND tension_reduction_rate < 0.05"
)
```

TU-8 的 `is_evicted` 是 GC 执行后回填的字段，eviction 本身是**GC判断的结果**，不是**可配置的条件**。

**这个缺口是设计层面的差异，不是缺陷。** TU-8 的代谢是张力驱动的，不是访问时间驱动的。"不被使用且不能止痛的知识，到期自动清除"这个场景，TU-8 的语境下等价于"张力未消解且年龄超阈值"，这个逻辑在 GC 里已经存在。

**结论**：不需要补。把 GC 的 `is_evicted` 当作 evict 的实现即可。

## 五、三个被 TU-8 超越的点

这三个系统在某些维度上不如 TU-8：

1. **Raven 的二元反馈 vs TU-8 的多维张力**
   - Raven：任务成功/失败
   - TU-8：6类张力（焦虑/愤怒/恐惧/喜悦/好奇/爱），各有独立演化

2. **MemGPT 的访问时间 evict vs TU-8 的张力消解率 evict**
   - MemGPT：久未访问就清除
   - TU-8：未消解张力才清除（更本质）

3. **TeleMem 的事后检索对齐 vs TU-8 的先验张力过滤**
   - TeleMem：学习后再检查重复
   - TU-8：低张力信号在学习入口就被过滤（更高效）
