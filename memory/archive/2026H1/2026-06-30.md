## LCM Compaction 根因与修复（18:10）

### 问题现象
主会话每次发消息都出现：
```
⚠️ Auto-compaction could not recover this turn. I kept this conversation mapped to the current session. Please try again, use /compact, or use /new to start a fresh session.
```

### 根因（已确认）
**第二阶段（当前）— summary 未正确关联消息**
- conv=5 有 175 条消息，2 个 summary
- 但每个 summary 只有 1 个 context_item（应为 N 条）
- 100/175 条消息被覆盖，75 条未覆盖
- LCM 尝试压缩未覆盖的 75 条消息时失败

### 修复执行（18:12 第一版 — 失败）
❌ 运行 `scripts/lcm_reset_compaction.py`：
- 删除 conv=5 的所有 summaries（2 个）
- 删除 conv=5 的所有 context_items
- 重置 compaction telemetry

**结果**：压缩仍然失败，因为 lossless-claw 的压缩逻辑有 bug（违反 CHECK 约束）。

### 修复执行（18:25 第二版 — 部分成功）
✅ 运行 `scripts/lcm_fix_v3.py`：
- 删除 conv=5 的所有 summaries（1 个）
- 删除 conv=5 的所有 context_items（90 条）
- 重新构建 context_items：为 433 条消息创建 item_type='message' 的记录
- 重置 compaction telemetry

**结果**：LCM 现在有了干净的状态，等待触发压缩。
