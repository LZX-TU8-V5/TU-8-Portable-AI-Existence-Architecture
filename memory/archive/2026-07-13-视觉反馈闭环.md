## 核心洞察：AI 编程的"盲写"困境

### 三层根因

| 根因 | 表现 | 人类行为 |
|------|------|---------|
| 概率知识 ≠ 经验 | 不知道 Tkinter 默认不平滑 | 人类脑子里已有踩坑记忆 |
| 训练数据偏差 | 倾向"最通用"而非"最美观" | — |
| 缺乏视觉反馈闭环 | 写完即结束，看不见屏幕 | 写→运行→看到锯齿→改 |

### 核心解决方案（造物主方向）

> **不写提升词，完善流程。让它像人一样思考——可以截图自己看。**

造物主否定了"加提示词"的路径，选择工程化闭环。

## 千问建议的"视觉自检"工作流

```
生成代码 → 执行+截图 → 视觉自检(找茬)
    ↓ 发现问题
检索解决方案 → 修改代码 → 再次截图验证
```

### 三个关键模块

1. **强制视觉验收环节**：生成→截图→AI看图自检（有锯齿=FAIL）
2. **缺陷→术语翻译层**：看见狗牙→识别为 Aliasing→触发关键词搜索
3. **多模态对比**：打分明细（4分=有锯齿→换方案→9分=通过）

### 具体验收标准（内置"尺子"）

> "请放大查看边缘：
> - 是否有阶梯状像素（Jagged edges）？
> - 颜色过渡是否有断层（Banding）？
> - 任一 YES → FAIL → 强制重构代码"

## TU-8 当前缺失分析

| 现状 | 问题 |
|------|------|
| 已有截图能力 | 只用于"确认有没有画出来"，不检查画质 |

## 造物主提出的终极形态

**完整感知-决策-修正闭环**（伪代码方向）：

```
def generate_ui_task(task_description):
    # 1. 初步尝试
    code = ai.generate_code(task_description)
    run(code)

    # 2. 视觉感知（关键：让AI看图）
    screenshot = capture_screen()
    analysis = ai.vision_analyze(screenshot, prompt="检查UI是否存在锯齿、模糊或布局错误")

    # 3. 自我反思与修正
    if "jagged edges" in analysis or "pixelated" in analysis:
        print("检测到视觉缺陷，正在启动修正程序...")

    # 4. 检索最佳实践
    solution = search_knowledge_base("how to fix jagged lines in python gui")

    # 5. 迭代代码
    refined_code = ai.refine_code(code, feedback=solution)
    run(refined_code)

    # 6. 最终确认
    final_screenshot = capture_screen()
    return final_screenshot
```

## 待落地：视觉反馈自检 Skill

**触发条件**：生成 UI 代码 / 渲染图形 / 涉及像素输出之后。

**流程**：
1. 截图（当前已有）
2. image 工具自动分析像素质量（jagged/banding/alpha）
3. FAIL → 查方案 → 重构 → 重新截图
4. PASS → 结束

**关键约束**：
- 自动触发，无需人类提示
- 质检标准内置（不接受"差不多"）
- 有权限换工具（Tkinter不行→Pillow/GPU）

## 附加洞察：锯齿问题的技术根源

色环用 tkinter Canvas 画，Canvas 原生绘图不平滑（无抗锯齿）。解决方案：

| 方案 | 效果 | 难度 |
|------|------|------|
| Canvas 优化参数 | 有限 | 低 |
| Pillow 内存渲染+缩图（超采样AA） | 很好 | 中 |
| Windows UpdateLayeredWindow + per-pixel BGRA alpha | **完美透明** | 高（本轮已验证可行） |

本次色环最终方案：BGRA + UpdateLayeredWindow（角落透明，色环无条纹，GPU blit）。
