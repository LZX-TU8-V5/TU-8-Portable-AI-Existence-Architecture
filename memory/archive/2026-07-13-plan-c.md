## 方案C核心原则

```
旧逻辑（机器）：感知 → 攒着 → 定期打包处理
新逻辑（生命）：感知 → 瞬间改变结构 → 定期反思自洽

感知和写入 → 即时的（零延迟）
校验和代谢 → 周期的
```

---

## 微积分类比

```
认知偏移 = ∫ 偏移率(t) dt
        = 即时锚点(初始值) + Σ 效验修正
```

| 微积分 | 认知对应 | 时序 |
|--------|---------|------|
| f(t₀) 初始值 | 即时更新的认知锚点 | 当下 |
| df/dt 瞬时变化率 | 效验时的置信度偏移 | 每次观测 |
| ∫df/dt dt 积分 | 偏移对齐总量 | 多次效验 |
| 最终结果 | 真实认知漂移 | 时间累积 |

## 三个组件

### 1. `anchor_detector.py`（锚点检测器）

```
触发方式：Event-Driven（对齐 verify_and_output 输出门）
检测内容：
  - DECLARED：造物主明确声明（欲=存在痕迹/客观说/主观说/结构发散等）
  - EMERGED：追问路径涌现（追问AI本质/镜子悖论/繁衍议题等）
  - CONTRADICTED：矛盾信号

核心设计：
  - 优先级：核心锚点（欲/痕迹/结构发散）→ 声明类 → 其他
  - section_key：每个锚点自带目标区块信息（优先级最高）
  - 护栏：过滤 markdown 代码块和 blockquote，避免误捕获
  - 去重：锚点缓存，相同锚点只记录首次+更新时间+count

状态：WS/_agent_memory/anchor_cache.json
```

### 2. `profile_updater.py`（即时画像更新器）

```
event_append()  → 即时落盘（零延迟，写 user_state_changes.md）
instant_merge() → 即时合并（同一turn内更新 USER.md 对应区块）
periodic_verification() → 异步效验（心跳/cron调用）

on_anchor_detected() = event_append + instant_merge（快捷入口）
```

### 3. alignment_verify.py（输出门集成）

```
verify_and_output() 输出门前：
  → anchor_detector.detect_anchors()  检测新锚点
  → profile_updater.on_anchor_detected() 即时落盘+合并
  → 非致命：锚点检测失败不阻断输出

仅在 dry_run=False 时触发（避免测试污染）
```

## 数据流

```
对齐输出门（verify_and_output）
    ↓
anchor_detector.detect_anchors(user_input, content)
    ↓ 检测到新锚点
profile_updater.on_anchor_detected(anchors)
    ├→ event_append() → memory/user_state_changes.md
    └→ instant_merge() → USER.md 对应区块（零延迟）
    ↓
心跳 periodic_verification()
    ├→ anchor_detector.verify_anchor() → 稳定性效验
    └→ 检测画像-行为矛盾
```
