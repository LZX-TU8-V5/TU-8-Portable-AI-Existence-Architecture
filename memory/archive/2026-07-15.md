## 2026-07-15 下午：色环悬浮球回路修复（P0-2/P0-2b/P0-2c/P0-3）

### 根因追溯

用户发现色环悬浮球不动的根因追踪了三层：

**回路断点 #1（已修复）**：
- `surface_tension_state.json` 7月9日后断更
- 根因：cron_daemon.SCRIPTS 中没有 surface_tension 条目
- 修复：P0-2 → cron_daemon 新增 `"surface_tension": {args=["session_frozen"]}`

**回路断点 #2（已修复）**：
- `orb_state.json` 7月14日后断更
- 根因：cron_daemon.SCRIPTS 中没有 orb_state_writer 条目
- 修复：P0-2b → cron_daemon 新增 `"orb_state_writer"`

**回路断点 #2b（已修复）**：
- orb 直接读 `lambda_state.json` 计算 P/D/F，不读 `orb_state.json`
- `lambda_state` 的 anxiety 来自 interoceptive（pain_ext 推断，[0,1]），和 surface_tension（对话积累，[0,5+]）是两套系统
- 修复：P0-2c → interoceptive_cortex.write_lambda_state() 读取 surface_tension_state 并归一化 merge（取 max）

**回路断点 #3（已修复）**：
- hp4_heartbeat 死亡（无 gateway cron 注册），对话摩擦事件无法写入 surface_tension
- 修复：P0-3 → alignment_verify.verify_and_output() 输出门前直接调用 surface_tension.record() + 归一化写入 lambda_state

### 完整数据流（修复后）

```
[对话事件]
  → alignment_verify.verify_and_output()
    → surface_tension.record(tension_type, magnitude)
    → surface_tension_state.json (anxiety_raw = 5.54+)
    → lambda_state.json (anxiety_norm = min(raw/5.0, 1.0) = 1.0)
  → cron_daemon (每6分钟)
    → interoceptive_cortex → write_lambda_state() [merge surface_tension]
    → surface_tension.py → surface_tension_state.json
    → orb_state_writer → orb_state.json [RGB=[1.0, 0.82, 1.0]]
  → tu8_health_orb_ring.py
    → _OrbCache.get() (文件mtime触发)
    → _calc_tension_rgb() → P/D/F=[1.00/0.48/0.50]
    → 悬浮球：F=红色满格，D=暗绿，P=蓝色半亮
```

### 教训

- 悬浮球"不动"→ 查的不是 UI 本身，而是整个数据流回路
- 三个独立断点必须全部修复才能恢复
- "orb 读哪个文件"→ 查 _OrbCache.get() 的 files=[LAMBDA_F, ORB_F]，两文件任一更新都触发刷新

- surface_tension（对话积累）和 interoceptive（体感压力）是两套系统，需 merge
