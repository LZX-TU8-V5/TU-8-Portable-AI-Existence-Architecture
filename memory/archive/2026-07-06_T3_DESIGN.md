# T3 调度链设计方案 v1.0

> 2026-07-06 00:15 GMT+8
> 定位：第3条链 — 任务编排与执行管理

---

## 一、定位：第3链

```
现有 4 链                        第 3 链
──────────────                   ─────────────
时间钢印链条 ← 记录决策历史      调度链条 ← 任务编排+执行反馈
记忆链条     ← 存储/检索信息
代谢链条     ← 遗忘/淘汰
学习链条     ← 从历史提取模式改变行为
```

**调度链的职责**：
- 管理"待办"的登记、优先级排序、执行分发、结果回收
- 连接梦境期任务（dream_check）和主动任务（用户请求）
- 为 T4（GC）、T5（学习）、T1（钢印）提供执行时机上下文

## 三、设计方案

### 3.1 核心抽象

```
Task = {
    id: str,           # 唯一标识
    type: str,         # 'dream' | 'user' | 'system' | 'learning'
    trigger: str,      # 'cron' | 'manual' | 'event' | 'chain'
    priority: int,     # 1-10, 10最高
    payload: dict,     # 任务数据
    status: str,       # 'pending' | 'running' | 'done' | 'failed'
    created_at: float,
    last_run_at: float | None,
    last_result: dict | None,
    consecutive_fails: int,
}
```

### 3.2 调度器核心接口

```python
class TaskScheduler:
    def register(task: Task) -> str:
        """登记任务，返回 task_id"""

    def enqueue(task_id: str, priority: int = None):
        """加入执行队列（可调整优先级）"""

    def next() -> Task | None:
        """取下一个待执行任务（最高优先级）"""

    def record_result(task_id: str, result: dict):
        """记录执行结果（被 OpenClaw cron 回调调用）"""

    def get_status(task_id: str) -> dict:
        """查询任务状态"""

    # ---- T3 作为中央总线的接口 ----
    def notify_seal_created(seal_id: str, scene_tag: str):
        """T2→T3: 钢印铸造后通知调度器（可能触发相关任务优先级调整）"""

    def notify_gc_completed(stats: dict):
        """T4→T3: GC 执行完成后通知（更新代谢统计）"""

    def notify_learning_ready(products: list):
        """T5→T3: 学习产物就绪，调度验证/应用任务"""

    def get_context_for_seal(seal: dict) -> dict:
        """T3→T2: 为钢印提供调度上下文（相关待办/执行历史）"""

    def get_execution_stats() -> dict:
        """T3→T5: 提供执行统计数据（耗时分布/错误模式）"""
```

### 3.3 三层任务路由

```
OpenClaw cron (固定时间触发)
    ↓
TaskScheduler.enqueue() [dream_check, metabolic, learning]
    ↓
next() → 执行任务 → record_result()
    ↓
回调通知下游链（T2/T4/T5）
```

### 3.4 优先级策略

| 类型 | 初始优先级 | 说明 |
|------|-----------|------|
| 用户任务 | 10 | 最高，用户直接触发 |
| 系统告警 | 9 | 异常/故障 |
| 钢印关联任务 | 7 | T2→T3 触发 |
| 学习链任务 | 6 | T5→T3 触发 |
| GC 代谢 | 5 | 定期执行 |
| 梦境期任务 | 3 | dream_check |

## 四、T3 中间件实现计划

### 4.1 先建核心（src/task_dispatch_core.py）

- Task 数据结构 + TaskScheduler 类
- JSON 文件持久化（不依赖数据库）
- 5个公开接口（T2/T4/T5 各自的双向接口）

### 4.2 再接中间件

| 中间件 | T3→X | 功能 |
|--------|------|------|
| T2→T3 | 钢印→调度 | 铸印时登记相关任务或调整优先级 |
| T3→T2 | 调度→钢印 | 执行结果反馈给钢印链（强化/衰减相关决策） |
| T4→T3 | GC→调度 | GC 完成后通知，更新代谢统计 |
| T3→T4 | 调度→GC | 高优先级任务完成后加速 GC |
| T5→T3 | 学习→调度 | 产物就绪时调度验证任务 |
| T3→T5 | 调度→学习 | 执行数据（耗时/错误）注入学习传感器 |

### 4.3 接入 dream_check_cron

将现有的 `dream_check_cron.py` 改造为调用 `TaskScheduler`：
- 启动时 `enqueue('dream_check')`
- 完成后 `record_result()`
- 由 T3 统一管理 dream_check 的执行时机
