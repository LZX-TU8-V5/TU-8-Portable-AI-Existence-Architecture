## 一、流转图（Mermaid）

```mermaid
stateDiagram-v2
    [*] --> DISTILLING_T2

    state DISTILLING_T2 {
        [*] --> GUARD_CHECK
        GUARD_CHECK --> COST_ACCOUNTING : [所有Guard通过]
        GUARD_CHECK --> BROKEN_OUT : [Sanity Guard FAIL]
        GUARD_CHECK --> BREAKTHROUGH_T2 : [Tension Guard FAIL: T >= θ_H]
        GUARD_CHECK --> DROPPED : [Sanity Guard FAIL: C/δ越界]

        note for GUARD_CHECK
            "物理锁：所有Guard必须同时通过\n
             任一失败 → 对应路径强制跳转\n
             不允许跳过"
    }

    state BROKEN_OUT {
        [*] --> BROKEN_record
        BROKEN_record --> BROKEN_logged : [记录: cost+=1, reason=broken]
        BROKEN_logged --> COST_ACCOUNTING
    }

    state BREAKTHROUGH_T2 {
        [*] --> BREAKTHROUGH_apply
        BREAKTHROUGH_apply --> BREAKTHROUGH_record : [强制纠错ΔC = -(0.25+0.30T)]
        BREAKTHROUGH_record --> BREAKTHROUGH_logged : [记录: cost+=1, mode=breakthrough]
        BREAKTHROUGH_logged --> COST_ACCOUNTING
    }

    state DROPPED {
        [*] --> DROP_log
        DROP_log --> DROP_recorded : [记录: cost+=1, reason=dropped, node=removed]
        DROP_recorded --> [*] : [物理删除节点，状态机终止]
    }

    COST_ACCOUNTING --> TRANSITION_NEXT : [cost已记录]
    COST_ACCOUNTING --> COST_BLOCKED : [cost未记录]

    COST_BLOCKED --> [*] : [物理锁死，无法流转]

    TRANSITION_NEXT --> T3_BREATHER : [进入下一阶段]
    TRANSITION_NEXT --> [*] : [节点处理完毕]
```

### 流转规则（物理约束）

| 触发条件 | 目标状态 | 法则 |
|---------|---------|------|
| Sanity PASS + Tension < 0.80 | `COST_ACCOUNTING` → `T3` | 法则1 |
| Sanity FAIL (NaN/Infinity/C越界) | `DROPPED` | 法则1 |
| Tension ≥ 0.80 | `BREAKTHROUGH_T2` | 法则2 |
| cost 未记录 | `COST_BLOCKED`（锁死） | 法则3 |

## 二、状态机核心伪代码

### 三法则 → 三道物理锁

```python
"""
三法则在状态机里的物理实现
不是注释，不是文档，是强制前置条件（Pre-condition）
违反 → 物理锁死，不流转
"""


# ═══════════════════════════════════════════════════════════
# 法则1：边界即防线
# 对应：GUARD_CHECK 阶段
# ═══════════════════════════════════════════════════════════
class SanityGuard:
    """
    法则1的物理实现

    在状态机中，这个检查不是"if判断"，是"物理锁"。
    检查失败 → 状态机无法进入 COST_ACCOUNTING
    → 只能进入 DROPPED 路径
    → 节点物理上从状态机中移除
    """

    LOCK_NAME = "LAW1_BOUNDARY"

    def check(self, node: DreamNode, delta: float) -> GuardResult:
        """
        返回值决定状态机物理流向：
          PASS → 允许进入 COST_ACCOUNTING
          FAIL → 强制跳转到 DROPPED 路径
        """
        import math

        C = node.confidence
        cost_recorded = False

        # ── 检查1：delta 是 NaN / Infinity ──────────────────
        if math.isnan(delta) or math.isinf(delta):
            return GuardResult(
                pass_=False,
                target_state="DROPPED",
                law="LAW1",
                reason="delta_non_numeric",
                cost_impact=1,
                detail=f"C={C}, delta={delta}",
            )

        # ── 检查2：C 不在 [0, 1] ───────────────────────────
        if not (0.0 <= C <= 1.0):
            return GuardResult(
                pass_=False,
                target_state="DROPPED",
                law="LAW1",
                reason="confidence_out_of_bounds",
                cost_impact=1,
                detail=f"C={C}",
            )

        # ── 检查3：|delta| > 1.0（单次更新不可能）─────────
        if abs(delta) > 1.0:
            return GuardResult(
                pass_=False,
                target_state="DROPPED",
                law="LAW1",
                reason="delta_excessive",
                cost_impact=1,
                detail=f"|delta|={abs(delta)}",
            )

        # ── 检查4：delta 与 C 变化方向矛盾（逻辑检查）─────
        # 例如：C=0.1, delta=-0.05 → C_new=0.05（合理，信心下降）
        # 例如：C=0.1, delta=+0.05 → C_new=0.15（合理，信心上升）
        # 但如果 delta 符号和逻辑矛盾（如 C=0.99 且 delta>0.1 且无breakthrough理由）
        C_new = C + delta
        if not (0.0 <= C_new <= 1.0):
            return GuardResult(
                pass_=False,
                target_state="DROPPED",
                law="LAW1",
                reason="post_update_out_of_bounds",
                cost_impact=1,
                detail=f"C={C}, delta={delta}, C_new={C_new}",
            )

        # ── 全部通过 ────────────────────────────────────────
        return GuardResult(
            pass_=True,
            target_state="COST_ACCOUNTING",
            law="LAW1",
            reason="sanity_ok",
            cost_impact=0,
            detail=None,
        )


# ═══════════════════════════════════════════════════════════
# 法则2：稳态是例外
# 对应：BREAKTHROUGH_T2 分支
# ═══════════════════════════════════════════════════════════
class TensionGuard:
    """
    法则2的物理实现

    当 T >= θ_H，状态机物理上必须进入 BREAKTHROUGH_T2 路径
    没有"跳过"选项——这是强制路径，不是可选分支

    锁死条件：如果系统在 T >= θ_H 时尝试绕过 BREAKTHROUGH_T2
              → COST_ACCOUNTING 拒绝接收，状态机卡死
    """

    LOCK_NAME = "LAW2_BREAKTHROUGH"
    THETA_HOMEOSTATIC = 0.80  # 稳态打破阈值

    def check(self, T: float) -> GuardResult:
        """
        两种结果：
          PASS：T < θ_H → 正常稳态路径
          FAIL：T >= θ_H → 必须进入 BREAKTHROUGH_T2
                （FAIL 在这里不是"错误"，是"特殊路径触发"）
        """
        if T >= self.THETA_HOMEOSTATIC:
            return GuardResult(
                pass_=False,  # 故意 FAIL，触发特殊路径
                target_state="BREAKTHROUGH_T2",
                law="LAW2",
                reason="homeostatic_break",
                cost_impact=1,
                detail=f"T={T:.3f} >= θ_H={self.THETA_HOMEOSTATIC} → 强制纠错",
                mode="breakthrough",
            )
        else:
            return GuardResult(
                pass_=True,
                target_state="COST_ACCOUNTING",
                law="LAW2",
                reason="normal_tension",
                cost_impact=0,
                detail=f"T={T:.3f} < θ_H={self.THETA_HOMEOSTATIC}",
                mode="normal",
            )


# ═══════════════════════════════════════════════════════════
# 法则3：隔离有代价
# 对应：COST_ACCOUNTING 阶段
# ═══════════════════════════════════════════════════════════
class CostAccountingGuard:
    """
    法则3的物理实现

    在状态机流转到下一状态之前，cost_counter 必须已更新
    如果 cost 未记录 → COST_BLOCKED 状态
    → 状态机物理上锁死，无法流转

    这是最强的物理锁：其他 Guard 失败还可以走特殊路径
    COST_ACCOUNTING 未完成 → 彻底卡死
    """

    LOCK_NAME = "LAW3_COST"

    def check(self, node: DreamNode, guard_result: GuardResult,
              cost_state: CostState) -> GuardResult:
        """
        前置条件：
          每个 DROPPED、BROKEN_OUT、BREAKTHROUGH_T2 事件
          必须在 cost_counter 中有对应的 +1 记录

        物理锁：
          如果 cost_state.cost_last_node != cost_state.cost_expected
          → 拒绝流转，状态机卡死
        """
        cost_impact = guard_result.cost_impact

        if cost_impact == 0:
            # 无代价事件，正常流转
            return GuardResult(
                pass_=True,
                target_state="TRANSITION_NEXT",
                law="LAW3",
                reason="no_cost",
                cost_impact=0,
                detail="无隔离代价，状态机正常流转",
            )

        # 有代价 → 必须验证 cost 已记录
        # 读取 cost_state，如果最后一次 cost 记录不是 +1 → 锁死
        if not cost_state.last_recorded(node.entry_id, cost_impact):
            # 物理锁死：cost 未记录，状态机无法流转
            return GuardResult(
                pass_=False,
                target_state="COST_BLOCKED",  # 锁死状态
                law="LAW3",
                reason="cost_not_recorded",
                cost_impact=0,
                detail=(
                    f"节点 {node.entry_id} 产生 cost_impact={cost_impact}，"
                    "但 cost_counter 未更新——状态机锁死，等待人工介入"
                ),
            )

        return GuardResult(
            pass_=True,
            target_state="TRANSITION_NEXT",
            law="LAW3",
            reason="cost_recorded",
            cost_impact=cost_impact,
            detail=f"cost={cost_impact} 已记录，状态机流转",
        )


# ═══════════════════════════════════════════════════════════
# 状态机主体
# ═══════════════════════════════════════════════════════════
@dataclass
class GuardResult:
    """Guard 返回值——决定状态机的物理流向"""
    pass_: bool
    target_state: str
    law: str          # 哪个法则触发
    reason: str       # 具体原因
    cost_impact: int # 产生多少隔离代价
    detail: Optional[str]
    mode: str = "normal"  # breakthrough / normal


class T2StateMachine:
    """
    T2 阶段状态机
    三法则 = 三道物理锁，嵌入状态机的每个流转节点
    """

    def __init__(self):
        self.sanity = SanityGuard()
        self.tension = TensionGuard()
        self.cost = CostAccountingGuard()
        self.cost_state = CostState()
        self.node_registry: Dict[str, DreamNode] = {}

    def process(self, node: DreamNode, ctx: DreamSignalContext) -> ProcessResult:
        """
        状态机主入口
        每次调用 = 一次完整的物理流转
        """

        # ═══ 阶段1：GUARD_CHECK（所有Guard并行检查）══════════════
        # 计算 delta（在 Guard 检查之前先算出来）
        delta = self._compute_delta(node, ctx)

        sanity_result = self.sanity.check(node, delta)
        tension_result = self.tension.check(ctx.tension_resolved or 0.0)

        # ── Guard 并行检查结果路由 ────────────────────────────
        if not sanity_result.pass_:
            # → 法则1：Sanity FAIL → DROPPED
            return self._drop_node(node, sanity_result)

        if not tension_result.pass_:
            # → 法则2：Tension ≥ θ_H → BREAKTHROUGH_T2
            return self._breakthrough_node(node, tension_result)

        # ═══ 阶段2：COST_ACCOUNTING（代价核算）═════════════════
        # 正常路径：先记录 cost，再流转
        cost_guard_result = self.cost.check(node, sanity_result, self.cost_state)

        if not cost_guard_result.pass_:
            # → 法则3：cost 未记录 → 物理锁死
            return ProcessResult(
                state="COST_BLOCKED",
                node=node,
                cost_blocked=True,
                lock_reason=cost_guard_result.reason,
                detail=cost_guard_result.detail,
            )

        # ═══ 阶段3：流转到下一状态 ═══════════════════════════
        # 三道锁全部通过 → 物理上允许流转
        self._record_cost(node, cost_impact=0)  # 正常节点 cost=0
        return self._transition_next(node)

    def _drop_node(self, node: DreamNode, reason: GuardResult) -> ProcessResult:
        """
        DROPPED 路径（法则1触发）
        物理操作：节点从 node_registry 移除，状态机终止
        """
        # ── 法则3强制：cost 必须记录 ─────────────────────────
        self._record_cost(node, cost_impact=1, reason=reason.reason)
        self.cost_state.assert_recorded(node.entry_id, 1)

        # ── 物理删除 ───────────────────────────────────────────
        if node.entry_id in self.node_registry:
            del self.node_registry[node.entry_id]

        return ProcessResult(
            state="DROPPED",
            node=node,
            dropped=True,
            reason=reason.reason,
            law=reason.law,
            cost_recorded=True,
            detail=f"节点被移除。代价={reason.cost_impact}。{reason.detail}",
        )

    def _breakthrough_node(self, node: DreamNode, reason: GuardResult) -> ProcessResult:
        """
        BREAKTHROUGH_T2 路径（法则2触发）
        物理操作：强制纠错计算，状态机继续流转
        """
        T = reason.detail.split("T=")[1].split(" ")[0]  # 提取T值
        T_val = float(T)

        # 强制纠错计算（已在 TensionGuard 中标记 mode=breakthrough）
        delta_breakthrough = -(0.25 + 0.30 * T_val)

        # ── 法则3强制：cost 必须记录 ─────────────────────────
        self._record_cost(node, cost_impact=1, reason="breakthrough")
        self.cost_state.assert_recorded(node.entry_id, 1)

        # ── 物理应用 ───────────────────────────────────────────
        node.confidence += delta_breakthrough

        return ProcessResult(
            state="BREAKTHROUGH_T2",
            node=node,
            breakthrough=True,
            reason=reason.reason,
            law="LAW2",
            delta_applied=delta_breakthrough,
            cost_recorded=True,
            detail=(
                f"强制纠错：T={T_val:.3f} >= θ_H=0.80。"
                f"ΔC={delta_breakthrough:.3f}。"
                f"C_new={node.confidence:.3f}。"
                f"代价={reason.cost_impact}（已记录）"
            ),
        )

    def _transition_next(self, node: DreamNode) -> ProcessResult:
        """
        TRANSITION_NEXT（全部通过）
        状态机流转到 T3 阶段
        """
        return ProcessResult(
            state="TRANSITION_NEXT",
            node=node,
            cost_recorded=True,
            detail="三法则全部通过，状态机流转至T3",
        )

    def _compute_delta(self, node: DreamNode, ctx: DreamSignalContext) -> float:
        """计算delta（委托给 updater 的数学内核）"""
        # 这里可以调用 SynapticConfidenceUpdater 的计算逻辑
        if ctx.track == "track_A":
            alpha = 0.2
            return alpha * (1 - node.confidence) * (ctx.activation_strength or 0.5)
        else:
            # 通路B：带强制纠错的版本
            T = ctx.tension_resolved or 0.0
            if T >= 0.80:
                return -(0.25 + 0.30 * T)
            else:
                return 0.10 + 0.30 * T * node.confidence * (1 - node.confidence)

    def _record_cost(self, node: DreamNode, cost_impact: int,
                     reason: str = "normal"):
        """法则3强制：每次隔离事件必须记录代价"""
        self.cost_state.record(
            entry_id=node.entry_id,
            cost=cost_impact,
            reason=reason,
            ts=time.time(),
        )

    def get_state_cost_report(self) -> dict:
        """
        法则3：状态机成本透明度报告
        任何时刻可查询：产生了多少代价，流向了哪里
        """
        return self.cost_state.summary()
```

## 三、关键设计：什么使它成为"物理锁"

### vs 注释版Guard

| 维度 | 注释版 Guard | 状态机物理锁版 |
|------|-------------|--------------|
| 失败后果 | 警告/日志，继续执行 | 状态机跳转，物理隔离 |
| 流转控制 | if语句，可绕过 | GuardResult决定，不可达代码无法绕过 |
| 代价记录 | 可选 | `assert_recorded()` 失败则异常 |
| 可追溯 | 事后查日志 | 状态机内嵌，`get_state_cost_report()` 实时查询 |
| 扩展性 | 加if | 加新 Guard 类，状态机无需改 |

### 物理锁的三种形态

```python
# 锁1：Sanity FAIL → 只能到 DROPPED
if not sanity_result.pass_:
    return self._drop_node(...)  # 物理删除，无其他出口

# 锁2：Tension >= θ_H → 只能到 BREAKTHROUGH_T2
if not tension_result.pass_:  # FAIL 在这里是"特殊路径触发"
    return self._breakthrough_node(...)  # 物理纠错，无其他出口

# 锁3：cost 未记录 → COST_BLOCKED（彻底卡死）
self.cost_state.assert_recorded(...)  # 失败则抛出异常
```

## 五、与 P1-D0 v1.1 Facade 的关系

```
P1-D0 v1.1 Facade（流程层）
    │
    └── process_dream_signal()
            │
            ├── 阶段路由（DreamPhase）
            ├── 冷却检查
            └── 数学计算
                    │
                    ▼
            T2StateMachine（物理锁层） ← 新增
                    │
                    ├── SanityGuard [法则1] ─→ DROPPED
                    ├── TensionGuard [法则2] ─→ BREAKTHROUGH_T2
                    └── CostAccountingGuard [法则3] ─→ COST_BLOCKED

关系：Facade 是"门卫"，状态机是"锁"
       Facade 决定"能不能进门"
       状态机决定"进门后发生什么"
```
