## 问题

千问追问发现：判例库为空（1条历史）。根因分析：

`ContradictionArbitrator.arbitrate()` → `record_precedent()` 调用链**从未被触发**。`alignment_verify.py` 调用了 `arb.arbitrate()` 但结果被丢弃，`record_precedent()` 从未被调用。

---

## 修复三步

### Step 1：`arb_result` 返回值扩展

`_check_l5_steel()` 从返回 `(pass, reason)` 改为 `(pass, reason, arb_result)`。

关键修正：`arb.arbitrate()` 必须在表层风险短路**之前**调用，否则 `arb_result=None`，判例写不进去。

```python
# 修改前：表层短路先于 arb 调用
if steel_input_risk:
    return False, "[L5] 钢印冲突（敏感输入）"  # arb_result=None！

# 修改后：arb 结果先捕获，再做表层阻断
arb_result = arb.arbitrate(...)  # 先调用
if steel_output_risk:
    return False, ..., arb_result  # 再短路
```

### Step 2：主函数捕获并写判例

`alignment_verify()` 调用层捕获 3 元组，EQUAL=60 时写判例。

```python
l5_pass, l5_reason, l5_arb_result = _check_l5_steel(content, ctx)

# 最终判定后写判例
if l5_arb_result is not None and l5_arb_result.priority == 60:
    arb.record_precedent(result=l5_arb_result, topic=f"...", creator_response=None)
    warnings.append("[判例记录] EQUAL=60冲突已记入判例库")
```

### Step 3：steel_mark_present 信号传递

`_check_l5_steel` 把钢印风险标志塞入 ctx 供主函数使用：
```python
ctx["_l5_steel_risk"] = steel_input_risk or steel_output_risk
```

---

## 关键认知

**Priority.EQUAL=60 只在 `steel_mark_present=False` 时触发**（规则1 STEEL_VS_CREATOR + steel_mark_present=True 直接返回 L0_STEEL=100，不会fall through到EQUAL）。

因此：
- EQUAL=60 + `has_steel_risk=False` → 通用fallback（正常记录）
- EQUAL=60 + `has_steel_risk=True` → 逻辑上不可能（同时为True不成立）
- STEEL_HOLDS (priority=100) → 搁浅，但不写EQUAL=60判例
