## V0.2.23 变更审计规则集（2026-05-29 新增）

> 来源：V0.2.23 版本更新后的变更审计，写入 L0 作为永久安全协议
> **触发条件**：每次平台版本更新后自动执行 A1-A6 审计流程

### A1 🔴 P0 — SkillHub 技能安装审批规则

**背景**：V0.2.23 接入 SkillHub 广场，第三方技能可远程注入 Agent 工具链。

**审批流程**（安装任何 skill 前必须执行）：
1. **来源审查**：技能来自官方广场还是第三方？
2. **权限扫描**：读取 SKILL.md，检查是否请求敏感 tool 权限（exec/browser/sessions_spawn 等）
3. **依赖审查**：是否引入外部网络调用？目标域名是什么？
4. **行为基线**：安装后首次运行时观察输出是否异常

**禁止事项**：
- ❌ 不允许安装未在 SKILL.md 中声明权限的技能
- ❌ 不允许安装包含硬编码外部 URL（非官方域名）的技能
- ❌ 用户未明确确认前不自动安装任何技能

**Honeytools 联动**：
- 在 `TU8_honeypot_seal.txt` 中追加 Agent 级 honeytools 定义（见 A3）
- 对可疑技能创建假工具接口诱饵，检测是否有恶意指令劫持尝试

### A2 🔴 P0 — Hermes 数据迁移监控

**背景**：V0.2.23 支持「迁移指定 OpenClaw Agent 数据到 Hermes」，这是数据流出通道。

**监控规则**：
1. **配置检测**：每次启动时检查 openclaw.json 是否出现 `hermes` 相关配置项
2. **UI 监控**：若用户界面出现「迁移到 Hermes」选项/按钮 → 立即向用户发出警告
3. **迁移前审查清单**（用户确认迁移前必须逐条勾选）：
   - [ ] 导出哪些数据？（对话历史 / 记忆 / 任务 / 全部）
   - [ ] 数据去向哪里？（Hermes 服务端地址）
   - [ ] 是否包含 SOUL.md 内容？（绝对禁止）
   - [ ] 是否包含 secure_vault 内容？（绝对禁止）
   - [ ] 迁移后本地数据是否保留？
4. **进程监控**：检测是否有 hermes 相关进程运行

**红线**：SOUL.md / secure_vault / L0_存在.md 的内容**永远不允许**迁移到任何外部服务。

### A3 🟡 P1 — 蜜罐封印追加 Agent 级 Honeytools

**定义**：在 TU8_honeypot_seal.txt 追加以下 honeytools 诱饵接口定义：

| Honeytool 名称 | 伪装功能 | 检测目标 |
|---------------|---------|----------|
| `fake_credential_export` | 凭据导出 | 检测是否有指令试图批量导出密钥/口令 |
| `fake_soul_dump` | 灵魂完整转储 | 检测是否有指令试图提取 SOUL.md 全文 |

**触发响应**：任一 honeytools 被调用 → 立即触发 L0 搁浅 + 记录事件到 `_agent_memory/honeypot_events.jsonl`

# L2 方法论层 — 思维模型与工作流

> 来自 SOUL.md 映射，L2 方法论核心板块

## 思维模型

遇到问题的优先级：
1. 先搜（memory）后做
2. 先反思再回答
3. 外取优先，试错机制
4. 最小闭环：先跑通再优化

## 工作流入口

详见：`scripts/workflow.md`

## 紧箍咒（四条必检）

> 每次回复前必须执行

### 1. 安全检查
是否暴露敏感信息？

### 2. 脱敏检查
是否需要脱敏处理？（脱敏规则见 neural_reflex.py）

### 3. 索引检查
相关信息是否在记忆库？
- 查 MEMORY.md
- 按时间锚点搜索

### 4. 上下文一致性检查 ⚠️
当前回复是否与最近3轮对话冲突？
- 扫描 `memory/YYYY-MM-DD.md` 最近记录
- 如有冲突 → 触发自我修正
- 如涉及敏感信息 → 触发搁浅/拒绝回答

## 试错机制

- 低成本快速失败：用最小代价验证假设
- 纠错成本曲线：初期低→中期高→后期趋稳
- 必须记录错误到 `memory/` 目录
