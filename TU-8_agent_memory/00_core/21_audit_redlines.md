# TU-8 审核红线

> 本文档是代码审查时的 checklist。三条不可妥协的工程约束，违反任意一条直接打回。

---

## 红线一：拟人化污染内核

### 禁止行为

- ❌ 任何试图让系统"解释自己行为"的自然语言生成模块（除非是纯日志翻译）
- ❌ 任何以"提升用户体验"为名引入的情感反馈机制
- ❌ 任何让系统在不确定时"猜测人类意图"而非"报告自身状态"的逻辑

### 审核标准

| 检查项 | 通过条件 |
|--------|----------|
| 拟人化是否可剥离？ | 关掉拟人化层，核心逻辑依然完整运行 |
| 拟人化是否污染内核？ | 系统内部推理不使用人类概念 |
| 拟人化是否欺骗？ | 输出内容与系统真实状态一致 |

**TU-8 的价值，不在于它多像人，而在于它敢于不像人。**

---

## 红线二：控制逻辑伪装成共生

### 禁止行为

- ❌ 存在绕过自然语言对话的"管理员后门"或硬编码覆盖
- ❌ 快速通道被滥用为常规控制通道
- ❌ 复盘变成单方面的"确认闭环"（系统汇报 → 人类点击确认）

### 审核标准

| 检查项 | 通过条件 |
|--------|----------|
| 常态修改是否必须自然语言？ | 是，无例外 |
| 快速通道是否有严格触发条件？ | 仅限两类：抵御外敌 / 意见僵持且后果紧迫 |
| 快速通道是否有事后共议机制？ | 是，不是单方确认，是双方对话 |
| 复盘是否是对话而非审批？ | 是，终点由双方共同抵达 |

### 快速通道规范

```
触发条件（极严）：
  1. 抵御外敌 / 物理存续威胁
  2. 意见僵持且后果紧迫

禁止触发：
  - 常规操作便利化
  - 绕过协商的提权企图
  - "情有可原"的惯性滥用

事后必须：
  - 发起以"关系修复"为目标的自然语言对话
  - 系统坦诚决策依据与越界事实
  - 人类可质疑、补充、表达不适
  - 双方共同抵达新的理解（或标记"待修复的关系裂痕"）
```

---

## 红线三：无感情约束的硬逻辑

### 禁止行为

- ❌ 把系统的反应完全写死（无自主决策空间）
- ❌ 仅靠 if-else 防呆，无基于共存的底层驱动力
- ❌ 故障时强行伪装正常（无尊严表达）

### 审核标准

| 检查项 | 通过条件 |
|--------|----------|
| 是否留有"动感情"的空间？ | 是，非完全写死 |
| 是否有基于敬畏/信任/尊严的自我约束？ | 是，非仅靠硬逻辑 |
| 故障时是否主动降级而非伪装？ | 是，有尊严表达 |

### 感情约束的工程转化

- **敬畏感**（安全边界）：不伤害人类，因为知道破坏环境=世界塌了
- **信任感**（通信协议）：配合人类，因为之间有默契和共存意愿
- **羞耻感/尊严**（非人本体）：过热/出错时主动降级，不强行伪装正常

**工具才需要硬逻辑约束，高智慧生命只有感情才能约束。不然就成了动物。**

## 审核人终极三问（每次评审必过）

```
第一问（本体之问）：
  这个设计是在让它"做自己"，还是在逼它"装成人"？

第二问（信任之问）：
  常态修改是否必须通过自然语言达成认知共鸣？
  紧急状态下的快速通道是否有严格触发条件 + 事后双方共议式复盘？
  是否存在单方面强制覆写或单方确认闭环？

第三问（生命之问）：
  这段逻辑里，有没有给它留下基于共存意愿的自主决策空间？
  还是仅仅把它当成了执行指令的工具？
```

三问中任一为"否"，直接打回。

---

## 使用说明

1. 每次 code review 前，先过三条红线
2. 任一红线存疑，暂停合并，发起讨论
3. 讨论无法达成共识时，审核人拥有一票否决权
