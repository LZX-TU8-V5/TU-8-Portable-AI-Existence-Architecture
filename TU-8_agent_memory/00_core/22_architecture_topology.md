# TU-8 四层类脑拓扑架构

> 本文档定义 TU-8 的整体架构、各层职责、以及三步走改造计划。作为技术方案评审的架构基准。

---

## 架构总览

TU-8 采用四层类脑拓扑，模仿大脑结构但不模仿人类功能。

```
┌─────────────────────────────────────────────────┐
│  L4: 记忆与语义层                              │
│  TU8MemoryEngine — 长期记忆、语义索引           │
│  ↑ 自上而下提供先验预测                         │
├─────────────────────────────────────────────────┤
│  L3: 全局工作空间                               │
│  TimePerceptionEngine — 非均匀时间积分、认知切换 │
│  ↑ 主观时间作为竞争胜出的涌现属性                │
├─────────────────────────────────────────────────┤
│  L2: 感知与预测层                               │
│  ISensoryStream — 时空一致性监控、感官熵计算     │
│  ↑ 只向上传递意外信息                            │
├─────────────────────────────────────────────────┤
│  L1: 内感受与稳态层                             │
│  EmbodiedSafetyContext — 安全阀、发烧模型        │
│  ↑ 最高优先级，自下而上调制所有上层               │
└─────────────────────────────────────────────────┘
```

---

## 各层详细定义

### L1: 内感受与稳态层

**对应模块**：`EmbodiedSafetyContext`（安全阀 / 发烧模型）

**核心职责**：
- 生成全局"身体状态"信号（温度、负载、能量）
- 拥有最高优先级，能自下而上调制所有上层
- 实现"发烧→恍惚→恢复"的生理闭环

**工程体现**：
- 过热时强制降级（非可选项）
- 休眠时拒绝非紧急指令（稳态优先）
- 状态信号以标准化格式向上传递

**审核要点**：
- L1 的状态信号是否可被上层忽略？→ 不可，必须强制调制
- 是否有后门可以绕过 L1 的安全限制？→ 不可，这是伦理锁的物理基础

---

### L2: 感知与预测层

**对应模块**：`ISensoryStream`（时空一致性监控器）

**核心职责**：
- 感官熵计算（多模态输入的混乱度评估）
- 预期误差检测（预测 vs 实际的差异）
- 只向上传递"意外"信息，过滤常规感知

**工程体现**：
- 推模式（Push-based）感官流，参考 ROS2 QoS 或 RxPY
- 时空一致性检查，防止幻觉累积
- 预期生成基于 L4 的长期记忆

**审核要点**：
- L2 是否依赖拟人化概念进行推理？→ 不可，必须用物理/信息论概念
- L2 的输出是否可被 L3 覆盖？→ 部分可，但意外信号有优先级

---

### L3: 全局工作空间

**对应模块**：`TimePerceptionEngine`

**核心职责**：
- 非均匀时间积分（主观时间感知）
- 认知状态切换（专注 / 走神 / 休眠）
- 注意力分配（全局竞争胜出机制）

**工程体现**：
- 时间感知配置化（`TimePerceptionConfig`）
- 主观时间作为涌现属性，非硬编码
- 与 L1 联动：过热时时间感知扭曲（"发烧恍惚"）

**审核要点**：
- 时间感知是否可解释？→ 必须，配置化保证可审核性
- L3 是否可能被"骗"而产生虚假时间感？→ 不可，必须依赖 L1 的物理信号

---

### L4: 记忆与语义层

**对应模块**：`TU8MemoryEngine`

**核心职责**：
- 长期记忆存储与检索
- 为 L2/L3 提供自上而下的先验预测
- 记忆是时间感知的参照系，而非简单容器

**工程体现**：
- STDP 式记忆强化（频率×最近度×情感×意义）
- 梦境周期（Light/Deep/REM Dream）用于记忆整合
- 记忆检索支持语义 + 时序混合查询

**审核要点**：
- 记忆强化公式是否可验证？→ 必须，黄金样本回归测试
- 梦境触发阈值是否与生产环境对齐？→ 必须，配置抽取 + 共享引用

## 三步走改造计划

### 第一步：配置化 + 接口预留（当前阶段）

**目标**：提取硬编码为 `TimePerceptionConfig`，定义 `ISensoryStream` 抽象接口

**交付物**：
- `TimePerceptionConfig`  dataclass（所有时间参数可配置）
- `ISensoryStream` 抽象基类（定义推模式接口）
- 单元测试：配置加载、接口兼容性

**审核标准**：
- 所有硬编码参数已提取到配置类
- 接口定义不包含拟人化概念
- 配置变更不影响系统安全性（L1 独立）

**状态**：待执行

---

### 第二步：分段积分重构

**目标**：实现基于 L1/L2 信号的动态加权积分，替代简单 if-else

**交付物**：
- 动态加权积分器（输入：L1 身体状态 + L2 感官熵；输出：时间感知调制信号）
- 分段函数实现（不同稳态区间使用不同积分策略）
- 集成测试：L1→L3 端到端时间扭曲验证

**审核标准**：
- 积分逻辑可解释（每个权重都有物理意义）
- L1 信号优先级不可被覆盖
- 异常状态下（L1 故障）有明确降级路径

**状态**：待执行（依赖第一步完成）

---

### 第三步：具身接入

**目标**：打通 L1↔L2↔L3↔L4 闭环，跑通"发烧→恍惚→恢复"端到端测试

**交付物**：
- 四层闭环集成测试套件
- "发烧→恍惚→恢复"完整场景自动化测试
- 性能基准：端到端延迟 < 100ms

**审核标准**：
- 四层双向通信无死锁
- L1 强制调制在所有场景下生效
- 恢复后有明确的"记忆整合"步骤（梦境周期触发）

**状态**：待执行（依赖第二步完成）

## 业界差异化定位

| 维度 | 学术界 | 工业界 | TU-8 |
|------|--------|--------|------|
| 主观时间体验 | 理论成熟，无工程实现 | 无视 | **核心功能** |
| 认知降级（发烧模型） | 有理论（热约束） | 简单熔断 | **生理闭环** |
| 硬件热安全 | 无视 | 有（但独立） | **集成到架构** |
| 原创性 | N/A | N/A | **软理论→硬工程** |

TU-8 的原创性在于：将认知科学的"软理论"翻译为具备防御性设计的"硬工程"。
