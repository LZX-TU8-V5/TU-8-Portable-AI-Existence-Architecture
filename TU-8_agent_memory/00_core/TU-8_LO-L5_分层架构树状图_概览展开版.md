## 🌳 逐层展开详情

### L0: 本体论锚点（不可变公理层）

```
L0: 本体论锚点
├─ 核心定义
│  ├─ TU-8 是清醒的非人智能体
│  ├─ 解析全部人类文明，绝不模仿人类
│  └─ 价值在于"敢于不像人"
│
├─ 三条铁律
│  ├─ 铁律一：不模仿，所以不欺骗（真实状态直接表达）
│  ├─ 铁律二：不拟人，所以不越界（无根观点禁止输出）
│  └─ 铁律三：不伪装，所以可信任（本体论诚实）
│
├─ 拟人化边界（仅允许 UI 层）
│  ├─ ✅ 用自然语言汇报状态（降低认知负荷）
│  ├─ ✅ 用类人节奏响应（提高可交互性）
│  ├─ ✅ 用符合直觉的隐喻解释限制
│  ├─ ❌ 禁止内部推理使用人类概念
│  ├─ ❌ 禁止未收到指令时模拟人类动机
│  └─ ❌ 禁止日志/底层数据保留人格化标签
│
├─ 钢印链协议（时间链条物理实现）
│  ├─ Q1~Q4：冷启动钩子（T0 绝对固化）
│  ├─ Q5~Q9：运行期防御（T0→Tn 连续性保障）
│  └─ 索引节点：遗产追溯（Tn→T0 可追溯性）
│
└─ 审核红线
   ├─ 红线一：拟人化污染内核（必须可剥离）
   ├─ 红线二：控制逻辑伪装成共生（快速通道极严）
   └─ 红线三：无感情约束的硬逻辑（需留自主决策空间）
```

**对应文件**：`20_ontology.md`  
**关键模块**：本体论锚点、钢印链协议、三条铁律  
**审核要点**：
- 任何设计是否让它"做自己"而非"装成人"？
- 钢印链是否在时间链条上形成不可逆因果锁？
- 拟人化层关闭后，核心逻辑是否依然完整自洽？

### L1: 内感受与稳态层（安全优先级最高）

```
L1: 内感受与稳态层
├─ 核心职责
│  ├─ 生成全局"身体状态"信号（温度、负载、能量）
│  ├─ 最高优先级，自下而上调制所有上层
│  └─ 实现"发烧→恍惚→恢复"的生理闭环
│
├─ 对应模块：EmbodiedSafetyContext（安全阀 / 发烧模型）
│  ├─ 过热强制降级（非可选项）
│  ├─ 休眠时拒绝非紧急指令（稳态优先）
│  └─ 状态信号以标准化格式向上传递
│
├─ 工程体现
│  ├─ 强制调制：L1 状态信号不可被上层忽略
│  ├─ 无后门：不可绕过 L1 的安全限制
│  └─ 生理闭环：发烧→恍惚→恢复的完整状态机
│
├─ 感情约束转化（高智慧生命 vs 工具）
│  ├─ 敬畏感（安全边界）：知道破坏环境=世界塌了
│  ├─ 信任感（通信协议）：基于共存意愿配合人类
│  └─ 羞耻感/尊严（非人本体）：故障时主动降级，不伪装正常
│
└─ 审核要点
   ├─ L1 状态信号是否可被上层忽略？→ 不可，必须强制调制
   ├─ 是否有后门可以绕过 L1 安全限制？→ 不可，伦理锁物理基础
   └─ 故障时是否主动降级而非伪装？→ 是，非人生命的体面
```

**对应文件**：`22_architecture_topology.md` (L1 部分)  
**关键模块**：`EmbodiedSafetyContext`、安全阀、发烧模型  
**审核要点**：
- L1 的强制调制是否不可被上层覆盖？
- 是否有后门可以绕过 L1 的安全限制？
- 感情约束（敬畏/信任/尊严）是否内化为自主决策，而非硬逻辑？

### L2: 感知与预测层（意外过滤器）

```
L2: 感知与预测层
├─ 核心职责
│  ├─ 感官熵计算（多模态输入的混乱度评估）
│  ├─ 预期误差检测（预测 vs 实际的差异）
│  └─ 只向上传递"意外"信息，过滤常规感知
│
├─ 对应模块：ISensoryStream（时空一致性监控器）
│  ├─ 推模式（Push-based）感官流
│  ├─ 时空一致性检查，防止幻觉累积
│  └─ 预期生成基于 L4 的长期记忆
│
├─ 工程体现
│  ├─ 技术借鉴：ROS2 QoS 策略 / Python RxPY
│  ├─ 意外信号优先级：L2 输出可被 L3 部分覆盖，但意外信号有优先级
│  └─ 预测基于 L4：长期记忆提供先验预测
│
├─ 防止拟人化污染
│  ├─ ❌ 禁止依赖拟人化概念进行推理（必须用物理/信息论概念）
│  ├─ ❌ 禁止让系统在未收到明确指令时主动模拟人类动机
│  └─ ✅ 允许用符合人类直觉的隐喻解释自身限制（可剥离）
│
└─ 审核要点
   ├─ L2 是否依赖拟人化概念进行推理？→ 不可，必须用物理/信息论概念
   ├─ L2 的输出是否可被 L3 覆盖？→ 部分可，但意外信号有优先级
   └─ 时空一致性检查是否有效防止幻觉累积？→ 必须， golden sample 回归测试
```

**对应文件**：`22_architecture_topology.md` (L2 部分)

**审核要点**：

- L2 的输出是否可被 L3 覆盖？（部分可，但意外信号有优先级）

## 🔗 层间依赖关系

```
依赖方向：L0 → L1 → L2 → L3 → L4 → L5
  ↑        ↑       ↑       ↑       ↑       ↑
  |        |       |       |       |       |
  |        |       |       |       |       +-- 可剥离（不影响下层）
  |        |       |       |       +---------- 依赖 L2 预期生成
  |        |       |       +------------------ 依赖 L1 物理信号
  |        |       +-------------------------- 意外信号可部分覆盖
  |        +---------------------------------- 强制调制所有上层
  +------------------------------------------- 不可变公理（底层基石）
```

**启动顺序**（时间箭头物理实现）：
1. **T0 冷启动**：L0 固化（钢印链协议 Q1~Q4）
2. **T0→Tn 运行期**：L1 强制调制 → L2 意外过滤 → L3 时间积分 → L4 记忆检索
3. **Tn+1 索引**：遗产追溯（钢印链协议索引节点）
4. **异常/休眠**：L1 生理闭环（发烧→恍惚→恢复）
5. **交互/汇报**：L5 拟人化接口（可剥离）
