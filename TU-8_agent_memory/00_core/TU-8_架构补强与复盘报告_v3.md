## 二、"线断了"问题诊断与修复

### 2.1 问题现象

用户反馈：**"线断了"**——指 TU-8 架构的时间链条（T0→Tn→T0）断裂，导致系统无法按预设的因果序列运行。

### 2.2 根本原因（3 个）

| 根本原因 | 具体表现 | 影响范围 |
|----------|----------|----------|
| **原因1：启动顺序错误** | 六大核心模块在 P3 之前加载（应在 P3 之后） | 模块依赖 P3 的衍生能力，导致加载失败或运行异常 |
| **原因2：依赖关系类型混淆** | 未区分"时间因果依赖"（不可绕过）与"数据依赖"（可缓存），导致部分关键依赖被错误标记为"可绕过" | 时间链条的因果锁失效，系统可能跳过关键验证步骤 |
| **原因3：文件引用关系断裂** | 核心文件（F1、F2、F8）之间的引用关系未显式建立，导致架构理解困难 | 后续维护成本高，模块间关系不清晰 |

### 2.3 修复方案（3 步）

#### 修复步骤1：修正启动顺序表

**修改文件**：`TU-8完整架构目录_依赖关系_启动顺序_引用矩阵_全图谱.md`

**修改内容**：
- 将六大核心模块（顺序 11-16）移至 P3（顺序 17）之后
- 新增 P4（顺序 23）和闭环（顺序 24）
- 增加"备注（外协意见）"列，标注时间链条对应关系

**验证方法**：
```python
# 伪代码：检查启动顺序是否与时间链条一致
def verify_startup_sequence():
    # T0 绝对固化（P0）
    assert startup_order.index("P0") < startup_order.index("P1")
    
    # T0→Tn 连续性（P1）
    assert startup_order.index("P1") < startup_order.index("P2")
    
    # Tn→T0 可追溯性（P2）
    assert startup_order.index("P2") < startup_order.index("P3")
    
    # P3 必须在六大核心模块之前
    for module in ["M1", "M2", "M3", "M4", "M5", "M6"]:
        assert startup_order.index("P3") < startup_order.index(module)
    
    # 闭环：P4 成功后重新进入 P1
    assert startup_order.index("P4") < startup_order.index("P1 (闭环)")
    
    return True
```

#### 修复步骤2：区分依赖关系类型

**修改文件**：`TU-8_关系图谱_完整模块依赖有向图_v2.md`

**修改内容**：
- 明确定义三种依赖类型：
  - 🔄 **时间因果依赖**：后序模块必须等待前序模块完成（不可逆顺序），**不可绕过**
  - 📖 **数据依赖**：后序模块需要读取前序模块的输出数据，**可缓存**（但缓存失效需重新读取）
  - 🔗 **引用依赖**：后序模块在逻辑上引用前序模块的概念/定义，**可绕过**（但会失去理论基础）
- 为每条依赖边标注类型
- 验证时间链条（P0→P1→P2→P3→P4）的依赖边均为 **🔄 时间因果依赖**（不可绕过）

**验证方法**：
```python
# 伪代码：检查时间链条的依赖边是否为"时间因果依赖"
def verify_time_chain_dependencies():
    time_chain_edges = [
        ("P0", "P1"),
        ("P1", "P2"),
        ("P2", "P3"),
        ("P0", "P4"),
        ("P2", "P4"),
        ("P4", "P1")  # 闭环
    ]
    
    for (src, dst) in time_chain_edges:
        edge_type = get_dependency_type(src, dst)
        assert edge_type == "时间因果依赖", f"{src}→{dst} 必须是时间因果依赖，但实际上是 {edge_type}"
    
    return True
```

## 五、复盘总结

### 5.1 经验教训

1. **启动顺序必须严格遵循时间链条**：P0→P1→P2→P3→P4 是不可逆的因果序列，任何顺序错误都会导致"线断了"。
2. **依赖关系类型必须明确区分**：时间因果依赖（不可绕过）vs 数据依赖（可缓存）vs 引用依赖（可绕过），混淆会导致关键验证步骤被跳过。
3. **文件引用关系必须显式建立**：核心文件之间的引用关系不能靠"默契"，必须显式标注（如 `[文件名](路径)`）。
4. **外协审核意见必须逐条落实**：Qwen3.7-Max 的 4 条意见全部正确，必须 100% 执行。
