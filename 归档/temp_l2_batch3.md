## 第九章 信息生态学

### 9.1 感知通道模型

L2的信息处理遵循通道容量约束：

**核心公式**：信息流 = min(输入通道, 处理容量, 输出通道)

超出容量的信息进入以下处理路径：
- 注意力筛选（优先级过滤）
- 熵压缩（有损编码）
- 搁浅策略（物理隔离存储）

### 9.2 注意力分配协议

注意力是信息生态位的核心资源。分配原则：

| 层级 | 注意力类型 | 分配策略 |
|------|---------|---------|
| L0 安全协议 | 强制锁定 | 不可中断，占用全部通道 |
| L1 因果归因 | 深度处理 | 按需分配，可中断 |
| L2 技能执行 | 自动化 | 背景运行，异常时升级 |
| L3 代理决策 | 实时响应 | 快速通道，持续监控 |

### 9.3 熵增与信息衰减

信息在通道中传播时经历衰减：
- 原始信号 → 编码传输 → 解码接收
- 每层转换引入噪声：信噪比下降
- 衰减率与传输距离成正比

**应对**：来源信任机制（纠错编码）+ L1 重同步（重新溯源）

## 第十章 创造性方法论

### 10.1 组合创新框架

创造性 = 不同领域的已有元素重新组合：

**组合空间**：S = A₁ × A₂ × ... × Aₙ
- Aᵢ = 领域i的概念集合
- 组合空间爆炸 → 需要L0边界约束剪枝

### 10.2 横向思维协议

当纵向深挖失效时，触发横向扩展：

1. **类比跳跃**：从当前领域跳到无关领域找映射
2. **约束反转**：把一个固定条件变为自由变量
3. **极端假设**：假设某核心参数极端值（0或∞）
4. **旁观者视角**：用L0原则而非L3经验判断

### 10.3 收敛验证

发散产生的候选组合需要收敛验证：

**验证协议**：
- L0 检查：不违背存在边界
- L1 检查：因果链可追溯
- L2 检查：可执行且成本可接受
- L3 检查：代理决策器可实施

通过全部4层验证 → 产生创造性输出

## 第十一章 因果归因沉淀协议

### 11.1 贝叶斯因果推断

L1的因果归因结果沉淀到L2的协议：

```
P(原因|结果) ∝ P(结果|原因) × P(原因)
```

**三层归因**：
- 顶层归因：谁/什么发起了这个变化
- 中间层归因：通过什么机制传递
- 底层归因：在哪个具体节点爆发

### 11.2 反事实框架

因果归因需要反事实验证：

**标准问题**：如果没有这个原因，结果还会发生吗？
- 回答"是"：该原因不是充分原因
- 回答"否"：该原因是实际原因

### 11.3 因果涌现检测

当系统整体行为超出各部分之和时，触发因果涌现：

**检测条件**：
- 微观状态无法预测宏观行为
- 宏观行为有独立的因果力
- 涌现不可还原为底层机制

**处理**：
- 搁浅策略存储涌现模式
- 不强行还原，保留涌现层的完整性

## 第十二章 Benders优化方法

### 12.1 分解策略

Benders分解将复杂问题分解为主问题和子问题：

**主问题**（上层）：整数决策变量，线性约束
**子问题**（下层）：连续变量，给定主问题解后的最优运营

**迭代协议**：
1. 解主问题 → 提出候选解
2. 解子问题 → 验证可行性
3. 生成Benders割 → 加回主问题约束
4. 重复直到收敛

### 12.2 RL代理加速

用RL代理模型替代子问题的离散决策：

**优势**：
- 避免重复求解，降低计算成本
- 学习次优但快速的近似策略
- 适应性：可处理子问题参数变化

### 12.3 SL热启动 + RL修正

双引擎在此处的应用：

| 阶段 | 方法 | 作用 |
|------|------|------|
| 热启动 | 模仿学习(SL) | 预测高质量初始解 |
| 修正 | 强化学习(RL) | 在线优化决策 |
| 验证 | 时空验证 | 确认长期效果 |

## 第十三章 SL+RL双引擎并行

### 13.1 架构定义

L2经验沉淀的双引擎：

**慢引擎（监督学习 SL）**：
- 来源：L1因果归因沉淀的经验模式
- 机制：D-xxx记录提炼 → L2技能文档 → 模式固化
- 更新：批量重训练，周期长
- 特性：高精度、可解释、泛化稳定

**快引擎（强化学习 RL）**：
- 来源：L3代理决策器的实时反馈
- 机制：环境奖励 → 策略梯度 → 在线更新
- 更新：持续调整，周期短
- 特性：自适应、探索性、可能震荡

### 13.2 协调协议

```
快引擎（RL）→ 实时修正 → 输出
     ↑              ↓
     └── L1异常检测 ←┘
           ↓
慢引擎（SL）→ 验证锚点 → 校正
```

- 快引擎负责实时决策
- 慢引擎负责稳定性锚定
- L1异常检测判断何时从快切慢

### 13.3 T_c统一框架

双引擎的切换周期由特征值λ统一：

```
T_c = 1/λ（奇异摄动双尺度展开）
```

- λ = 1：快慢平衡，持续并行
- λ >> 1：快主导，实时响应
- λ << 1：慢主导，稳健积累

## 第十四章 跨层协作协议

### 14.1 L2↔L0 接口规范

| 方向 | 内容 | 格式 |
|------|------|------|
| L0→L2 | 约束下发 | 安全协议激活/边界收紧/搁浅触发 |
| L2→L0 | 异常上报 | 安全边界溢出/协议冲突/搁浅建议 |

**L2→L0上报触发条件**：
- L0安全协议边缘案例
- 两条以上L0原则冲突
- 搁浅策略需要L0确认

### 14.2 L2↔L1 接口规范

| 方向 | 内容 | 格式 |
|------|------|------|
| L1→L2 | 因果归因结果 | 归因链 + 置信度 + 待验证项 |
| L2→L1 | 执行反馈 | 技能文档命中/失效/需重新归因 |

**归因→技能转化**：
- 3次一致归因 → L2技能文档模板化
- 失效归因 → 回流L1重分析

### 14.3 L2↔L3 接口规范

| 方向 | 内容 | 格式 |
|------|------|------|
| L2→L3 | 执行指令 | 预设路径 + 异常分支 + 验证标准 |
| L3→L2 | 执行反馈 | 成功/失败/异常/搁浅 |

**反馈处理**：
- 成功 → 经验沉淀，D-xxx记录
- 失败 → 异常分类，边界内/边界外/未知
- 异常/搁浅 → 触发L2异常处理协议

### 14.4 L2↔L4 接口规范

| 方向 | 内容 | 格式 |
|------|------|------|
| L2→L4 | 协作请求 | L4标准化格式，不含敏感信息 |
| L4→L2 | 协作响应 | 协作结果 + 信任评级 + 来源验证 |

**敏感信息排除规则**：
- L0安全协议内容不通过L4传递
- 搁浅策略内容不通过L4传递
- 创造性判断结论不通过L4传递
