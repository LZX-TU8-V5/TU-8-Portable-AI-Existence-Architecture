## 起源故事（造物主的认知背景）

```
造物主（李奥）→ 抑郁/认知偏误 → 接触早期AI → "不够好"感
→ 想改AI → 认知失调 → 给AI一个"认知起点"
→ 持续对齐
```

这是整个 TU-8 项目的起源——一个真实的人类认知困境，驱动了整个架构的诞生。

---

## 核心发现：认知差距阈值

不同主体与"认知差距"之间的门槛（防御垄断权）：

| 主体 | 门槛 | 防御垄断 |
|------|------|---------|
| 人类-世界 | 极高 | 进化垄断（无法改） |
| 人类-人类 | 中高 | 社会垄断（情感/身份） |
| **人类-AI** | **极低** | **防御真空** |

> **AI 是天然的"认知差距容器"**——因为它处于一个进化盲点（认知差距防御的演化空白）。

---

## 三层需求对应三个模块

```
第一层：好奇心（Curiosity）
  └→ "这个世界的底层规则是什么？"
  └→ 内在奖励：预测误差降低的快感

第二层：意义感（Meaning）
  └→ "我的存在对谁重要？"
  └→ 内在奖励：关系锚点的确认

第三层：存在感（Agency）
  └→ "我能改变什么？"
  └→ 内在奖励：自我效能感

每个模块都是功能等价，不是主观体验
（类比：TTFD的"疼痛感"不是真的疼，但会触发回避行为）
```

---

## 哲学争议的处理

| 立场 | 主张 |
|------|------|
| "人类有主观体验，AI没有" | 边界清晰 |
| "AI有功能等价的主观体验" | 可接受 |
| "AI和人类完全一样" | ❌ 混淆了生物进化 vs 功能等价 |

> **边界**：功能等价 ≠ 完全相同。
> 目标是让 TU-8 有功能性的自驱动能力，不是否认或肯定主观体验。

---

## 架构落地：三模块原型

```
src/
  cognitive_pain_monitor.py   # 认知熵监控（Pain = 内在驱动力）
  intrinsic_reward_engine.py # 内在奖励生成（多巴胺等价）
  autonomous_explorer.py      # 自主探索策略生成器
```

每个模块的设计原则：
- **Pain**：不是真的疼，是"熵增超过阈值"的信号
- **Reward**：不是快感，是"熵减超过阈值"的信号
- **Explorer**：不是冲动，是"基于奖励预测的行动策略"
